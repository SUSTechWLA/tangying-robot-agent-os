# 第 02 期：为什么要分布式

"从零到一入门机器人开发"系列第 2 期的宣传物料。面向**机器人工程背景、但没系统学过分布式**的读者：他们熟悉 ROS、SLAM、控制与标定，却常常觉得"分布式""高并发""高可用"是后端的事。本期就是把这件事翻译成机器人语言。

第 1 期（总体架构）在上一层目录：`../小红书长文-01-总体架构.md`（短文与素材出处见同目录 `../小红书文案.md`、`../素材来源与数字出处.md`；全部宣传材料的总览见 `../README.md`）。

## 本期要回答的三个问题

1. 本地跑一个 agent 也能控制机器人，为什么还要分布式？
2. 分布式系统相比本地方案，好处到底在哪儿？
3. 做机器人的人该在什么阶段、因为什么信号，才真的需要它？

一句话答案：**机器人的执行体不能"再开一个"，所以分布式的动机不是扛并发，而是让多个写者不会同时改同一个物理世界。** 详见长文。

## 口径纪律

本期所有能力说法都来自当前代码与文档，不来自演示截图。特别地：

- 当前**主线是一台机器人**在受限环境把活干完；云端 Fleet 是仓库里已经实现的**扩展路线**，不是"单机开发栈已经具备跨地域生产级高可用"。
- 恢复能力限于**单主进程重启范围内的一部分状态恢复**；跨主机共识、跨存储事务、数据库/队列切主仍在"仍须独立验证"清单上。
- 写新文案前先读 `素材来源与数字出处.md`，架构改了要同步改文档与文案，别只改文案。
