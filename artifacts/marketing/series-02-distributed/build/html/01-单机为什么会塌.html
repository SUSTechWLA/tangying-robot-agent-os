为什么是分布式 · 01 · 本地单机为什么会塌

本地 agent 只有一台机器替所有人思考

让大模型直接控制机器人，本地跑一个进程就够了——直到你有第二台机器人、断一次网、或者主机重启一次。 下面两张图是同一件事的两种放法：差别不在算力，在谁承担故障。

本地 agent （单机单进程）
执行体只有 1 个
✕故障域 = 全部。一台机器关机，所有机器人的任务一起停。
✕没有第二双眼睛。谁也不知道另一台机器人此刻抓着什么。
✕没有对账依据。工具报"成功"就是成功，世界里改没改没人复核。
分布式 AgentOS （控制面 + 边缘）
可 N 台 · 单台失联不塌
✓故障域分层。云端负责对账，边缘负责实时；一边失联不带走另一边。
✓世界只有一份权威视图。资源有归属，越权写入会被 fencing 挡住。
✓事实先落盘再投递。重启后按事件与快照恢复，不靠内存记忆。
说明 本项目当前主线是一台机器人在受限环境里把活干完；上面右侧的云端 Fleet 是仓库里已经实现的扩展路线，不是"单机开发栈已经具备跨地域生产级高可用"的意思。
