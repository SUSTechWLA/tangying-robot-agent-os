我把这套机器人系统写成了一本书

这是"从零到一入门机器人开发"系列的第 04 期。前三期讲了总体架构、为什么要分布式、以及软件 MCP 和物理世界工具调用的区别。这一期不一样：不讲某一层，讲**一本把整个系统讲透的书**。

先说结论：**《深入理解分布式机器人 Agent 系统》**，16 章 + 3 附录，约 55 万字，已经开源在仓库根目录 `book/`。它不讲"我们做了什么功能"，只回答一个问题——**要让大模型真的把活干完，系统必须建成什么样。**

一、为什么值得写成一本书

因为这套系统里最不直观的那些设计，**每一个都是同一条约束的投影**。

那条约束是：**发起动作的那一方，在原理上无法知道自己是否达成了目的。**

工具可以知道自己"发出去了"，可以知道"对方收到了"，甚至可以知道"执行器动了"。但它**无法知道世界变成了什么样**——世界不在它的观测范围内。

这一句话往下推，推出了一整套东西：证据门禁、八类失败分类、三值逻辑、租约、fencing token、审批范围、字段白名单。它们看起来是七八个不相干的功能，其实是**同一条约束在七个层面上的投影**。

而这条约束**不是机器人独有的**。任何操作物理世界的系统都要面对它。所以这本书讲的不只是一个项目的实现，是一类系统的设计方法。

二、书里有什么

**六部分，16 章：**

起点（第 1–2 章）：三条物理硬约束怎么逼出分层；36 天、328 个提交、9 个真实缺陷修复的演进史。

内核（第 3–4 章）：闭环契约是怎么判的——**判定顺序不可交换**，一个连"命令何时下发"都不知道的动作，不会因为带了一份看起来很新的观测就被判定完成；以及世界模型为什么必须用三值逻辑。

器官（第 5–7 章）：29 个给模型的工具、5 级安全标注、为什么只有 2 个工具不给模型；多 Agent 里"观察者碰不到机器人"怎么从一句注释变成**一个会失败的 for 循环**；一句中文怎么变成 12 步计划。

分布式（第 8–9 章）：为什么"分布式"是故障假设而不是部署姿势；租约、fencing、Outbox 的六个拒绝点；以及砍掉几乎所有分布式机制之后**剩下的那三样**。

落地（第 10–14 章）：三个仿真后端与 sim2real；可观测性与自动恢复；评测与后训练（含三轮实验的**全部真实数字和负结果**）；安装部署；最后是**从零搭建的施工图**。

前望（第 15–16 章）：这套系统自己承认还有哪些没解决；以及与通用 coding agent 的**二十条完整对照**。

三、几个书里最值得看的数字

**① 错误接受率从 58.57% 降到 13.81%**

这是物理接地验证实验的结果：150 个仿真任务实例、210 条物理动作轨迹、1,470 次真实模型调用。**在加入独立验证之前，超过一半的"成功"是假的。**（实测，双侧配对 t，p=0.00003336）

**② 上下文实验：语法不是关键，信息完整性才是**

两模型因子实验，480 个状态、12,484 个真实请求、31,716,142 tokens。结果：**"JSON 还是自然语言"这个因素在两个模型上都不显著**（+0.55 / +1.17 个百分点）；而"删掉必要字段"的影响是压倒性的（+73.55 / +65.51 个百分点）。

**③ 报告自己算出"我这个实验功效不够"**

每环节只有 4 个留出族，双侧符号翻转的**最小非零 p 就是 0.125**——所以这一轮**无法提供严格的逐环节优越性证明**。报告把这句话写进去了，还算了"要做到 5 个百分点需要至少 4,615 个独立族"。

**④ 一个只有 2 毫秒的安全陷阱**

避障检查从当前位置开始采样，于是机器人一旦落进包络半径内，"你离墙太近"对**每一个**候选动作都成立——**包括那个把它开离墙的动作**。实测离墙 0.373 米、包络 0.375 米，差 2 毫米，这个回合剩下的时间它再也动不了。

书里对它的定性是：**这不是安全属性，是陷阱。**

四、边界：书里也写了没做到的部分

**这一节不能省。**

书里第 15 章整章在讲这套系统**自己承认没解决的事**：五条"仍须独立验证"的清单、五条刻意的非目标（每条都写了代价）、24 条明确的未实现声明。

几条最硬的：

- **当前主线是一台机器人在受限环境把活干完**；云端 Fleet 是仓库里已经实现的扩展路线，不等于单机开发栈已具备跨地域生产级高可用。
- **"返程导航受地图覆盖限制"**——README 原话是"在这一版上返程确实没走通"。这是"不知道的地方不进去"，不是缺陷。
- **跨机学习（A 机解决的故障 B 机受益）被列在架构优势里，但实现不在**——书里给了五处代码证据说明它没落地。
- **仓库没有已训练的通用实机模型**；软件发布与实机放行是两项独立结论，仿真通过不等于实机可用。
- 规划环节的语言表达实验里，**两个模型 × 八种表达的完整字段正确率全部是 0.00%**，报告的处理是把它写进"禁止套用"名单，并且写明**"不能用最高候选分数掩盖这个负结果"**。

写这一段比写"我们做成了什么"难，但**少一段它就不是一本可信的书**。

五、三句话记住这一期

第一句：**"工具返回成功"是一个关于工具自身的陈述，不是一个关于世界的陈述。**

第二句：**去掉分布式，闭环契约、失败分类、证据与回放这三样依然需要；去掉这三样，分布式机器人 Agent OS 就只是个很慢的遥控器。**

第三句：**每一个"已实现"的机制，都问一句"如果我把它的实现改成 return nil，会有什么测试失败"——如果只有单测失败、集成测试全绿，那它就是没通电的。**

六、怎么读

**想快速建立判断力（半天）**：前言 → 第 1 章 → 第 3 章 → 第 16 章。

**想自己搭一套（两周）**：第 2 章 → 第 3 章 → 第 5 章 → 第 8 章 → **第 14 章（施工图）**。

**想写论文 / 做研究**：第 3、11、12 章 + 附录 C 的实验数据索引。

**教书用**：每章末尾都有"教学要点"和练习题（含答案要点），可以直接当课程单元。

七、关于这本书的可信度

写作方法说清楚：**先派了六个任务逐个子系统读源码**，产出 7,909 行带 `文件:行号` 的研究笔记（保留在 `book/research/`），再据此写章节。

所以：**每一个技术断言都能回溯到源码；凡推断，标注"推断"；凡文档与代码冲突，标注冲突并给出代码事实。**

写作过程中就抓出了一批过期说法，书里全部按代码更正了：

- 文档说失败分类是"七类"，**代码是八类**；
- README 说工具 27 / 25 / 28 个，**实测 31 个注册、29 个给模型**；
- 文档说"113 个运行时故障码"，那是 2026-09-17 的**历史值**；
- 文档说"279 条报告变成 7 个问题"，这个数字有**四个不同版本**；
- 文档说 Local Agent"引用云端 0 处"，实测**无运行时依赖，但二进制里有 227 处相关符号**——文档、构建产物、测试三者可以同时为真，因为**没有任何工具在检查这件事**。

最后一条我自己觉得是这本书最有价值的方法论：**一个数字写在文档里，它就是一个和其他断言一样的断言，需要和其他断言一样的检查。**
