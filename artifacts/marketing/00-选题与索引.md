## 一之二、短文连载（每天一更）

长文效果不好，改为短文连载：把长文按"一条一个点"拆开，正文 260–450 字，每天一条，
标题（总标题 + 期号 + 本期钩子）与行动区都写进正文，整段复制即发。
计划、排期、论文映射与发布纪律见 [讲什么-短文连载计划.md](讲什么-短文连载计划.md)；
成稿在 [shorts/](shorts/README.md)，已完成 S01–S10 = 第（一）–（十）期（够发 10 天），下一条按 S11 起排。

**登记要求**：每条发完回来在 `shorts/README.md` 标状态与数据（阅读/收藏/涨粉），
两周后按数据淘汰选题方向。

## 二、已发各期的定位（避免以后写重）

| 期 | 一句话钩子 | 与前后期的边界 |
| --- | --- | --- |
| 01 | 一句话变成十几步，每一步都留可回放的证据 | 只讲**总体架构**，不深入任何单点 |
| 02 | 机器人做分布式不是因为高并发，是因为**执行体不能"再开一个"** | 讲**跨机器**的问题：写者数量、租约、fencing、恢复 |
| 03 | **MCP 定义了怎么调用，没定义调用之后世界变成什么样** | 讲**单次调用**的问题：证据、闭环、失败分类；不重复讲租约 |

| 04 | **我把这套系统写成了一本书** | 宣传对象是**书**（16 章 + 3 附录），不是某一层代码；与 01-03 期构成若干专题对一本总纲的关系，不复述任何一期的机制细节 |

写第 05 期时注意：导航的"速度租约"与第 02 期的资源租约同源但不同层，**讲工具契约与安全监督，不要重讲分布式**。

## 五、发布检查清单

每次发之前过一遍：

- [ ] 正文第一行是 `深入理解分布式机器人AgentOS（期号）`，第二行是本期钩子（≤20 字）
- [ ] 该期 `素材来源与数字出处.md` 逐条核对过
- [ ] 小红书正文**不含 markdown 符号**（`**`、`###`、反引号）
- [ ] 连载正文 ≤ 450 字；速览/长文 ≤ 1000 字（含链接与标签）
- [ ] 行动区三行齐全：仓库地址 + 一句话项目介绍 + 下一篇预告 + star 请求
- [ ] 标签 5–6 个，第一个是 `#开源项目`
- [ ] 图是重新渲染过的，不是旧版本（改了文案就要重跑 `tools/render.mjs`）
- [ ] 协议说法跟根 `LICENSE` 一致（当前 MIT）
- [ ] 能力边界说法没越界：主线一台机器人 / Fleet 是扩展路线 / 恢复能力限于单主重启范围
- [ ] 评论区第一条自己占：仓库地址 + 联系方式
- [ ] 招聘方向写具体关键词（SLAM / 导航 / 机器人 Agent / 具身智能软件）
