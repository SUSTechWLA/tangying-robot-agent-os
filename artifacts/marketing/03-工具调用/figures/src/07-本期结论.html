工具调用的本质区别·07·本期结论

MCP 解决接入，语义要自己定义

协议让任何客户端都能用同一套方式访问机器人；但"调用之后世界变成什么样"，协议管不着，必须由机器人系统自己定义——而且要定得足够死。

能力分层 从下往上读：只有最上面一层是协议给的，下面三层必须自己做
04
接入层 MCP 负责

工具名 + JSON Schema + 返回值。任何支持 MCP 的客户端用同一套方式访问不同机器人。

协议到此为止，下面三层必须自己做
03
语义层 机器人系统自己定义

这个动作改不改世界、幂不幂等、什么安全层级、要什么审批。

02
验证层 机器人系统自己定义

返回成功之后，必须拿到命令之后的、新鲜的同坐标观测证据才算完成。

01
恢复层 机器人系统自己定义

失败分七类分别处置；结果未知禁止自动重试，先对账。

如果只有 MCP 三个会真实发生的场景
场景 01 只有协议

工具返回 SUCCESS，任务就标记完成。杯子没夹住，系统认为已经拿到了。

场景 02 只有协议

调用超时了，重发一次。机械臂把"前进一米"执行了两次。

场景 03 只有协议

拿一张命令之前的照片当证据，任务照样判定成功。旧观测被洗成了新的完成。

三句话结论 可以直接拿去对照自己的系统
01

软件工具的返回值是事实，物理工具的返回值是声明。

声明需要被验证。

02

"未知"不是"失败"。

物理世界里结果未知是独立状态，它的正确处置是先对账，绝不是自动重试。

03

幂等性在物理世界里不是特性，是约束。

它不是"实现出来的"，而是"必须在调用前记住"的——因为世界不参与重试。
