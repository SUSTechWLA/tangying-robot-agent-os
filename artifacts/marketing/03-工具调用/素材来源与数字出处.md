## 2. 数字的确切来源（**发布前请照抄，不要凭印象**）

全部来自仓库根目录 `tools.json`（`schema_version: llm.tools.v1`）。统计口径：`metadata` 里每个工具的 `mutates_world` 与 `idempotent` 字段。

| 说法 | 数值 | 口径 |
| --- | --- | --- |
| 工具总数 | **30** | `metadata` 条目数 |
| `mutates_world = true` | **14** | 改世界，返回成功不算完成 |
| `idempotent = false` | **14** | 重发就是重做一遍 |
| 幂等且不改世界（可安全重试） | **15** | `idempotent != false` 且 `mutates_world != true` |
| 完全不暴露给大模型 | **2** | `excluded_from_llm`: `move_arm_to_joints`、`navigate_to_pose` |
| MCP 对外工具数 | **8** | `robot/mcp/README.md` 的统一工具表 |

**四个象限的确切成员**（图 02 逐格使用，逐个核对过）：

- 只读 · 幂等（15）：`capture_image`、`check_collision`、`detect_object`、`emergency_stop`、`get_arm_state`、`get_current_pose`、`get_gripper_state`、`get_object_pose`、`get_robot_status`、`plan_work_area`、`recall_object`、`resolve_location`、`scan_environment`、`set_speed_limit`、`stop_navigation`
- 改世界 · 幂等（1）：`set_gripper_width`
- 只读 · 非幂等（1）：`reset_safety_stop`
- 改世界 · 非幂等（13）：`explore_for`、`fetch_object`、`grasp`、`home_arm`、`move_arm_relative`、`move_arm_to_joints`、`move_arm_to_pose`、`navigate_to`、`navigate_to_pose`、`navigate_to_work_area`、`pick_object`、`place_object`、`release`

**两个特例的解读**（文案里用到，别写错）：

- `set_gripper_width` 既改世界又幂等——把宽度设成同一个值两次，结果相同。说明"改世界"与"能不能重试"是两个**正交**属性。
- `reset_safety_stop` 不改世界但不幂等——它不写物理世界，但不该被重复调用。它证明"不改世界"不等于"可以随便重试"。

> 复现命令：`python3 -c "import json;d=json.load(open('tools.json'));..."`，或直接看 `tools.json` 的 `metadata`。**改工具目录后本表必须同步。**

## 4. 七类失败：逐条出处

分类表在 `core/closedloop/closedloop.go` 的 `classification`（有序查表，**先匹配先生效**），类别常量在同文件 `Class`。

| 类别 | 图里的"唯一安全的下一步" | 依据 |
| --- | --- | --- |
| `TRANSIENT` | 基础设施恢复后原地重试一次 | `Class.Retryable()` 为真；`DefaultPolicy().MaxAttempts = 2` |
| `PERCEPTION` | 先重新观察或搜索 | 同上，可重试；`TestPerceptionFailureIsRetryableButPlanningAndValidationAreNot` |
| `PLANNING` | 换目标或换计划 | 不可重试，直接升级；同一测试 |
| `PERMISSION` | 先补齐许可 | 不可重试；`TestClassifiedFailuresEscalateImmediatelyWhenNotRetryable` |
| `RESOURCE` | 等资源归属理清 | 不可重试；同上 |
| `VALIDATION` | 修正参数 | 不可重试；`TestPerceptionFailureIsRetryableButPlanningAndValidationAreNot` |
| `FATAL` | 需要人介入 | 不可重试 |
| `UNKNOWN_OUTCOME` | **先对账，禁止自动重试** | `ErrUnknownRetry`；`TestUnknownOutcomeNeverRetries`、`TestFailureCodesWithUnknownOutcomeAlsoEscalateWithoutRetry` |

**代码里的原话**（图 05 引用）：`unknown physical outcome must not be retried automatically`（`ErrUnknownRetry` 的文案）。

**"不认识的错误码默认归到结果未知"**：`Classify` 对未命中的 code 返回 `UnknownOutcome`；`closedloop.go` 注释写明 *"an unrecognised code is classified UnknownOutcome rather than being guessed as retryable"*。测试：`TestClassifyAssignsTheExpectedClassForRealRuntimeCodes`。

**重试预算**：`DefaultPolicy()` = `MaxAttempts: 2`、`BackoffBase: 250ms`、`BackoffMax: 2s`；注释原文 *"no retry for anything that could have reached the hardware without a known result"*。测试：`TestTransientFailureRetriesWithinBudgetThenEscalates`、`TestRetryBudgetIsEnforcedOnDispatchToo`、`TestBackoffGrowsThenSaturates`。

**"取消也是一种已发生"**：`edge/agent/recovery_test.go` · `TestCancelledRunnerDoesNotStartAnyToolsEvenWhenInvokerIgnoresContext`；`FATAL` 集合含 `CANCELLED`。

## 6. MCP 这一层：口径与边界

| 说法 | 依据 |
| --- | --- |
| MCP 对外 8 个粗粒度工具 | `robot/mcp/README.md` 的统一工具表：`list_robots`、`get_robot_capabilities`、`observe_world`、`list_tasks`、`create_task`、`get_task`、`cancel_task`、`emergency_stop` |
| 不暴露关节、电机或审批接口 | 同 README 开头："不向外部 Agent 暴露关节、电机或审批接口" |
| 建任务必须未审批 | 同 README：`create_task` 成功必须 `approved=false` 且状态为 `READY`/`WAITING_APPROVAL` |
| 没有自动批准、没有重置急停 | 同 README："MCP 不提供批准、自动批准、重置急停、上电解锁、关节控制或厂商 SDK 任意调用工具" |
| 结果可能已生效时不能直接重提 | 同 README 错误码表：`OUTCOME_UNKNOWN` → "变更请求可能已经生效；先查询任务或设备状态，不能直接重复提交" |
| 急停 `status=pushed` 不等于物理停止 | 同 README：示意"物理停止须结合设备反馈核验" |

**边界（别讲过头）**：

- MCP 桥接**不扩充**自然语言解析器已支持的技能范围，也不能仅凭能力注册证明某台实机已完成安全验收。
- "断网停止"、实体急停、限速等属于实机验收项，仿真通过不等于实机放行（见 `docs/production/testing-and-acceptance.md`）。
- 当前主线仍是**一台机器人**在受限环境把活干完；云端多机是已实现的扩展路线。
