软件 MCP 和物理世界工具调用，差在哪儿

这是"从零到一入门机器人开发"系列的第 3 期。

第 1 期讲了总体架构，第 2 期讲了为什么要分布式。这一期回答一个更具体的问题——也是我被问得最多的问题之一：

你们做的这个 MCP、这些工具，和 Codex、Claude 调 GitHub API、调数据库，到底有什么区别？不都是工具调用吗？

先给结论：**协议上确实没有区别，语义上几乎是相反的。**

MCP 把"怎么调用"标准化了：工具名、JSON Schema 参数、返回值。这是它真正的价值。但它没有、也不可能定义"调用之后世界变成什么样"。同一套 tools/call，可以表达"查一下这条记录"，也可以表达"把机械臂伸进柜子抓那个杯子"，而这两件事的失败代价、重试语义和验证方式完全不同。

这一期就讲清楚差在哪，以及为了让物理调用可靠，我们具体做了什么。

一、根本差异：软件工具是查询，物理工具是动作

我先用一句话概括最核心的区别：

软件工具的返回值可以证明调用成功；物理工具的返回值只能证明调用被执行了。

为什么？因为软件系统是静止的——你不调用它，它就不动。所以"我读到了这条记录"和"这条记录存在"是同一件事。

物理世界不是静止的。东西会被移动、会滑落、会被别人拿走、光照会变、电池会掉。你在两次调用之间什么都没做，世界照样在变。所以"我说我做完了"和"世界已经变成我要的样子"是两件事，中间隔着一次独立的观察。

这个差异往下推出五条，每一条都在改代码结构。

第一条，做错了回不去。事务可以回滚，机械臂不能 ROLLBACK。杯子碰倒了就是碰倒了。所以物理动作的代价不是毫秒级的，是不可撤销的。

第二条，幂等性不是想加就能加的。软件里加个幂等键，同一个请求发两次结果一样——这是"实现出来的特性"。物理世界里，"前进一米"发两次，它真的走两米。世界不参与重试，你能做的只是**在调用之前**记住这个动作已经发出去了。

第三条，结果不确定时不能重试。软件超时了重发一次就好，因为重复调用没有副作用。物理动作超时了，你不知道它做完了没有——可能刚启动、可能做到一半、可能已经做完了。三种情况的正确处置完全不同。

第四条，成功不等于做对。工具返回成功，只能说明"命令执行完了"。杯子有没有真的夹住、有没有夹稳、是不是夹的你要的那个——都得再看一眼。

第五条，响应时间差三个数量级。查数据库是毫秒级，一次抓取是几十秒到几分钟。这会反过来改变超时、租约、任务调度的整个设计。

二、我把这五条落成了具体的工具标记

空谈区别没意义，说我们怎么做的。

在这个项目的工具目录里，每个工具都带一组声明式标记。当前 30 个工具里有 14 个标记了 mutates_world=true——意思是"这个工具会把物理世界改成新状态，返回成功不算完成，必须有新的观测证据来确认"。抓取、放置、导航、开夹爪、回零，都在这一类里。

另外 14 个标记了 idempotent=false——意思是"重发就是重做一遍"。这两个集合高度重叠但不完全相同，因为它们是两个不同的问题：一个问"会不会改变世界"，一个问"重复执行会不会产生额外后果"。

剩下 15 个是幂等且不改世界的，比如查询位姿、检测物体、拍照。这些可以安全重试。

有一条设计上的硬约束值得单独说：**标记 mutates_world 但不标记 side effect 的工具，会在加载时直接报错拒绝启动。** 理由写在代码注释里——那等于告诉调用方"这个动作不需要确认"，同时让闭环在等一份永远不会到来的证据。这种自相矛盾必须在启动时就炸掉，而不是等到现场。

还有个更能说明态度的细节：`move_arm_to_joints` 和 `navigate_to_pose` 这两个工具，**根本不暴露给大模型**。它们是关节角级别和位姿级别的原始接口，留给工程调试用。给大模型的是 pick_object、place_object、navigate_to 这种带语义的任务级工具。模型不接触关节角、轮速和坐标——这不是洁癖，是因为让语言模型输出关节角，等于让它直接写硬件寄存器。

三、同一次调用，在系统里会走出一条有分叉的状态机

这是我觉得最值得讲的部分。

在软件工具调用里，状态机通常只有三个状态：调用中、成功、失败。物理调用不行，因为"工具说成功了"和"我确认过了"必须分开。我们的实现是这样的：

命令发出，进入 EXECUTING。

工具返回成功——状态不是"完成"，而是 AWAITING_EVIDENCE（等待证据）。物理结果此时仍然未知。

然后必须附上一份新鲜的、命令之后采集的观测证据。校验通过，才是 VERIFIED。

如果工具返回失败，不是简单重试，而是先分类。我们把失败码分成七类，因为每一类**唯一安全的下一步动作**不同：

TRANSIENT（瞬时故障）——基础设施恢复了可以原地重试一次。
PERCEPTION（感知类）——需要先重新看一眼或重新找，不能闭着眼睛重做。
PLANNING（规划类）——同样的命令再发一遍没有意义，得换目标或换计划。
PERMISSION（许可类）——审批、安全 profile、工具目录版本、fencing 状态不对。
RESOURCE（资源类）——东西在别人手里，或者没有拿到授权。
VALIDATION（参数类）——命令本身不合法，原样重试不可能成功。
UNKNOWN_OUTCOME（结果未知）——物理结果无法确定，**禁止自动重试**。
FATAL（致命）——重试解决不了。

其中 UNKNOWN_OUTCOME 是这套设计的核心。注释里写得很直白：结果未知**不意味着失败，也不意味着成功**。它的处置只有一个——升级，让人或上层先去对账，然后才允许碰硬件。

这里有个我很在意的细节：**分类表里不认识的错误码，一律归到 UNKNOWN_OUTCOME，而不是猜成可重试。** 默认值是"不许重试"。这个默认值选对了，系统才会在遇到没见过的故障时停下来，而不是莽上去。

四、"证据"不是随便一份数据：四道校验

上面说成功要附证据，但证据本身必须过四道关，缺一道都不算数：

第一，必须有观测 ID——不能是一句"我看到了"。
第二，必须有采集时间——而且是**传感器采集时间，不是系统收到的时间**。这两个时间在真实系统里能差好几秒。
第三，采集时间必须**晚于命令下发时间**。早于命令的观测，哪怕再清晰，也证明不了命令之后发生了什么。这条挡掉的是最隐蔽的一类错误：拿一张旧照片当新证据。
第四，来源的新鲜度判定不能是 STALE 或 UNKNOWN。

第四条的注释写得很好：这么做是为了**防止一个过期的数据源被"洗"成一次完成**。时间戳对得上还不够，数据源自己得说它是新鲜的。

除此之外还有坐标系和变换版本的一致性——物理世界里"杯子在 (0.3, 0.1)"如果没有说明是哪个坐标系、哪个标定版本，这句话就是没有意义的。

五、恢复策略：把"不确定"当成一等公民

物理调用还有一类软件里几乎不存在的失败：**可恢复的失败**。

软件调用的结果基本是二元的：成了或者没成。物理动作有第三种——比如抓取时发现目标位置偏了，这时候正确的做法不是重试，也不是报错停在那，而是**退到一个安全姿态**，重新观察，再决定。

所以我们的恢复策略里有一个独立的分类叫"可恢复失败"，对应的处置是执行 recover_to_safe_pose 这类动作。这个设计的价值在于：它把"出错"从一个异常，变成了一个有明确下一步的正常状态。

还有几处相关的处理，我列在一起：

数量边界在前面挡。动作的位移、夹爪的开合宽度、策略输出的动作块长度，都在执行前校验数值上下限。安全层级最低到最高分了 5 级，最高级（物理运动）必须有安全 profile、必须有默认租约、必须有副作用标记，否则加载时报错。

超时要可取消。取消并不等于没执行——取消也是一种"动作已经发生但结果未确认"的情况，同样要走对账。

审批是人工的。物理动作要人在控制台上批准。MCP 那一层只提供 8 个粗粒度工具（列出机器人、查能力、看世界快照、建任务、查任务、取消、急停等），**不提供批准、不提供自动批准、不提供重置急停，也不暴露关节控制**。外部 Agent 建的任务一样要人工审批。

工具目录带版本号。每次派发都会校验工具目录版本，版本不符直接拒绝执行——防止"我以为是这个工具定义，机器人那边其实是另一个"。

视觉降级时明确降级。如果三维资产挂了但语义数据还可信，界面会显示"视觉降级"并用语义画布，而不是假装一切正常。

六、所以 MCP 这层的价值到底是什么

说了这么多"物理调用有多难"，回到 MCP 本身。

我的看法是：MCP 的价值在于它把**接入**标准化了，让任何支持 MCP 的客户端都能用同一套方式访问不同机器人。这个价值很大，但它止步于接入层。

真正决定系统可靠性的，是接入层下面的四件事：

工具声明的语义（这个动作改不改世界、幂等不幂等、什么安全层级）；
执行前的校验（目录版本、坐标系版本、数值边界、租约、审批）；
执行后的验证（证据必须新鲜、必须晚于命令、来源不能过期）；
不确定时的处置（禁止自动重试，先对账再说）。

这四件事，MCP 协议管不着，Codex 和 Claude 的通用工具调用约定也管不着。它们必须由机器人系统自己定义，而且要定得足够死——因为定松一点，代价就是一台机械臂把一个杯子碰倒。

七、三句话记住本期

第一句：**软件工具的返回值是事实，物理工具的返回值是声明。** 声明需要被验证。

第二句：**"未知"不是"失败"。** 物理世界里结果未知是独立状态，它的正确处置是先对账，绝不是自动重试。分类表里不认识的错误码，默认也归到这里。

第三句：**幂等性在物理世界里不是特性，是约束。** 它不是"实现出来的"，而是"必须在调用前记住"的——因为世界不参与重试。
