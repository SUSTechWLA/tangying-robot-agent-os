工具调用的本质区别 · 03 · 协议相同，世界不同

MCP 定义了怎么调用，
但没有定义调用之后世界变成什么样

同一个 tools/call，可以是"查一下天气"，也可以是"把机械臂伸进柜子抓那个杯子"。 协议层看起来一模一样，但这两件事的失败代价、重试语义和验证方式完全不同。 这一期讲清楚差在哪，以及为了让物理调用可靠，我们具体做了什么。

共同的协议层 工具名 + JSON Schema 参数 + 返回值。Codex、Claude 调 GitHub API 和调一台机器人，在协议上没有任何区别——MCP 把"怎么调用"标准化了，这是它的价值，也是它的边界。
软件工具调用 查数据库 · 调 API · 改文件
返回值是什么
就是事实本身。接口说这条记录存在，它就是存在——返回值是你唯一需要的信息源。
做错了怎么办
回滚。事务可以撤销，文件可以恢复上一个版本。代价是毫秒级的。
重发的代价
加个幂等键就解决了。同一个请求发两次，结果和发一次一样——幂等是"实现出来的特性"。
结果不确定时
重试到收敛。超时重发一次就好了，因为重复调用没有副作用。
世界会自己变吗
不会。你不调用它，它就不动。系统是静止的。

物理世界工具调用 导航 · 抓取 · 放置 · 开夹爪
返回值是什么
只是一个声明。"我执行完了"不等于"世界按你预期的样子变了"。SUCCESS 只是去看一眼的触发器。
做错了怎么办
回不去。杯子已经碰倒了，机械臂没法 rollback。代价是物理的、不可撤销的。
重发的代价
就是又做了一遍。"前进一米"发两次，它真的走两米。幂等性不是想加就能加的——世界不参与重试。
结果不确定时
必须先去看，再决定。"未知"是独立状态，禁止自动重试——宁可停下等人，也不猜一个成功。
世界会自己变吗
会。东西会被移动、会滑落、会被别人拿走、光照会变。系统在你不调用它的时候依然在变。
一句话 软件工具调用的返回值可以证明调用成功；物理工具调用的返回值只能证明调用被执行了。这两句话之间，隔着一整套验证与恢复机制——也就是后面几张图要讲的东西。
