## 正文（长文版）

### 先说这个系列想做什么

我做的是一套机器人的"操作系统"：**Tangying Robot AgentOS**。你对着控制台说一句中文，它自己拆任务、走到地方、看懂现场、伸手把活干完，并且每一步都留下能回放的证据。
开源地址放在最前面：**https://github.com/SUSTechWLA/tangying-robot-agent-os**

这个系列我打算**从零到一**讲完它，每个模块一期。第一期不写代码，只讲**总体架构**——因为架构不清楚，后面每一行代码都会看得痛苦。

### 一、它到底是什么：不是遥控台，是分布式 AgentOS

机器人圈子里有两个常见起点：一个是"遥控器 + 脚本"，一个是"一个大模型直接输出关节角"。这条路线两个都不选。

它把自己定位成**分布式的 agent 控制面 + 面向具身机器人的边缘运行时**，有两种部署形态：

- **云端 Fleet（多机形态）**：浏览器控制台 → Fleet API → 任务服务/协调器/事件总线 → WorldHub 世界模型 + Harness 裁决 → 经 mTLS 下发到 N 台 Edge（每台一个机器人）→ Robot Runtime → 实机或仿真工具；
- **Local Brain（离线形态）**：控制台 → 本地 Agent + SQLite → **同一个** Robot Runtime → 实机或 MuJoCo 仿真。

关键点：两种形态**共用同一套 Runtime 契约、工具目录、观测契约和世界快照格式**。也就是说，"大脑"可以装在机器人身上离线跑，也可以接云端调度多台；换一台机器人、换一种本体，任务和证据链不用重写。（当前主线是一台机器人在装修家庭里把活干完；Fleet 多机是仓库里已经实现的扩展路线。）

### 二、整体架构：八层，各管一件事

我用"从人到电机"的顺序讲，每一层都能在仓库里找到对应目录。

**① 交互层** —— `web/`、`console/`
网页控制台：工作台（说一句话 + 看机器人此刻的画面）、任务记录、任务全过程回放、SLAM 建图、我的机器人、开发诊断。另有 `robot/mcp/` 作为给外部 Agent 的 MCP 统一入口（**通过 MCP 创建的任务依然要人工审批，也不暴露裸关节动作**）。

**② 理解与规划层** —— `agent/`、`orchestration/`
把一句中文变成"可执行的任务图"。设计上很克制：**已知意图优先走确定性解析**，歧义要求澄清，只有剩下的自然表达才交给可选的大模型；规划器另有一条确定性后备路线。模型不接触坐标、轮速、关节角——它只说"去厨房""拿杯子"。

**③ 任务与协调层** —— `tasks/`、`fleet/coordinator/`、`fleet/eventlog/`
`Task` 是聚合根，**`Revision` 不可变**：需求变更是"改版"（带 `changeSet`：保留哪些步、改哪些步、取消哪些步），确认时必须提交 `expectedCurrentRevision` 与幂等键，防止并发覆盖。协调器单写派发：领取步骤、分配机器人、检查租约、在**安全点**才切换版本、做资源监护权转移与恢复。

**④ 世界模型与裁决层** —— `core/worldmodel/`、`core/observation/`、`core/harness/`
这是我最喜欢的一层。`WorldHub` 把各来源状态合并成**带单调 revision 的 WorldSnapshot**（按 source sequence 去重；陈旧或自相矛盾就"失败关闭"，不猜）。`Observation Registry` 预先声明"应该观察什么、多久算过期"。最后 `Harness Agent` 拿**世界证据**去核对每一步的后置条件，输出 reason、evidenceIds、worldRevision——**它不接受"工具调用成功"这一个信号**。

**⑤ 执行与安全层** —— `edge/`、`edge/runtime/`、`robot/gateway/`
Edge Worker 负责连接、执行工具、上报观测，断网重连、幂等；Robot Runtime 提供统一的工具执行、观测流、取消与急停，**仿真和实机之间只替换 Adapter**。每条命令必须同时满足：deadline、审批、catalog revision、世界坐标系版本、任务 revision、资源 fencing、幂等键。安全监督与执行日志（`safety`、`journal`）在这一层落地：软件状态永远低于实体急停与硬件限制。

**⑥ 机器人能力层** —— `skills/`、`robot/gateway/`（标定 / 建图 / 导航服务）
导航、抓取、放置、以及三个"验证"工具（到达、抓稳、放好）。工具目录用大白话描述用途与安全参数，Agent 只能调用**本 revision 已注册**的工具。标定、稠密 SLAM 建图、导航规划/避障都在这里作为注册服务提供。

**⑦ 适配与本体边界** —— `examples/robots/`、`sim/mujoco/`、`robot/ros2_ws/`、`policy/sidecar/`
新本体接入走一条统一路径：`RobotProfile`（声明结构/传感器/可用工具子集）→ `PluginBackend`（用厂商 SDK 或 ROS 2 执行）→ `RobotRuntimeService`。策略（VLA / 模仿学习 / 强化学习）通过 `policy/sidecar` 接进来：候选动作先过身份与数值边界校验，再进 Runtime 执行，最后仍由 Harness 确认真实世界发生了什么。

**⑧ 契约与协议层** —— `proto/robot/v1`、`proto/fleet/v1`、`python/tangying_robot_proto`
跨语言、跨进程的硬约定：`robot.v1` Runtime 接口、`world.snapshot.v1` 世界快照、`scene.reconstruction.v1` 三维重建、`robot.profile.v1` 机器人数描述。**接口不变，本体可换**——这是"换机器人不用重写任务"的底气。

### 三、一句话任务，在系统里怎么走完

1. 你提交自然语言 → 任务服务创建 **revision 1**（未审批）；
2. 控制台先**复述它理解到了什么、准备怎么做**，你确认后才置为已审批；
3. 协调器领取步骤，检查机器人租约、工具目录版本、世界新鲜度、资源归属；
4. 命令经 Edge 下发到 Runtime（用命令号 + 幂等键去重，全过程流式回报状态与观测）；
5. 观测回到 WorldHub，投影成**新的 WorldSnapshot revision**；
6. Harness 用它核对这一步的后置条件，满足才判 `SATISFIED`，资源监护权换新 fencing token 交给下一台；
7. 所有步骤满足、最终资源归属正确 → 任务 `SUCCEEDED`。

中途你说"改成放到右边垫子上"，就是 revision 2 提案 + 安全点切换；中途断电重启，就按持久化的事件与快照恢复（**恢复后只接受更新的证据，旧观测不会变成新证据**）。

### 四、第一次打开仓库，按这个顺序读

1. `README.md`：一条命令 + 一句话任务，先看它想干什么；
2. `docs/README.md`：文档索引按"你想做什么"分组（装机、标定、建图、接实机、发版）；
3. `docs/production/architecture.md`：完整架构（就是本期头图那张）；
4. `docs/development/single-robot-loop.md`：当前主线的感知-执行-恢复链路；
5. `core/closedloop/`：闭环契约的判定与失败分类——**全项目最该先读的代码**；
6. 想直接跑：`make setup` 然后 `make home-furnished`，打开 `http://127.0.0.1:8897/`。仿真**不需要显卡，也不需要任何 API Key**。

## 正文（精简版 · 普通图文 1000 字以内）

我做了一套机器人的"操作系统"：说一句中文，它自己拆任务、走过去、看懂现场、把活干完，而且每一步都留下能回放的证据。这是一个**分布式 AgentOS**：云端可以调度多台机器人，也可以把"大脑"装在机器人身上离线跑，两种形态共用同一套运行时、工具和观测契约。

整体分八层：①控制台（`web/`、`console/`）②理解与规划（`agent/`、`orchestration/`，已知意图走确定性，歧义要澄清）③任务与协调（`tasks/` 的**不可变版本**、`fleet/coordinator/` 的单写派发与租约）④世界模型与裁决（`core/worldmodel/` + `core/harness/`，**不相信"工具调用成功"这一个信号**）⑤执行与安全（`edge/`、`edge/runtime/`，仿真与实机只换适配器）⑥机器人能力（导航、抓取、标定、建图）⑦本体适配（新机器人走 Profile → Backend → Runtime 一条路）⑧契约层（`proto/robot/v1`、世界快照、三维重建）。

一句话任务的旅程：创建版本 → 控制台复述理解与步骤 → 你审批 → 协调器派发 → Runtime 执行并回报观测 → WorldHub 生成新的世界快照 → Harness 核对后置条件 → 满足才继续。中途改需求是"改版 + 安全点切换"，断电重启按事件与快照恢复，**旧观测不会变成新证据**。

第一次读仓库的顺序：`README.md` → `docs/README.md` 文档索引 → `docs/production/architecture.md` → `core/closedloop/`（全项目最该先读的代码）→ 跑起来：`make setup` + `make home-furnished`，仿真不需要显卡也不需要 API Key。

这是我"从零到一入门机器人开发"系列的第 01 期，后面每期讲一个模块（底盘、标定、SLAM、导航避障、抓取、任务图、分布式恢复、真机）。仓库：https://github.com/SUSTechWLA/tangying-robot-agent-os
