## 正文

我做了一套机器人的"操作系统"——从底层 RGB-D SLAM、导航避障，到上层听懂人话、拆任务、抓东西，全是自己写的。现在它已经能在一个装修好的家里，**自己把整间屋子扫成地图，再听懂一句中文去干活**。做完这周最后一次验收，我盯着控制台笑了很久，想认真记录一下。

🗺️ **第一件事：它自己把家扫了一遍**
没有人遥控，没有底图。它自己找未知区域、规划路线，一段段把客厅、走廊、厨房、卧室、卫生间扫出来，一次跑完探明 **81%**，五个房间的工作区全部可通行。第二张图就是控制台里的地图面板：三维点云、房间标注、走过的轨迹全都留着。

✅ **第二件事：它听懂了中文，而且做完了**
任务记录里 40 条任务，验收那四个全是"任务已完成"：`从客厅出发，去厨房确认一下环境`、`巡检卧室和卫生间，最后回到客厅`、`从客厅出发，去厨房拿杯子，放进收纳盘，然后回到客厅`。
最后那条是完整链路：导航 → 到位 → 找到杯子 → 抓起来 → 放进收纳盘 → 回客厅。每一步都留下**同一次采集的原始 RGB-D 证据**，不靠事后补拍。

🔍 **第三件事：点开任意一帧，都能看见它当时看到了什么**
关键帧面板里每一帧都能点开：RGB 和深度预览、原始里程计、优化后的地图位姿、位姿修正、有效深度比例、配准与回环（RMSE、内点率、对应点数）。**做机器人最怕"看起来对了"**，所以我给自己留的是可回溯的证据链。

📉 **第四件事：我把误差量出来了**
我给自己写了评测夹具：同一条路线、真实渲染的 RGB-D 喂给 SLAM，和仿真真值对比。无漂移时误差 **0.2–8.5 毫米**；注入 4% 里程计漂移后压回一半左右（room 43.3 mm，纯里程计 84.9 mm）。改前的数字也留着：接受的配准 2/6 → 42/61，无漂移 ATE 12/4 mm → 0.60/2.60 mm。**先量，再改。**

🔧 **最近踩的三个坑（真实、且都很疼）**
1️⃣ 一段航迹的最后 124 个关键帧被位姿图拉偏 **0.38 米**——查到最后是"原地转身时深度配准发明了位移"：里程计说没动，配准却算出 6.8 厘米；修完逐帧修正最大 0.027 米，走廊里那五面"平行假墙"全消失。
2️⃣ 地图自相矛盾：**23% 的占用格在自己的点云里没有任何证据**——界面上看不到那个"障碍"，机器人却死活不肯过去。
3️⃣ 关键帧面板突然全空：后端把"配准被拒的原因"写进状态字段，前端白名单不认识，于是每一张真实地图都被判格式错误。今天修好了，也顺手加了"仅里程计"标记和 ←/→ 翻帧。

🧭 **这套系统的原则（我最在意的部分）**
· 未知区域一律不当作可通行——没看见就是没看见；
· 每一步运动都要有**同一帧深度**证明前方安全，证明不了就停下如实报告；
· 最终安全判定在驱动边界，用真实 CAD 做碰撞检查，净空按"实测包络 + 明确余量"给，不留祖传常数；
· 每次拒绝、失败都写清原因并留证，可复盘。

🦾 技术上它是 Go + Python + MuJoCo + ROS 2：参考实现里是点面 ICP + 局部子图配准 + 位姿图/回环的 RGB-D SLAM、前沿探索自动建图，以及 Nav2(NavFn + DWB) / RTAB-Map 的部署路径。**代码开源**（Apache-2.0），仓库地址放评论区～

最后说一句正事：**我在找具身智能 / 机器人软件相关的工作**（SLAM、导航、机器人 Agent 与系统方向）。上面这些不是 PPT，是能跑、能复现、有数据的工程。如果你们团队在做机器人、缺一个愿意钻到底层也愿意抠验收细节的人，**求内推、求聊聊** 🙏

机器人这条路我走了很久，还会一直走下去。🤖
