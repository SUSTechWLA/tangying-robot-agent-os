# 第 02 期：为什么要分布式

"从零到一入门机器人开发"系列的**第 2 期**。面向**机器人工程背景、但没系统学过分布式**的读者：他们熟悉 ROS、SLAM、控制与标定，却常常觉得"分布式""高并发""高可用"是后端的事。本期就是把这件事翻译成机器人语言。

## 本期要回答的三个问题

1. 本地跑一个 agent 也能控制机器人，为什么还要分布式？
2. 分布式系统相比本地方案，好处到底在哪儿？
3. 做机器人的人该在什么阶段、因为什么信号，才真的需要它？

一句话答案：**机器人的执行体不能"再开一个"，所以分布式的动机不是扛并发，而是让多个写者不会同时改同一个物理世界。** 详见长文。

## 口径边界

- **断网停止，不是断网继续跑。** 这是本期最容易说过头的一条，出处表 §3 专门记了这次修正：不向离线机器人分派、恢复后重新注册、持物时现场处置并提高 fencing（依据 `docs/production/operations-and-failures.md`）。
- 恢复能力限于**单主进程重启范围内的一部分状态恢复**；跨主机共识、跨存储事务、数据库/队列切主仍在"仍须独立验证"。
- 主线一台机器人；云端 Fleet 是已实现的扩展路线。
