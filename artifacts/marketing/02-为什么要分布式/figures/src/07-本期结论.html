为什么是分布式·07·本期结论

分布式系统真正给你的，不是算力

是一份事先写好的承诺：出了事，我知道去哪儿查、谁会接手、退到哪里。这是本地 agent 给不了的。

一张表说清：为什么本地 agent 不够用
维度 本地 agent 分布式 AgentOS
服务几个执行体 1 个进程，1 个执行体 控制面 + N 个边缘节点
任务状态在哪儿 在内存里 持久化事件与快照，可重放
进程重启之后 任务从头再来 按事件与快照恢复，旧观测不算新证据
谁能改世界状态 任何拿到进程的人都行 单写协调 + 资源归属 + fencing 挡越权
网络断了会怎样 能力全丢 控制环本就在本地；停机等待，恢复后对账
消息重复了怎么办 工具会白跑第二遍 幂等键去重，低 fence 完成被拒
证据从哪来 只有日志文件 证据链 + 世界快照版本，Harness 裁决
谁批准了动作 事后无从查证 审批与任务版本绑定，可逐条回溯
加第 N 台机器人 上层代码跟着改 加一个适配器，上层不变
本体换了怎么办 任务与工具重写 接口不变，换适配器
左列每一条都不是假设出来的失败：它们对应单机写法里必然会遇到的一次断网、一次重启、一次重复下发。
01

写机器人程序时，你已经有一个执行体。写机器人系统时，你必须假设执行体会死。

分布式不是把代码拆开，而是把“会死”写进设计。

02

数据库可以回滚，机械臂不能。

所以机器人系统对“不确定”的处理必须比后端更保守：宁可停下等人，也不猜一个成功。

03

云端负责慢的对账，边缘负责快的控制。

快的环不依赖网络，慢的环不依赖内存——这就是分层的全部意义。
