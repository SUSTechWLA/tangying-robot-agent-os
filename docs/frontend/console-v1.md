# 躺营机器人工作台：用户界面与开发诊断

这轮改版将默认界面整理为工作台、任务记录、我的机器人三个入口；开发诊断通过左下角的“开发模式”进入。使用明亮底色、紫蓝主操作色、中文状态与较大的阅读字号，现场视图保留深色背景以帮助识别空间。

2026-09-08 新增 Local 单机器人相机主视图：彩色、深度与观测点云按真实数据及新鲜度启用。点云只渲染标准重建中的 points/entities；不生成默认桌面、机器人或隐藏物体。无数据显示未知，旧语义图只在开发模式作为模拟状态诊断。Local 顶部与底部 RGB-D 相机统一读取 `/v1/scene/camera?adapter=...&sourceId=...`，一次返回同次采集的 snapshot、彩色和深度 PNG；不将另一次遥测的点云拼到当前图像上。旧仿真调试画面仍使用 `/v1/scene/frame`。下文 Fleet 旧画面的接收时间限制仍适用。任务历史证据与实时画面分开，原理见[单机器人闭环](../development/single-robot-loop.md)。

## 日常使用

- **工作台**：查看当前环境和连接状态，输入自然语言任务。示例按已识别的 MuJoCo/RoboCasa 环境提供，点击只填入输入框，不发送指令。尚未识别或真实机器人环境不推荐未经确认的仿真任务。
- **Fleet 场景展示**：工作区上方直接切换“三维场景 / 简洁视图 / 机器人画面 / 全局地图”，浏览器记住上次选择。三维与简洁视图均保留总览、俯视、1/2 号机器人视角和跟随。总览从上方朝工作区内部观察；已有自定义角度可点击“总览”复位。
- **显示选项**：展开后独立切换场景模型、构件边界、对象标签和任务路径。默认关闭密集对象标签与构件边界。桌面支持“放大”场景，点击“退出放大”或按 Esc 返回。
- **任务执行**：本地模式先生成任务，再批准物理动作；Fleet 保留现有“创建并开始任务”流程，并明确说明会立即执行。提交期间按钮禁用，错误和不确定结果在用户界面直接显示。
- **任务进展**：创建或选中任务后展开理解、步骤、动作和结果。更新任务默认折叠，仍保留预览与确认流程。取消不代表实体急停。
- **任务记录**：Fleet 可用鼠标或键盘选择历史任务并回到工作台。Local 也读取持久化历史，默认按更新时间选最新任务，切换任务隔离迟到响应，不重新审批或执行。
- **我的机器人**：显示设备、连接、运行环境和相机画面；租约、内部版本等信息仅在开发模式展开。
- **异常**：断线、场景过期、视觉层降级，以及多机器人急停与观测异常均有用户可见提示。场景同步不等同于机器人获准执行。

桌面使用左侧导航；手机使用底部导航。页面具有键盘焦点、跳转到主要内容、状态反馈和减少动画设置。

## 画面帧率、尺寸与刷新

Local 的彩色、深度、点云使用同一固定视口：默认 16:9，窄屏最低高度 280px、最高 62vh。图像保持原始比例，必要时留边；点云画布按实际视口比例调整，并以已观测工作区拟合视角，不添加未观测几何。切换不会因为图片固有尺寸改变页面高度。

画面左下角显示实际显示帧率与“画面 N 秒前”。FPS 只计入成功解码、实际发布的不同采集帧；点云只计入新采集，拖拽或重复重画不计帧。统计最近 5 秒中相邻成功帧的间隔，停止更新时逐渐下降；不足两帧显示“采样中”。它不是网络请求频率、浏览器动画帧率或相机额定 FPS。画面年龄来自原始采集时间，不使用浏览器接收时间冒充新观测。切换相机或模式、隐藏后返回会重新采样。

图像在独立 image 元素中准备完成后，才与同次 snapshot 一起发布。等待期间可保留上一帧，但显示“正在切换／暂显上一帧”、实际旧来源和模式；左下角持续显示其真实年龄。无效、过期或解码失败的观测显示未知，迟到的旧相机／旧模式回调不能覆盖新选择。历史证据始终保持用户选择的 capture，不被实时刷新替换。

同一相机和模式已有请求或解码进行时，定时刷新会等待它完成，不会每轮取消较慢的有效画面。超过 5 秒的请求会在轮询时回收；这不会延长观测自身的 2 秒有效期。切换相机、模式或页面仍立即撤销旧请求的发布权。

离开工作台或隐藏浏览器标签，会中止相机请求与待发布图像，停止点云绘制及导航地图的前端读取；返回工作台立即获取新观测。设备与诊断页只拉所需遥测元数据，指标与世界摘要仅在诊断页轮询，任务记录列表仅在记录页自动刷新。任务事件、运行状态和恢复安全状态继续更新，机器人任务不会因切页、隐藏或关闭前端而被暂停。重复的列表、步骤和工具卡数据保留现有 DOM 节点，避免打断键盘焦点和滚动位置。

调试定位：`#scene-stage` 为统一视口，`#scene-frame` 与 `#scene-canvas` 共用边界；`#scene-frame-stats` 的 `data-fps`、`data-capture-age-ms`、`data-source-id`、`data-mode` 对应实际显示的数据。`console_ui.js` 在路由变化时发出 `tangying:page-change`，由 `app.js` 管理请求代次、可见性和解码发布。该事件只控制界面刷新。

## 开发排查

进入“开发模式”后，在“开发诊断”中查看：

- 当前任务编号、世界版本、事件游标。
- 世界观测来源、资源监护权、Harness 结果。
- 执行事件、命令与步骤证据、全局地图、原始遥测。
- 关键词筛选；实时刷新和新增日志后继续保持筛选。
- “复制排查摘要”：按允许字段构造 JSON，包含关联编号和状态，不包含登录凭据、模型配置或原始任务内容。

普通状态提示来自现有运行时回调。`web/console_ui.js` 管理导航、模式、文案、摘要和示例；`web/app.js` 继续负责 API、任务协议、授权流程与场景生命周期。切换页面不会重建运行时连接，也不会提交或取消任务。

`GET /v1/tasks/{id}/experience` 当前返回完整快照，没有 `cursor` 字段；任务执行进展不保证增加 `aggregateVersion`。同一任务版本的新步骤/活动仍需刷新，不能按“版本没变”丢弃。Local/Fleet 都隔离重叠请求的迟到响应；若未来收到非零游标，仍拒绝重复/倒序数据。`updateStatus=ACTIVE` 只说明版本生效，完成状态结合 Task 的 `state` 展示。WorldSnapshot 的同版本事实约束不受此规则影响，见[数据契约](../production/data-contracts.md)。

四种展示共用同一世界与任务连接。机器人画面复用 `GET /v1/scene/frames` 及各机器人图像接口，工作台与设备页共享下载和 Blob URL；单次轮询超时为 5 秒，避免重叠下载，退出登录会中止请求并释放图像。接收失败后保留并标记最后画面。时间表示浏览器收到图像的时间，当前接口没有相机采集时间，不能据此保证图像拍摄的新鲜度。工作台地图复用 `GET /v1/maps/global`，每 30 秒更新，开发诊断仍可查看栅格详情。

隐藏三维视图时继续校验世界模型身份和观测，暂停 GPU 绘图与画布尺寸调整。切回后使用最新已接受的世界状态，避免高像素密度屏幕把隐藏画布的像素尺寸重复放大。

## 开发预览与简化场景排查

已有 Fleet 服务运行在 18080 时，可直接预览当前工作区前端：

```bash
CONSOLE_BACKEND_URL=http://127.0.0.1:18080 node scripts/preview-console.cjs
```

打开 `http://127.0.0.1:18130/#workspace`；端口可通过 `CONSOLE_PREVIEW_PORT` 修改。该脚本仅监听本机，适用于开发。HTML、脚本、样式读取当前 `web/`；`/assets/`、`/v1/`、`/healthz` 与 WebSocket 指向同一后端。生产部署使用同一构建中的 Go 嵌入前端和对应仿真资产。

WebSocket 转发保留浏览器侧 Host 与 Origin，以通过后端同源检查；不删除 Origin 或关闭校验。若 REST 有新观测而页面显示延迟，核对 WS 是否因代理改写 Host 被拒绝。页面预览只更新前端；要测试当前 Agent 代码，后端也须从当前检出构建。可使用[隔离自然语言评测](../development/natural-language-evaluation.md)的 `--keep-running`，将其 `ready.json` 中的实际地址作为 `CONSOLE_BACKEND_URL`，不要照抄上次随机端口。

若“三维场景”自动显示简化几何，开发诊断中的 `VISUAL_MODEL_MISMATCH` 表示模型身份校验失败。曾出现的原因是预览代理把当前仓库模型与另一运行版本的世界数据混用。现在预览入口统一资产与数据来源，避免这类混用；不能通过关闭身份校验消除错误。仍失败时核对运行环境、manifest 的 `modelHash` 和世界实体的 `model_hash`，再点击“重新加载场景”。无 WebGL、资产下载失败也会显示具体原因，其他展示仍可使用。

## 未来发布纯用户端

`web/index.html` 提供明确的展示配置：

```html
<meta name="tangying-console-edition" content="operator" />
```

当前开发版本为 `full`，默认仍进入用户模式。设置为 `operator` 后不显示开发开关，开发路由会回到工作台；刷新也不会沿用开发模式。配置需由发布构建设置，而不是通过 URL 参数控制。

这是展示能力开关，不是权限边界，也还不是独立构建包。正式分发纯用户端时，应进一步拆出开发资源，并按服务端角色限制诊断、配置和控制 API；CSS 隐藏不能代替访问控制。

认证仍由后端决定。仅当 `/healthz` 明确返回 `authMode: "demo"` 时，页面调用后端提供的 `/v1/auth/demo-session`。普通部署继续要求操作员登录；演示登录失败不会伪造已登录状态。
