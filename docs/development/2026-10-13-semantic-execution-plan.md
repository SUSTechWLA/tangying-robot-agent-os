# 点云语义到长程导航：实施计划与评估边界

日期：2026-10-13；源码基线 `56309f667983c08c04dae004b9f60d92f2b08709`。这是上一轮点云语义标注之后的独立扩展，旧实验结果不改写。

## 判断与方案

当前最有价值的升级是接通已有点云语义、任务权威和导航闭环。三维点云记录测量几何，标签及空间关系支持目标检索，实时定位和障碍观测决定当前可执行路径。语义标签不替代可通行性、实体重识别和动作后验证。

[VLMaps](https://vlmaps.github.io/) 将视觉语言特征与三维重建结合以支持语言导航；[ConceptGraphs](https://concept-graphs.github.io/) 从带位姿 RGB-D、分割及多视角关联构建对象和关系图。它们说明这条方向有研究依据，但不是本项目已经具有开放词汇识别的证据。[Nav2 的传感器与地图说明](https://docs.nav2.org/rolling/configuration_and_development/first_time_robot_setup_guide/sensors/mapping_localization/)区分静态地图、定位和实时障碍层。本文据此采用几何、语义与执行分层。

三种路线的比较：

| 路线 | 对当前项目的作用 | 本轮选择 |
| --- | --- | --- |
| 人工/已有感知标注 + 点云身份 + 现有导航 | 能直接复用地图、Runtime、任务账本及安全闭环，适合先验收执行能力 | 实施 |
| RGB-D 掩码投影与多视角语义融合 | 提高标注自动化，需要原始深度、掩码、位姿及关联评测 | 保留接口；不把深度伪彩预览当原始测量 |
| 开放词汇对象图与跨机器人语义地图 | 支持复杂关系检索，需要模型、坐标对齐、动态更新和系统性数据集 | 后续独立工作；不承诺本轮全图理解 |

## 实施顺序

1. 只读审计由执行、长程任务、感知三个子 Agent 独立完成。确认 `semantic.plan` 只提供候选，`navigation.navigate` 已有 Runtime journal、安全准入和 Nav2；避免新建绕过这些机制的 Python 运动入口。
2. 扩展 `robot.task` 的结构化语义路线输入，冻结地图/标定/点云/语义身份及目标标注 ID。模型不提交坐标。各阶段在执行时重新取得候选，保留已完成阶段与恢复绑定。
3. 候选携带 Runtime 签发的目标绑定；导航与到位验证都核对目标和版本。运动中基础身份变化时停止该段，未知运动结果保持待对账，不自动重发。
4. 新增读取真实内部感知的语义复核。到达观察位与识别到对象分开；零匹配、歧义、过期或错来源不成为成功证据。显式旧位置搜索不能刷新标签的观测时间。
5. 测试规划冻结、逐段 grounding、运行时篡改/版本变化/取消、恢复不重放及感知错配；运行新的 Gazebo 多目标自然语言任务并记录实际结果，失败尝试同样保留。
6. 更新指南与实验报告，修正基线远程 CI 中 README 测试函数数量过时问题；提交、推送现有功能分支并更新 PR。

## 预先约定的实验边界

- 新 Gazebo episode 复用历史有效地图，保留地图来源和摘要；不复用旧任务数据库或命令 journal。
- 人工点云巡检区域使用中性标签，不假称由模型自动识别房间。真实移动完成以唯一命令、动作后位姿、独立到位判据及 RGB-D 证据验收。
- 每个目标明确是到达观察位，还是还要求唯一对象感知匹配；二者不能混算识别成功率。
- 过期标注若明确允许搜索，只作为旧位置线索；当前路径仍需测量支持，目标存在性仍需重新感知。
- 不支持的真实移动底盘、空检测器、多楼层或跨机器人配准必须保持不可用；不因点云查询成功就启用运动。
- 原始文件、代码与二进制身份、命令、时间、失败、重试和证据摘要分别保存。模拟/回放/真实 Gazebo/真机证据各自报告。
