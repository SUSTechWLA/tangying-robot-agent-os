## 实施顺序与验收

1. 源码审查：分别核查单机 Host 的授权/取消/长程恢复、peer 数据持久性/隔离、教材事实与公式。只选择有具体失败场景的修复，避免为了“分布式”重写已有可靠机制。
2. 模型边界：实现显式可选、按作用域派生的缓存提示与稳定规则前缀；保留工具 allowlist、完整请求归档和当前权限重查。收集真实服务响应报告的 usage、缓存 token 和请求耗时；缺失不当成零，缓存不变成任务权威。
3. 运行时缺口：依据审查结果修复可复现的授权/通信窗口，补故障测试和持久重启验证。
4. 系统验证：本次包含运行时代码，执行相应 Go 功能/故障/race 测试及软件长程任务；按需要构建本地与 Linux ARM64 边缘入口。区分脚本模型、设备夹具、真实模型、仿真与实机。此前仅教材发布的“跳过流水线”不当作本轮运行时已验证的证据。
5. 教材 3.2.0：以实际修复反推不变量、公式与取舍，增加概念场景插图及精确矢量图，保存 3.1.0 源身份，构建离线 HTML/EPUB，留下指标与未覆盖条件。
