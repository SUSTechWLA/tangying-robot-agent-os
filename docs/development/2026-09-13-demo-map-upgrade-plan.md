# 家庭演示与已保存地图浏览升级

用户目标：使用更真实的开源房间资源承载现有移动机械臂，改善演示和 RGB-D SLAM 成果；已保存点云应有清楚的色彩、可点击的标注和局部聚焦。

## 约束

- Robot Agent OS 仍然只通过注册服务操作机器人，环境类型留在驱动内部。
- 地图浏览只使用所选版本保存的点云、轨迹和语义文件；不得把场景真值或当前实时物品位置冒充历史采集结果。
- 原始 RGB 必须可查看；辅助色必须说明含义。本机浏览标记与机器人导航标注明确分开。
- 优先复用本机已下载且许可清楚的场景资源。下载资源留在忽略目录，提交来源、固定版本和可复现准备脚本。
- 真实扫描场景与人工搭建的交互场景如实区分。不能把仅展示模型声称为已验证的导航或抓取能力。
- 当前工作分支 codex/map-readability；完成检查后遵循用户先前授权合入 main 并推送。

## 实施任务

1. 改造保存地图浏览器：保留原色，增加高度辅助色、适合小地图的完整细节、三维/俯视/全图、保存语义的标签与点击聚焦、轨迹开关、本机点云浏览标记。完善空数据与请求切换处理，紧凑布局和必要测试。
2. 核实可用真实房间/交互环境及许可，检查现有 RoboCasa 与 AWS 家庭资源，接入能使用当前机器人、传感器和动作服务的丰富场景；记录实际完成的能力。
3. 浏览器验证地图交互，运行场景和机器人相关检查；必要时重新采集地图并运行任务验收。更新使用文档及资源归属。
4. 独立审查差异、修复发现、构建测试、合并推送。

## 接口划分

地图任务拥有 web/ 下的地图渲染器、控制器、页面和样式；场景任务拥有 sim/、scripts/ 和资源生成。场景工作台的渲染改动需要先约定，避免修改同一代码段。两者通过现有地图 manifest 与机器人服务接口连接，无需新增环境特判。

用户追加：进一步增加家具与生活物品、厨房和卫浴瓷砖等装修细节；扩展有真实感知与动作证据的家庭自然语言测试场景。静态装修和可移动任务物品分开实现，保持已标定通道可用。最终家庭模型移除彩色杯测试物，改用陶瓷杯、收纳盘和日常陈设；感知使用受限工位的 RGB-D 几何观测。旧无资源包工位仅作为兼容回归基线。

最终验收要求：归档旧演示运行数据，用独立的任务、地图和标定目录启动装修家庭模型；通过注册服务完成标定、移动采集 SLAM、启用地图，再经自然语言任务入口完成巡检、厨房观察和杯子收纳后返回客厅。保留原始观测与逐步回执，明确仿真验收不等于训练完成或实机迁移成功。

追加关键帧诊断：保存接受的 SLAM 关键帧的时间、相机来源、原始里程计、优化位姿、修正量和配准/回环质量；地图位置可点击打开详情弹窗，查看同一次采集的 RGB/深度预览。数据与所选保存地图版本绑定，并设置资源预算。旧地图只能展示真实保存的信息，未保存图片不能借用当前相机补齐。
