# 标定与建图的 ROS 方案与精度门禁

用 ROS 2 生态里成熟的包做标定与建图，而不是自己实现视觉标定算法；但**每一项标定都必须有一个留在测试里的精度门禁**，否则"标定过了"只是一句话，不是结论。

现状：RTAB-Map 负责 SLAM、Nav2 负责导航、`tangying_navigation` 桥已提供 HTTP 接口；标定契约 `robot.calibration.v1` 与整机标定向导已在上一轮实现。本页补充的是**用哪些 ROS 包、按什么顺序、达到什么精度才算通过**。

## 1. 相机内参：`camera_calibration` + ChArUco 板

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 包 | `camera_calibration`（ROS 2 官方） | 输出标准 `camera_info` 的 `K`/`D`，可直接填入 `robot.calibration.v1` 的 `intrinsics` 与 `distortion` |
| 靶标 | **ChArUco**，不用纯棋盘格 | 部分遮挡、倾斜、边缘处仍能给出角点；头部相机俯角大、底盘相机接近鱼眼，纯棋盘格在画面边缘常常整帧丢弃 |
| 采集 | 15–25 个位姿，覆盖画面四角与中心 | 只在中景拍够张数会让畸变系数不可信 |
| **精度门禁** | 重投影 RMS **< 0.5 px**，且四角与中心各自的分区 RMS 都不超过 1.0 px | 只看整体 RMS 会掩盖"中心很准、边缘很差"，而抓取用的是边缘 |

畸变模型先固定为 `plumb_bob`（契约里已支持）；如果底盘相机收窄视场后仍有明显桶形畸变，再考虑 `equidistant` 并同步扩展契约。

## 2. 手眼标定：精度决定性环节，优先做

抓取精度几乎完全由这一项决定：相机看到物体 → 末端要到哪，靠的就是这个变换。

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 包 | `easy_handeye2`（ROS 2）+ `MoveIt`/关节轨迹执行 | 标准 AX=XB 流程，自动采集与求解，自带 `Tsai-Lenz`、`Park-Martin` 等解法 |
| 靶标检测 | `aruco_ros` 或 `fiducials` | 与 ChArUco 同族，检测稳定、给全 6DoF |
| 布置 | **eye-in-hand**：靶标刚性固定在夹爪上，相机看它 | 与相机装在同一链路上，标定结果直接可用；eye-to-hand 需要额外确认靶标绝对位置 |
| 采集 | 15–20 个位姿，**平移与旋转都要铺开**（不要只绕一个轴转） | 位姿退化是手眼标定最大的精度杀手，工具会给出退化提示，必须看 |
| **精度门禁** | 用**留出位姿**验证：平移残差 **< 5 mm**、旋转残差 **< 0.5°** | 用参与求解的位姿自评会偏乐观；留出集才是真话 |
| 前置依赖 | 关节零位先标定（整机标定向导已完成） | STS3215 无绝对编码器，零点错了手眼结果会整体偏移 |

**这一项是实机全流程里唯一无法用仿真替代的环节**，也是我建议第一个在真机上做的。

## 3. 双 RGB-D 外参：优先用运动法，不依赖共同视野

实测（仿真模型）两机共同可见体积约 **0.36 m³**（占采样体积 6.0%），够放靶但余量不大。真机安装未必有这么好的交集，因此**不把"两台相机同时看见靶"作为唯一路径**：

| 方案 | 何时用 | 精度门禁 |
| --- | --- | --- |
| **A. 共同视野 + 靶标** | 交集体积 ≥ 0.15 m³ 且能放稳 ChArUco | 两机各自 PnP 后合成的外参，在留出靶位上的重投影残差 < 10 mm |
| **B. 运动法（推荐备选）** | 交集不足，或底盘相机视野落不到靶上 | 已知底盘运动（直线 1 m + 原地转 90°）后，两路点云配准残差 **< 10 mm** |
| **C. 由手眼推导** | 头部相机在手眼标定链路上 | 用里程计把头部相机外参推到同一时刻，与实测外参对比 < 15 mm |

方案 B 依赖里程计精度——这也是**必须单独标定里程计**的原因（见下）。

## 4. 里程计标定：地图质量的地基

RTAB-Map 的位姿图以里程计为先验，里程计尺度错了，地图整体就是错的。

| 项 | 做法 | 精度门禁 |
| --- | --- | --- |
| 直线 | 直行 2 m，卷尺实测 | 距离误差 **< 2%** |
| 旋转 | 原地转 360°，回到起点朝向 | 角度误差 **< 2°** |
| 回环 | 绕房间一圈回到起点 | 起点位置漂移 **< 50 mm** |

第三项同时是**地图质量的最终判据**：漂移小于 5 cm 才说明这张图可以拿来跑跨房间任务。

## 5. SLAM：继续用 RTAB-Map，但要开对参数

| 参数 | 建议 | 理由 |
| --- | --- | --- |
| `Reg/Strategy` | `1`（RGBD + ICP） | 深度质量好的室内场景，ICP 精配准显著降低漂移 |
| `Grid/RayTracing` | `true` | 占据栅格用射线穿透标记自由空间，覆盖率指标才有意义 |
| `Rtabmap/DetectionRate` | 2–3 Hz | 太高会在慢速探索时重复入图，太低会漏回环 |
| `RGBD/ProximityBySpace` | `true` | 室内回环主要靠空间邻近触发 |
| `Kp/MaxFeatures` | 按分辨率评估，不照搬 320×240 的值 | 现有文档已警告过该参数不能跨分辨率照搬 |

**建图覆盖**继续用已实现的 `mapping_coverage.coverage_report()`：覆盖率、frontier、位姿均匀度、回环、深度有效率、运动过快，并把它反解成"下一个该去哪、怎么走"。

## 6. 顺序（按精度影响从大到小）

1. **里程计标定**（第 4 节）——地基，且是运动法外参的前提
2. **手眼标定**（第 2 节）——决定抓取精度，必须真机
3. **相机内参**（第 1 节）——畸变不修，手眼与外参都会被污染
4. **双 RGB-D 外参**（第 3 节）——优先运动法
5. **SLAM 建图 + 覆盖指标**（第 5 节）——最后一步，也是前面所有精度的综合体现

## 7. 统一出口：标定结果都写进同一份文档

无论用哪个 ROS 包，结果都填写进 `robot.calibration.v1`：内参与畸变进 `cameras.*.intrinsics/distortion`，外参与手眼进 `cameras.*.extrinsics`（手眼结果记录在 `geometry` 下作为末端-相机关系），里程计标定系数进 `geometry`。这样：

- 运行时与 Agent 仍然只看契约，不关心数据来自哪个包；
- 修订号是内容哈希，**换一次标定就换一个版本号**，任务证据能指出它是在哪份标定下采集的；
- 精度门禁可以写成契约层测试：不合格的标定在保存前就被拒绝，而不是等到抓偏了才发现。

## 8. 尚未实现

本文是方案。已实现并可测试的是：标定契约与校验、整机标定向导（20 步、24 项测试）、建图覆盖指标与相机交集检查（11 项测试，含对仿真模型的最小可用交集断言）。**未实现**：上述 ROS 包的接入封装、各精度门禁的自动判定、以及全部实机现场验收。
