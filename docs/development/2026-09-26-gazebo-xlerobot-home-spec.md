# Gazebo XLeRobot 家庭闭环升级规范

状态：2026-09-27 完整 Gazebo 家庭自然语言闭环实测通过；验收身份、软件门禁与边界见[逐轮报告](../experiments/2026-09-26-gazebo-xlerobot-home-closure.md)。保留旧实验记录，不覆盖历史结果。

## 目标与边界

- 唯一家庭资源源头为 `sim/mujoco/assets/xlerobot_home.xml`、XLeRobot CAD 和已调通的 furnished-home 资源包。四个房间、走廊、家具及厨房陶瓷杯/收纳盘保持同一布局。
- 构建阶段将已配置的 MuJoCo 模型导出为 SDF、网格、材质和标定清单。Gazebo 运行时与 Agent 不依赖 MuJoCo。导出保留连杆、关节轴/范围、惯量、视觉和碰撞几何；不得用差速箱体替换三轮全向 XLeRobot。
- 基座使用有超时和速度限幅的平面速度驱动，模拟参考原型的底盘控制接口。轮胎牵引、真空压力及实机接触控制认证不在本次软件闭环证明范围内。抓取仍必须通过真实仿真物理附着、释放、支撑及稳定性检查。
- Agent 仅使用 Runtime profile、工具、传感器、地图与任务语义；仿真器差异由适配器承担。不同机器人通过 profile 声明关节类型、工具、动作限制及证据源，不能假设所有机器人都是双臂移动底盘。
- 家庭对象检测共用测量 RGB-D 几何算法；模型初始位姿、分割 ID 与物理真值不得作为检测输入。物理状态只用于驱动内部抓放验证和独立验收。

## 验收要求

1. Gazebo 实际启动同源 CAD、完整家庭，发布新鲜 RGB-D、关节、IMU 和里程计。
2. 完成地图建立、保存、激活与版本绑定；禁止错误地图静默复用。
3. 通过自然语言任务完成卧室/卫生间巡检并返回客厅，厨房观察往返，厨房杯子放盘并返回客厅。
4. 动作由 Runtime 安全、取消、持久化日志和观察证据边界执行；失败不得靠重置物体、瞬移底盘或伪造到位修复。
5. 验证未知目标拒绝、取消/停车与跨架构契约；保留真实失败记录和复测证据。
6. 更新部署指南、资源入口、接口说明和变更报告，记录命令、版本、资源摘要及剩余实机认证项。

## 资源清理规则

删除由旧 Gazebo 差速模型及独立彩色工位产生的闲置操作入口。保留 XLeRobot 原始 CAD、上游版权、自动化契约所需异构机器人测试夹具及历史实验报告。生成资源可重建，原型源文件不可删。

## 2026-09-27 补充约束

- RGB、Depth 必须为同一个传感器时刻；内参使用驱动实测 CameraInfo，保留主点。捕获时位姿不得由最新里程计覆盖。驱动只能在有界、夹住时刻的测量之间插值；不得外推缺失测量。
- 位姿估计器接受驱动测量不确定度配置，并将该配置写入地图溯源。理想仿真参数不构成实机认证；不同机器人须完成独立标定。
- 已保存地图的资源、标定、版本与净空必须通过导航准入。准入路径与实际导航提供者分别标识，成功必须有动作后新鲜观察及到位验证。
- 放置稳定证据记录样本序列、采集时间、位置、最大位移和实际判据；允许已声明的末端/物理验证源。仿真物理反馈不得冒充相机检测或硬件传感器反馈。

- 工具声明的执行预算必须与 Runtime 允许的 command lease 上限一致。共享 Runtime 默认 60 s；已配置长导航动作的驱动显式选择有界上限，最大 600 s。该 lease 是动作的绝对预算，不能当作可无限续期的心跳租约。RPC 断连、超时、取消仍须停止正在执行的控制器；驱动不得在动作入口清除刚抵达的取消。

## 补充规范：原型工具坐标与夹爪独立控制（2026-09-27）

- 控制点不能默认是最后一个关节原点；原型的第六电机是活动夹爪，机械臂 IK 只有五个臂关节。
- 家庭吸附辅助工具坐标选在固定指末端 CAD pad 的中心附近：父链接 link5，局部平移 [0.012,-0.101,0] m。CAD pad 实测包围范围 x=[0.007863,0.016088] / y=[-0.106388,-0.095913] m。夹爪 1.5 rad 张开并独立控制，避免压入杯体。
- 文件 assets/gazebo_xlerobot_tool.json 是控制器与物理插件共同读取的工具标定配置；两边的完整 document 必须匹配。每份观测保留其内容 SHA-256 和版本。这份配置不改变相机标定或地图版本。
- 物理插件仍以实际工具点与实际杯心距离 <=0.09 m、身份白名单、命令有效期和占用状态作吸附入场；创建真实 DetachableJoint，不能写模型位姿。此模式为 sim_suction 辅助，不证明真实夹指力或真空压力。
- 从 RGB-D 测得杯心，工具点停在杯心上方 0.067 m；已知杯半高为 0.06 m，指端 CAD pad 厚度约 8 mm，保留约 3 mm 接近净空。目标位姿和抬升/转运/放置的整个工作空间必须在动作前预检。

## 补充规范：遮挡、载荷与捕获时序（2026-09-27）

- 工具配置 v2 为左右臂分别声明两段本体坐标观察航点。持物导致目标盘面不可见时，驱动允许一次有界主动观察，仍须保持所属任务、关节限制、竖直约束和取消响应；等待新 RGB-D 后仍不可见则拒绝放置，不循环搜索或用规划缓存补齐。
- 放置运动使用实际附着物相对 TCP 的局部刚体偏移来构造载荷中心 FK/IK，不能把世界坐标偏移当成固定工具偏移。先在原 XY 垂直上升到盘沿净空，再水平转运和下降；盘面目标来自当前视觉测量。
- 编码器状态和 CAD 表面过滤必须对应图像源时刻；不同步、缺少前后测量括号或间隔超过 100 ms 时拒绝组装。深度点仅在距机器人 CAD 表面不超过 4 mm 时排除，环境真值不得用于掩码。
- 命令完成后记录源时间下界，后置相机源时刻必须更晚。仅接收时间更新的旧排队帧不能确认命令。软件仿真时钟经同源前后锚点映射到墙钟及单调钟，保留源时间和 clock 来源，拒绝外推、跳变与过长间隔；实机须验证自己的采集时钟同步。
- 成功事件必须固定完整 command_observation 和原始图像摘要，然后持久化。相同命令重放原事件字节，不能重新执行或用新图像替换旧证据。

## 补充规范：命令日志与恢复（2026-09-27）

- Runtime journal v2 用内容摘要绑定的独立事件文件保存完整回执，原子索引引用事件文件。先持久化事件和目录，再提交索引；仅在索引提交后回收不再引用的事件。
- v1 在下一次持久化时迁移，保留回放、资源 fencing 和停止锁存。待核对或已核对的未知命令不得随普通终止历史淘汰。
- 缺失、损坏或非法引用的事件文件使重启锁存停止。恢复与备份必须同时保留 commands.json 和 commands.json.events/；不得删除未知结果日志后重发物理动作。

## 补充规范：导航视角与原生地图隔离（2026-09-27）

- 同源家庭在 MuJoCo/Gazebo 的导航 launch 读取同一家庭传感器 profile；显式声明 slam_camera，其他配置默认 base，非法选择拒绝启动。不得以配置文件已修改推断实际生效，应核对 ROS 订阅和实际参数。
- 本家庭采用固定头部 RGB-D 作为 RTAB-Map 输入，底盘与头部的原始深度共同用于 Nav2 和动作安全。仅在导航收纳姿态下，头部 SLAM 的词典/视觉深度范围为 1.05–4.9 m、原生网格最小范围 1.25 m；其依据为本机 CAD 可见范围。该型号配置不能复制为其他机器人或实机的认证结果。
- 更换导航相机或 profile 参数时，必须使用资源摘要和传感器 profile 摘要共同命名的新原生数据库，先建图再定位；保留旧图，禁止混合不同输入的视觉字典。保存地图仍保留自己的资源、相机标定和测量溯源。
- 当前帧/字典均至少 20 个视觉词、定位协方差、传感器新鲜度、碰撞和到位检查保持原有门槛；不能用降低质量门槛修复无纹理视角。

## 补充规范：任务派发前的能力等待（2026-09-27）

- 通用 Agent 对已声明但暂不可用的能力或 PhysicalReady=false，允许在调用方期限内、最多 2 s 刷新只读 Runtime 目录。只有实际新目录就绪才派发；该过程不调用 Invoke，不重新执行物理命令，不修改传感器时间或安全判断。
- 未知工具、身份不匹配、传输/profile 错误立即拒绝；持续故障和取消保持拒绝。此行为使用通用 Runtime 状态，不解释 Gazebo、MuJoCo 或特定硬件故障码。

## 补充规范：位姿测量的统计含义（2026-09-27）

- 相邻里程计增量的不确定度与世界坐标绝对位姿的不确定度分别声明。只有确有独立绝对锚定的驱动可以传 absolute_odometry_sigma，图优化才加入每帧绝对因子并在 provenance 留存；默认值为无绝对因子。
- 本家庭 PlanarDrive 的实际物理世界位姿同时声明相对/绝对 (0.001 m, 0.001 m, 0.001 rad)。该仿真测量模式不能转用于累计误差的轮式里程计，实机必须按其实际定位来源和校准结果配置。
- 不得用减少底盘足迹、删除有多帧证据的占用格或放宽未知区域，掩盖地图配准漂移导致的工作位准入失败。
