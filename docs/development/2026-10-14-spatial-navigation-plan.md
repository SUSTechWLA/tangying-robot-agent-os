# 2D、地形与 3D 空间导航升级记录

日期：2026-10-14。基线：`f2794e345d9419bb07b23ab123790ee0b6496b20`。
范围：ROS 2 边缘 Agent 的定位、建图证据、导航规划与执行边界。外部 SLAM 和设备控制器通过明确协议接入；不将点云文件、接口声明或记录式控制器当作实机性能。

## 现状与设计选择

现有 Dense SLAM、`RobotWorkflow` 的保存/续建/坐标锚点均为 SE2；点云可以保存三维坐标，但现有导航是二维栅格与 Nav2。仅放宽 z 参数会把三维空间错误地送入平面定位、碰撞与到达检查。

因此保持二维流程，增加独立空间模块：

1. **注册测量接入**：外部 RGB-D/LiDAR/VIO 等 ROS 2 定位系统提供完整 SE3 位姿、实际传感器光心、注册点云、时间、来源与坐标版本。新模块融合测量证据，不冒充新的 SLAM 优化器。
2. **不可变空间地图**：有界体素明确区分未知、实测自由、占据；射线经过处才能形成自由证据。地图包保存测量、来源、版本及摘要，修订变化需要重新准入。
3. **完整定位合同**：位姿采用 `xyz,wxyz`，保留高度和倾斜；检查来源、地图、世界、标定、观测 ID、六维质量、采集与接收年龄。由已验证定位派生兼容旧任务的 `base_pose`。
4. **按运动域规划**：二维继续使用现有 Nav2；空中采用三维体素 A* 与保守机身扫掠；地面空间规划要求连续支撑、坡度、步高和净空。地面机器人不能以三维无碰撞为由跨越无支撑区域。
5. **执行协议**：路径绑定地图、部署和定位证据，ROS 2 控制器需声明匹配的部署版本，接收路径并在结果中返回对应路径 ID。每段自然语言路线仍须独立到达验证。

map、odom 和机器人坐标职责参考 [ROS REP-105](https://github.com/ros-infrastructure/rep/blob/master/rep-0105.rst)：漂移连续的里程计与可发生修正的地图定位不能混为一谈。本项目要求显式世界版本，坐标重定位后停止沿用旧路径。三维占据与地形支撑是两类不同证据，参考 [OctoMap](https://github.com/OctoMap/octomap) 与 [elevation_mapping](https://github.com/ANYbotics/elevation_mapping) 的职责划分；本次实现不声明使用了这两个库。

## 任务安排与验收

| 工作 | 验收证据 |
| --- | --- |
| 独立注册点云融合、地图包保存与复查 | 光心与底盘不同、姿态/高度保留、越界/乱序/重复拒绝、未知保留、摘要篡改拒绝 |
| 体素/地形规划 | 空中绕障或升降；地面支撑断裂拒绝；坡度/步高限值；未知、边界、对角穿角与预算测试 |
| ROS 2 定位与规划接线 | 版本/质量/时效错误拒绝；无兼容控制器不得运行；路径结果绑定；旧 2D 兼容 |
| 自然语言长路线 | 真实 Local Agent → gRPC Runtime → ROS 2 DDS → 记录式控制器；逐段路径和到达证据可回溯 |
| 回归与交付 | 修复本轮发现的问题，保存原始失败与最终结果，文档分类，commit/push 当前工作分支 |

实验分开报告几何算法、实际 DDS 传输、记录式控制器、动力学仿真与实机层级。未运行的层级不计入通过率。仓库中营销资料的既有未提交改动不属于本次修改。

## 已识别的兼容问题

- 基线远程 CI 的镜像测试仍只统计两个预检角色，没有覆盖新 `exchange` 角色。改为逐角色核对预检与执行命令。
- MuJoCo RGB-D 与 ground-truth 共用任务目录，显式切换后触发持久 Runtime 身份冲突。按场景、感知模式和 seed 隔离目录，保留旧证据，不覆盖或放宽生产准入指纹。
- Profiled ROS 2 观测原先拒绝 `base_pose_frame`，而路线“回到出发点”要求 `world`。新增严格字段验证与完整定位派生，覆盖实际返回路线。
- 审查和真实 DDS 调试进一步修正：三维射线零长度接触、地面跨谷捷径、地图/策略可变、轻微非单位四元数造成到达角度阈值偏差，以及 ROS 节点回调与内部字段重名。反例与首次失败保留于实验报告。

最终实现说明与实验结果见 [空间导航接入](spatial-navigation.md) 和 [本轮实验记录](../experiments/2026-10-14-spatial-navigation.md)。
