# Gazebo SLAM → 语义地点 → 自然语言导航升级规范

日期：2026-09-27。基线：`7b34d52abbbd73c333ddd5566f85a6f3b17d59c6`。继承[同源家庭规范](2026-09-26-gazebo-xlerobot-home-spec.md)，保留 XLeRobot CAD、四房间家庭与原任务闭环。不得用场景网格或对象真值替代 SLAM/视觉输入。

## 目标与职责

1. Gazebo 相机/深度、CameraInfo、同帧里程计进入已注册的 RGB-D SLAM；保存点云、占据栅格、轨迹与原始采集 provenance。未知格保持未知。
2. 保存地图的语义层成为 Runtime 命名目标的权威。几何分区由栅格产生，房间功能名称由显式标注或经过验收的感知 provider 提供；不能把形状直接猜成厨房。
3. 区分房间、操作工作区和未命名几何区域。工作区停靠位姿与本机操作可达条件关联；仅通过底盘净空不能证明 IK、抓放或任意物品可操作。
4. 普通单目标自然语言不必显式指定起点。Agent 只产生地点名称，Runtime 从当前地图解析坐标；未知地点/歧义/不可通行拒绝。
5. 移动通过已激活实测地图的路径准入、Nav2、速度新鲜度门和实际机器人控制器，动作后观测验证到位。

## 持久数据与坐标

- `map.semantics.v1` 与点云/栅格同包，并参与地图哈希；绑定 mapId、标定与 map frame。不能在原目录直接覆盖语义或将旧坐标重新标成新地图。
- 每个地点保存 name/aliases、kind、target 与 navigationPose、annotationSource、geometrySource、footprintRadiusM、navigationReady/blockers，可附栅格分区 ID/面积。
- 通行校验复用执行准入的 `pose_is_clear`，未知、障碍、边界均阻断。普通房间种子可在 0.25 m 内选安全栅格位置，不能跨房间做最近点猜测；工作区位姿不自动平移，保留可达验收身份。
- 几何分区只能发布编号区域；分区面积是算法估计，不构成空间完全覆盖或功能识别证据。非零栅格原点旋转或超过 250,000 格暂不生成自动分区，但命名目标按实际栅格坐标校验。
- 以地图保存的 mapFromWorld 的逆变换把 navigationPose 转成 world，发布 `semantic.navigation.v1`，携带精确在用地图修订。激活校验完整性、设备、标定、世界坐标版本及别名冲突。
- 家庭 `routeEdges` 保留可用目标间的显式配置连接，并标记 `topologySource: commissioned_connections`；它不是 SLAM 自动生成拓扑，实际路径仍按实测栅格与 Nav2 准入。
- 历史地图可读取其显式标注，并重新检查当前足迹通行；缺语义地图不回退为全知 commissioning 地图。新构建产物包含分区与工作区。

## 服务与语言

- `semantic.locations`：只读列出在用地图地点与阻塞原因。
- `semantic.resolve {name}`：只读解析唯一名称并返回实际 world goal 和地图身份。
- Grounding 保留当前地图中指向已认证路线目标的别名；LLM 的 `goalPose` 名称在下发前转换为该路线坐标，不扩大路线，也不把名称传到物理工具。模型提供的数值目标也必须匹配该 Grounding 路线的一个已认证完整位姿（包含航向），不匹配则在物理执行前拒绝；等价正负四元数恢复为原认证位姿。确定性和 LLM 的单目标预摆位均使用第一个目标航向。
- 单目标请求示例：`去厨房`、`返回客厅`、`前往厨房工作区`、`移动到“实验台工作区”`、`go to loading bay`。
- 地点必须存在于设备当前语义目录。保留多房间巡检与家庭拿放解析，不能为了识别导航而丢掉“打开烤箱”等未实现动作或否定/条件要求。
- 新场地名称由 provider/标注配置提供；Agent/Go 导航客户端不按模拟器名称或家居 CAD 分支。

## 物体语义与证据

SLAM 会话读取普通感知路径的真实实体，保留采集时间、来源、观测时底盘位置与地图内最后发现位置。实体 provider 与 SLAM 捕获可能不是同一帧，必须使用实体自身时间/位姿，不能借用另一帧的时间或里程计。超时、缺少配对位姿或检测失败记录缺口，不能伪造物体。

物体记忆仅用于寻找线索；到达后重新观察。动作后固定回执、原始图像摘要、map_route、实际位姿误差仍为闭环依据。共享资源、实机认证与通用模型缺口保持原约束。

## 验收门禁

单元/边界验证：未知格/障碍/边界、工作区不漂移、别名冲突、坐标逆变换、地图修订、感知时间与位姿配对、单目标语法与不丢操作。实际 Gazebo 验证：完整注册扫描并发布/激活新地图，读取语义目录，按自然语言到工作区和返回，再巡检其他房间；每步核对命令固定证据和实际 Nav2 到位。不传送、不在任务中复位、不重发未知动作。

最终记录需写明 Git/镜像/资源身份、两个 SLAM 资源的区别（网关地图包与 RTAB-Map 数据库）、帧/轨迹/配准、地图修订、分区/标注来源、任务 ID、工具回执、位姿误差、失败与边界。本轮报告另行追加，不覆盖原家庭验收。
