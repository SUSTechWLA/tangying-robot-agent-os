# 单自然语言长程任务与多 Agent 协议验收计划

日期：2026-10-10。基线 `e78e00abfef4384371ed7c588c182d61a4ac987b`；PR #21 基线 12 项 CI 全部通过。现有用户营销文档改动保留。

## 任务与运行条件

在活动的 Gazebo `home_furnished` 世界中，经生产 Console API 创建、批准并执行一条完整任务：读取标定、移动 SLAM 并启用新地图、多房间巡检、厨房抓取同一杯子并放入盘中、返回客厅、最终读取地图和定位。使用已配置的真实 GOAL 模型与 task/ops/recovery；禁止验收器直接推进物理动作或伪造完成。

输入原句：

> 依次执行以下完整家庭任务：读取整机标定状态；重新按家庭巡检路线完成SLAM建图并启用新地图；读取导航定位状态；从客厅出发，巡检卧室和卫生间，最后回到客厅；再从客厅出发，去厨房拿杯子，放进收纳盘，然后回到客厅；最后读取并报告当前地图和导航定位状态。每个地点都确认抵达，抓取和放置分别验证。

活动 Runtime 为 `127.0.0.1:50161`，robot `gazebo-home_furnished`。运行前保存就绪、地图、定位、模型路由和源码/二进制摘要。首轮使用独立 Agent 数据目录，每轮使用新验收目录；修复部署复用原数据库，不覆盖历史任务或旧失败证据。世界已有地图及标定，固定巡检测绘起点须在客厅；准备动作如有需要使用独立批准任务并明确记录。

## 工作分工与顺序

| 工作 | 负责范围 | 验收 |
| --- | --- | --- |
| 环境与真实长程任务 | 主 Agent | 原冻结计划、同一 task ID、实际物理证据、最终成功 |
| 多 Agent 交互协议 | 协议审查 Agent | 版本化消息、发送方/主题权限、任务/机器人/版本/命令及因果绑定；旧消息拒绝 |
| 云边协议与恢复 | 云边审查 Agent | 精确完成回执、重复/失序/丢响应、checkpoint 对账；无未知物理重放 |
| 验收与独立重验 | 验收 Agent | API 原始响应、逐文件哈希、能力/观测/RGB-D/导航/抓放、恢复链及上下文快照 |
| 精确上下文持久化 | 主 Agent | 归档及模型输入原文穿过事件库与 HTTP 后哈希可核验 |
| 测试、文档、交付 | 主 Agent 汇总 | 相关竞态/全量回归、可追溯变更与失败、commit/push、远端 head 校验 |

先完成必要协议修复和针对性测试，再构建并固定实际运行代码。通过只读故障代理，在转发前对某个任务执行期 `navigation.status` 注入一次 `UNAVAILABLE`。同时在建图完成后的安全边界暂停超过 60 秒，再继续同一任务；操作员暂停/继续单独计数，不冒充自动恢复。

## 通过标准

1. 实际 GOAL 模型生成冻结计划；原任务终态 `SUCCEEDED`，目标房间序列与同物抓放均有证据。
2. 每个能力具有匹配回执和复验；物理子步骤具有派发后观测；到达误差及抓放稳定证据满足既有严格阈值。
3. 故障请求身份精确匹配：Task 请求恢复 → Ops 定位 → Recovery 计划/只读调查及独立复验 → Task 对原命令有预算重读 → 继续冻结计划。
4. 新消息保持 task/revision/robot/step/command 与因果关系；旧版本、错发送方、错作用域或冲突消息不能授予执行权限。
5. 上下文保留完整来源与未决状态，实际发生的压缩/回读分别计数；无模型调用或无回读不能据空数据宣称已覆盖。
6. 原始文件、任务版本、数据库快照、运行配置、源码及二进制 SHA256 可核验；失败不改写，修复后另存复验或新运行。
7. 云边完成响应丢失只重传完成，不重放动作；ACCEPTED 缺少充分终态证据继续要求对账。

本次是指定场景的实测与协议回归，不作为任意故障、任意任务或真实硬件成功率证明。未知物理结果仍停住，不以完成率为由绕过门禁。
