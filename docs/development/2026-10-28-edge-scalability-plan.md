## 问题与优先级

1. **P1，协作视图随历史增长失效。** `CoverageView` 对保留的完整 inbox feed 做有界 Snapshot，最多 1,000 项；历史条数越界后返回空提案。需要分开审计历史与当前状态，在完整身份和流作用域内先选最新，再检查新鲜度与任务/地图依据，不能回退到过时的旧消息。
2. **P1，长任务回放成本。** 先前 32 步 fixture 在 race 下耗时约 30 秒，96 步 case 存在历史超时记录。先做 profiling，确认根因后优化读取/投影；不得以缓存旧批准、丢弃未决动作或削弱回放校验换取速度。
3. **P2，系统入口与就绪程度表达。** README 需要优先解释边缘 Agent、Worker、Runtime、Peer Exchange 和云端的职责，以及上下文/证据的权威来源；把当前能力、历史实验和仍待实机验证的事项分开。
4. **用户追加：模型成本管理。** 已有逐次 usage/请求留痕，继续提供可配置的调用预算及真实用量汇总；缺失用量与零值分开，不用固定字节比伪造 tokenizer 或实际费用。
5. **用户追加：重复与相似任务经验。** 保存有界、持久、带来源的规划候选；精确目标也须重新读取当前条件并经过现行校验才能复用，相似目标仅提供参考。第一版存储对象是验证通过的规划草案，不冒充成功执行技能；旧观测、批准、命令 ID 和完成证明不成为新任务事实。

## 不变量与兼容

- Peer 建议不授予运动权，不直接更新本机地图真相，不等同物理完成。
- 完整 sender/recipient 身份隔离；同一流的无效或过期最新消息不得使旧有效值复活。
- Feed 游标与历史回溯保留；当前状态读数必须在一个一致的数据库快照中获得，真实活跃流超过上限仍拒绝不完整建议。
- 执行权、批准/版本、持久预算、unknown 对账、命令幂等语义保持；任何优化都要测试重启与失败路径。
- 已发行教材 3.2.0 与历史实验身份固定；新增解释放在当前指南和教材更新页，不能改写已出版证据。
