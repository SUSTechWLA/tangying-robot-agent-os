# 2026-10-15 分层目标委托与统一边缘核心升级记录

## 基线与目标

基线：`b1223a0838eb3151afc2f2a4e31293849743e0fa`。此前 Local Agent 装配目标规划器，Fleet Worker 执行云端已规划能力节点；两者没有统一的目标委托执行入口。本次按方案 2 升级：云端批准目标与授权包络，边缘根据本机能力及只读观测生成子计划、执行、验证并受控重规划。

## 实施计划

1. 新增版本化目标合同：机器人与能力目录绑定、工具参数包络、效果/资源范围、预算、期限、机器可检查的完成条件。
2. 新增共享边缘宿主：兼容旧能力计划；目标模式共用现有能力规划/执行器；持久保存子计划、因果关系、完成步骤和诊断。未知动作结果不得自动重规划或重放。
3. 将 Fleet 目标作为单个已批准父节点交给 Worker；父节点续租覆盖完整子任务。增加目标创建 API，验证独立的目标完成证据。
4. 将 Local 和 Worker 装配到同一宿主；保留原本地观察/恢复运行时与旧任务入口。
5. 更新架构、接入指南、README 与 book 源码，测试目标完成、越权拒绝、安全重规划、结果未知、重启及回执重复等路径。

## 本轮明确边界

目标模式以一个机器人、`robot` 资源为执行范围；跨机器人共享物品/区域的占用仍交给云端已有协调器，不能通过目标字符串自行取得。云端租约丢失必须停止；本轮不引入离线继续授权。模型只生成子计划，不生成授权或完成判定。现场模型推理可以部署在边缘，也可以使用已有云端推理端点，任务控制权仍在边缘。

重规划仅允许有证据证明未产生效果的失败或完成条件尚未成立；已确认写调用不得超出原批准次数（默认每个相同写调用一次）。执行中断且结果未知时保留历史并进入对账。大学教材/行业手册中的功能描述必须区分合同测试、仿真和真机验证。

## 变化与测试结果

已实现的变化：

| 模块 | 变化 |
| --- | --- |
| `core/objective` | 版本化合同、Schema/效果/资源准入、次数额度、精确值完成条件、目标/计划/效果摘要 |
| `tasks` | 目标作为单个未批准父节点持久化；目标创建幂等键绑定 actor，重试不重置状态 |
| `internal/edgeagent` | Local/Worker 共享宿主；逐代计划、步骤检查点、完成证据；有限事实投影、完整历史校验；Ops 诊断与可替换 Recovery 建议端口 |
| `capabilityagent` | 规划工具/参数按 grant 收窄，原目录身份保持；输入验证与旧计划行为兼容 |
| `fleet/console` | 新目标 API、目录摘要、原鉴权和批准；云端核验目标及已申报子计划证据 |
| `edge-worker/local-agent` | GOAL/INTENT 规划装配、原 Runtime 及执行库复用；结果上报丢失补传；安全检查点重入，待定步骤对账 |

测试原始输出、案例矩阵、首次失败与源码哈希见[实验报告](../experiments/2026-10-15-hierarchical-edge-objectives.md)。11 站合同任务已经通过明确拒绝后的剩余规划与宿主重建；云边 HTTP 验证父目标、设备租约、子证据及结果丢失窗口；负例保留未知动作、验证丢失、越权和预算等拒绝。

最终验证：18 个功能顶层测试 / 31 项含子测试全通过；6 包 race 检查通过；项目 `make test-go` 通过；Python 文档与出版 48 项、Go 文档守卫、lint、book-check、目录同步、三个入口编译通过。替换 RecoveryPolicy 的错误也不能掩盖未知结果，有单独回归。`go test ./...` 的历史源码归档失败单独在实验记录中保留，不据此删除研究制品。

修复了写后验证错误未升级未知结果，以及完整目标证据上报错误可能把已完成工作误判失败的边界。取消测试首次在回执持久化前注入，原 CANCELLED 预期不成立；改为等待持久进度测试 owned stop，未知结果另测，失败记录不删除。HTTP 模型 mock 首次误用点号工具别名且记录 channel 阻塞；修正为实际 `propose_capability_plan` 名称及非阻塞采集，属于测试设置修正。

## 迁移、交付与回退

现有数据库不需要新增 SQL 表：Task/Revision、SQLite 原子聚合与事件存储复用。升级先停止同机器人旧控制进程、备份执行库、更新云边两端后使用新增目标 API；运行合同 pin 的变化仍按原现场准入流程处理。未配置 GOAL 模型时只有明确离线语法，不能承诺复杂目标自动编排。

旧 `/v1/tasks` 保持兼容，前端表单不自动切换目标模式。已有 Fleet system/MCP 的旧任务草案工具保持原语义，云端同事通过新目标 API 对接；本轮不改同事的云端大脑实现。书籍 2.1.0 正文保持出版身份，新补充章说明当前协议。

回退前取消或对账所有活动 `edge.goal`，保留子计划与回执；旧 Worker 不理解 `edge.goal`，不得接收此类目标，不得删除 journal 后重发已执行任务。既有任务可以继续走旧通道。正式发布标签和具体设备放行与本轮功能分支交付分别管理。
