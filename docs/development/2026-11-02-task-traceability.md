# 2026-11-02：从原始指令到原子调用的持久回溯

基线：`ab5c9822c`。本轮是代码与诊断能力升级；不重启现有机器人进程、不改变历史实验结论。当前机制见[回溯架构](../architecture/task-traceability.md)，逐任务数据见[实验报告](../experiments/2026-11-02-task-traceability/README.md)。

## 问题与实施顺序

先检查创建、计划版本、执行事件和观测的真实来源，再修持久化，最后增加统一查询、前端展示与故障实验。审查发现的问题不是“日志不够多”这一类泛泛判断：

| 发现 | 修复与验收 |
| --- | --- |
| 状态前后值只发 observer，未保存到数据库 | `STATE_CHANGED` 与任务状态同次提交；SQLite 重开后与观察者内容相同 |
| 内存返回对象与已保存的事件 payload 共享可变引用 | 深复制嵌套容器，隔离 observer；测试修改返回值不会改写账本 |
| 当前 `Task.Request` 会被修订覆盖，UI 却标“原始指令” | 读取不可变 revision 1，分别显示原句与当前目标 |
| 父能力状态不足以定位哪一次轮询、复验或停止失败 | 每次服务 RPC 有独立 ID 和开始/结束记录；重试不覆盖前次结果 |
| 停止时丢失原执行上下文，部分存储错误被吞 | 保留绑定及错误链，审计失败不能冒充成功或普通网络重试 |
| 版本 2 以上的 legacy 观测前缀与工具步骤名不同 | 只按生产者的精确 `revision-N/step` 契约匹配，仍检查任务/机器人/版本 |
| 空证明、孤儿 RPC、跨机器人完成可能误判一致 | 校验调用链、父命令、版本、结果状态与冻结计划机器人 |
| 仅查父任务看不到完整 edge.goal 子执行账本 | 核对子计划声明并读取权威 aggregate，父镜像不当作原始证据 |

## 实现边界

- `tasks/trace*.go`：确定性投影、身份/状态/引用检查、双读快照及子聚合加载。报告保留原事件与版本；未知不补成成功。finding 携带所属 `taskId`，父子序号不会混用。
- `console/trace.go`：只读 `GET /v1/tasks/{id}/trace`。持续写入使三次读取均不稳定时返回 503，不拼接混合快照。接口沿用现有工作空间代理和访问边界。
- `internal/capabilityagent/rpc_trace.go`：每次 dispatch/status/verification/stop RPC 的开始、结果、参数摘要及时间。物理命令与 RPC 的成功分别记录。
- `web/`：原句、修订目标、持久快照水位、命令、RPC、子计划、发现与 JSON 导出；异步响应绑定任务，失败清除旧报告。父水位未变的子聚合也定期重读。

普通服务调用在开始日志写入失败时不派发；已派发后的结束日志失败不返回成功。已有授权的停止操作有明确例外：审计盘故障不能阻止停止机器人，但失败必须返回、不能声称停止证据完整。它没有新增自动恢复权限。

记录写入优先使用既有 `RecordEvent` append-only 端口，兼容旧 `AppendEvent`。子 aggregate 仍有完整快照写入成本；本轮未更换其存储模型。新增记录增加存储与上下文原始来源数量，不能据此声称长期存储开销恒定。

## 信息正确性的范围

`consistent` 表示已有检查未发现冲突或缺口，不等于物理验收。三种重要“不完整”保留在产品中：旧日志缺字段；保留期已过或未展开的传感器原文；子计划没有独立 TaskRevision 表。子目标来自生成计划，不冒充用户原句。超过证据索引或子计划展开上限均有游标/截断说明。

`source.stable` 检查本机任务、版本与已声明子聚合的两次读取；证据元数据分页是 best-effort，不能当全局分布式快照。`snapshotSha256` 是服务器读集指纹，不是响应 JSON 文件校验和，也不是防篡改签名。原始输入、计划和完整事件可能包含业务数据，实验导出按既有数据保留制度管理。

## 验证与留存

最终软件实验包含 4 种自然语言场景各 3 次及 1 次三站点 Host 子计划实验。正常/只读恢复成功，坏复验/丢动作回执保持未完成；12 次 SQLite 重开逐字节一致。另有记录缺失、跨版本、错身份、并发变化、写失败、停止例外及 UI 异步隔离测试。完整命令、原始数据和限制见[实验报告](../experiments/2026-11-02-task-traceability/README.md)。

本轮记录过的验证问题：初次 API 文档检查因路由未登记失败，已补；README 的静态测试数过期导致 Go 文档检查失败，重新按仓库规则计数后修复；一次长包 race 测试为诊断主动中断，不计作通过，后续完整运行通过。没有将这些中间失败删除或解释成实体任务失败。

冻结出版的 Book 3.3.0 继续对应原出版快照；本轮当前机制以新架构页与本记录为准，不改写已发布教材的历史源码身份。
