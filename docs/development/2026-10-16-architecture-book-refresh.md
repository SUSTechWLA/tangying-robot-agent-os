## 变更目标与范围

文档已有分层目标专题，但书籍 2.1.0 和若干总览仍将 Worker 描述为只执行云端计划，读者容易将模型推理位置、生命周期所有权和进程角色混为一谈。2.2.0 将主线改为：Cloud/操作者创建粗目标授权包络 → 批准 `edge.goal` → Local 或 Worker 中共享 Host → Task 规划、Ops 诊断、Recovery 提案 → Executor → Runtime/控制器与独立验证。

旧 `/v1/tasks`、现有 UI 和 MCP 草案工具的冻结能力计划路径继续单列。Local 的原事件运行时没有整体迁入 Worker；共享 Host 内的逻辑角色也不意味着多个独立 LLM。资源 v1 只绑定单台 robot，设备 advisory 数据不会取得任务授权。模型位置、云边任务控制、peer 数据、设备 ROS 2 接口和物理完成语义分别说明。

| 文档类别 | 处理方式 | 主要入口 |
| --- | --- | --- |
| 项目/部署与学习入口 | 更新当前架构、目录和两条任务路线 | 根 README、deploy/README、docs 四条阅读路线 |

| 教材正文与教学附件 | 集成新架构到对应章，更新案例、实验、课程与工程模板 | book/front、chapters、appendix |

## 证据与能力边界

正文区分四类计量：父计划数、子能力调用数、Host 业务读取数、内部控制/观测次数。Host 最近 8 次/8000 字节的进度投影不删除完整账本，不与旧 actionloop managed view 32768 字节混为同一预算。完成谓词需结合独立任务覆盖检查，单独地图身份相同不证明机器人已经巡检。

恢复矩阵保留未知写的停止规则；仅完整 StepCompleted 和绑定 CAPABILITY_VERIFIED、冻结目录语义及当前授权一致时补父记账。完成读取的持久重试跨重启计量，落盘确认中断不能无限重读。已验证且上报待闭合只补传原 proof；失去原 claim 不继续运动。

本轮引用 2026-10-15 已登记的 final-campaign-04、真实 Gazebo 五项尝试和四个二进制身份。软件五个连续目标确认 368 次写，不能外推到实体；Gazebo 一个 episode 内不同任务/版本不合成成功率。点云语义、二维/单层地形/三维路径、三类 ROS 2 接口与实际飞行/步态/异构机群认证分别叙述。
