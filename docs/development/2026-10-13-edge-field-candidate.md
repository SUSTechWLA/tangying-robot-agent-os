# 边缘 Agent 实机测试候选版实施记录

日期：2026-10-13。起点：`a05e6cf6f0247c6a4a985178e36c4114fc15177d`。范围是设备侧软件，云端业务由独立团队维护。本次目标是让边缘 Agent 的配置、执行记录和数据通信能够在现场测试中接受核验；软件测试通过不等于任何具体机器人已获得物理放行。

## 计划与验收边界

1. 保留 Local Agent 单机自治和 Fleet Worker 两种部署方式，同一 Runtime 只有一个派发者。核对持久任务、未知动作、故障恢复和退出顺序。
2. 将 Runtime 型号、完整 Profile、工具目录和安全配置绑定到持久准入记录。跨进程重启仍拒绝不一致；瞬时 READY/离线变化不生成新身份。
3. 为地面、空中和足式机器人加入明确的运动与控制器安全策略契约。驱动实现、飞控和机载低层控制器仍各自负责执行与停止；声明能力不等于实现硬件驱动。
4. 增加独立的边缘数据交换进程，负责可靠收发、重复检测、身份/域/时效检查和重启恢复。对等节点和云端使用同一数据协议；消息不得直接变成动作命令。
5. 对更改运行单元、契约、持久化与进程测试；记录失败、修复、证据路径与尚未验证范围。保持现有长任务上下文预算和动作审批语义。
6. 更新部署、云端对接与开发资料，完成回归后提交并推送当前工作分支。

## 基线判断

已有单机任务账本、不可变任务版本、步骤完成记录、未知动作对账、只读恢复和分层上下文。现存缺口包括：Python Runtime 的目录指纹只覆盖工具，不覆盖完整机器人 Profile；Go 客户端对 Profile 的固定只存在于内存；Worker 通知领取与持久保存之间存在失联或重启丢通知的窗口；同进程 Agent Bus 不提供跨主机持久数据通信。

因此先补确定性边界，避免依赖更多模型角色掩盖持久状态问题。无人机自主起降、足式步态、越障能力和任意机器人机群调度不由本次软件协议自动产生。

## 实施与验证

### 执行与重启

`edge/robotclient` 新增原子写入、同步刷盘的运行契约文件；Local Agent 和 Worker 都在领取/执行任务前准入。完整 Profile、目录、型号、协议和安全配置跨重启保持一致。动作调用再次检查；临时 READY 状态不改变目录。已有执行历史但丢失准入文件时拒绝自动建立新基线，避免重启后把换过的机器人当成原设备。`--admit-runtime-contract` 提供对账后的无动作迁移入口，只创建缺失指纹，不覆盖旧指纹、不清除任务和 Runtime 锁存。

Worker 的通知 ID 先落 SQLite 再 ACK Redis；重启先取未处理通知。控制面重试不再在 60 次失败后丢弃任务。物理调用传输异常、能力服务结果未知、Runtime 返回显式未知结果，都保留 `ACCEPTED` 并要求对账。没有下一节点不等于前一动作已确定完成。取消使用独立有界 context；退出等待 telemetry、claim renewal 和 Link 收发结束，再关闭数据库。

已派发服务操作需要在 Info 不可用时仍可请求停止：执行器从原始 receipt 冻结 robot/operation/owner/status/cancel 身份，提供进程内有时限的停止上下文。仅允许同一已准入客户端、精确服务、空参数、零续租；新任务和普通服务调用继续校验目录。远端服务的原子 owner 校验仍取决于已有服务合同，不能用此本地上下文宣称升级了所有旧服务的并发控制。详见[Worker 可靠性](edge-worker-reliability.md)。

### ROS 2 与异构机器人

统一 `robot.mobility.v1` 描述运动模型、SE2/SE3、单位、坐标、速度上限、准备方式和控制器所有的停止流程。Go/Python 都严格验证；完整 Profile 参与 Runtime 目录散列。UGV、UAV、legged 三份模板对应不同的控制器职责。

新增 ROS 2 Profile Gateway，实际实现 Action、驱动状态、观测、命令租约和停止 Service 的接线。动作携带审批、deadline、lease、Profile、目录、坐标依据和 fencing；设备侧必须独立实施去重、限幅、失联保护和停止策略。Gateway 验证身份、递增序号、采样时间、接收时间、就绪状态及命令后新观测，默认不允许运动。通过真实 DDS/gRPC 夹具验证这条链路，并不等于提供了厂商飞控/步态控制器。

原路线模板总是加入地面 `navigation.pre_position`。现在由已验证 Profile 的 `navigationPreparation` 决定：`controller` 只加入观测，旧设备保持原行为。确定性计划和模型计划都遵守此约束；模型不得自行给无人机插入地面准备动作。每段导航仍有独立到达验证，三维目标高度保持不变。40 段路线编译回归验证依赖关系和验证步骤，属于计划合同测试，不是 40 段实机试验。详见[异构接入与 ROS 2 协议](heterogeneous-mobility.md)。

实际自然语言 ROS 2 测试进一步发现旧 `manipulation_ready` 总门禁使没有抓放能力的移动机器人无法执行。共享就绪现在可由已验证 Profile 声明的可用运动能力提供；急停、只读工具、缺失声明和任一 blocker 不能提供就绪。Local Runner 和 Worker 仍逐工具校验，Worker 在每次派发前用新鲜 Info 再检查确切工具，不能因导航可用而派发不可用的抓取。

### Agent 间通信与扩展

新增独立 `edge-exchange` 与 `agent.data.v1`：身份/域绑定、时效、空间依据、持久 outbox/inbox、单调序号、精确 ACK、去重、断线重传、有限保留和容量背压。生产传输为 TLS 1.3 + 每对等端独立凭据；管理 API 只监听回环。双方重启的两进程实验验证连续性；跨语言固定样例验证摘要和大序号。

数据通道不控制 Runtime、不持有动作租约、不自动把收到的消息变为任务真相。云端或别的设备可实现相同协议；业务消费必须先核对时效、坐标和任务版本。执行授权仍走 Local Agent 或 Fleet，只有一个执行权威。新增依赖守卫防止交换模块引入 Runtime 控制。详见[数据协议](edge-data-exchange.md)。

### 部署和资料

镜像和构建目标增加 `edge-exchange`；Orin 的原生 systemd 与 Compose 模板明确身份、凭据、状态卷和退出超时。保留 Fleet 原容器数据库路径，避免路径变更造成空日志。新 duration/pose/任务源严格校验，旧的错误配置需要修正；Profile 目录变化需要重新审批。完整迁移顺序和分级试验见[现场部署手册](../operations/edge-field-testing.md)。

## 问题、修复与证据

| 发现 | 处理 | 证据层级 |
| --- | --- | --- |
| 原通知有限重试、接收即 ACK，进程退出有丢通知窗口 | 持久通知、落盘后 ACK、先恢复再领取 | Go 故障注入、真实 Redis 7 |
| 云端暂时无节点时可能释放未知动作通知 | 先检查 `ACCEPTED`，未知结果禁止普通失败/重放 | 首次失败与修复后日志保留 |
| Runtime 正常返回 RPC，但结果仍为未知物理状态 | 显式终态码及停止失败后缀按未知处理 | Worker race 回归 |
| 准入只在内存，或丢文件后重启自动记录新硬件 | 持久 pin、历史检查、无动作显式准入 | 跨重启/并发/损坏文件测试 |
| 目录校验可能阻止已拥有操作的停止请求 | 仅 receipt 绑定的有界停止上下文例外 | Robot client 与执行器回归 |
| 路线模板强制地面准备动作 | Profile 声明准备策略；模型计划同步约束 | 40 段编译与跨语言接入测试 |
| 纯导航机器人被旧抓放就绪门禁挡住 | 共享就绪依据实际运动能力；Worker 同步新增新鲜逐工具检查 | 首次 NL 零动作失败、修复后十站完成及混合能力拒绝回归 |
| 同毫秒旧观测可能满足命令后证据条件 | 同 source 的新序号和接收单调时钟双重检查 | 独立审查后新增回归；DDS run2 |
| ROS topic 单帧队列覆盖动作引用的证据，十站任务第六站后停止 | 可靠有界 64 队列、每订阅串行回调，保留确切命令观测和 500 ms 时效 | 保留失败；最终 DDS 六组及同版三次十站任务通过 |
| 并行开发时跨语言 probe 编译失败 | 待共享字段/调用接线完成后重跑，保留失败日志 | 构建装配失败，不计为导航失败 |

原始日志分布在 `artifacts/experiments/edge-field-candidate-20261013/`、`artifacts/experiments/edge-field-20261013/ros2/` 与 `artifacts/edge-hardware-candidate/20261013/worker/`。论文引用应以[实验报告](../experiments/2026-10-13-edge-field-candidate.md)的证据分类、任务分母和未测项为准。原始日志是本地制品，不默认随 Git 发布。

## 留给后续集成的边界

这次交付是可部署调试的边缘软件候选版。具体设备还需实现并验证 ROS 2 控制器、独立 watchdog、停止策略、感知标定、地形/碰撞约束和真实任务；普通 Cancel 会锁存本轮 ROS 桥，当前需要本地核对、重新调试并重启，未实现远程自动解锁。未经核对的未知结果应停下来，不能以“自动恢复”为由重新尝试物理动作。

单个 Agent 已有持久任务、分段执行和分层上下文；新增数据协议提供跨域交换依据，不自动解决跨地图配准或多机器人联合规划。HTTP Fleet 通知在响应到落盘前的崩溃窗口仍需云端补 ACK 协议。此次没有实体机器人、实际飞行/步态、小时级长期稳定性或公网时延试验，也没有对任何型号作投产保证。
