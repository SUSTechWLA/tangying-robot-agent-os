# 躺营 v0.4.0

> 2026-09-11。标签、最终提交、逐项 CI 结果和制品校验值见本版 [GitHub Release](https://github.com/SUSTechWLA/tangying-robot-agent-os/releases/tag/v0.4.0) 的 `release-manifest.json`。

本版有两个交付面：

1. **标准机器人工具层** —— 把机器人能力变成 LLM 可以直接 function calling 的工具，覆盖底盘、机械臂、夹爪、感知、复合技能与安全六类，并且**不新增执行通道**：每个工具最终都编译成既有的 `ExecuteSkill` 命令，安全监督、租约、幂等、journal 与闭环完成判定全部照旧生效。
2. **任务全过程回放** —— 工作台里一条自然语言任务如何被拆解、调用了哪些工具、每一步由哪次采集证明、哪里对不上，一屏看完。

软件版本与实机放行仍是两项独立结论。`v0.4.0` 不代表已完成真实 XLeRobot 的现场验收，也不替代现场 `PHYSICAL_GO`。

## 获取准确版本

```bash
git clone --branch v0.4.0 https://github.com/SUSTechWLA/tangying-robot-agent-os.git
cd tangying-robot-agent-os
make setup
make build
./bin/robot-agent version
```

`VERSION`、Python 项目、内置 Runtime、MuJoCo 运行时、ROS 包与适配器运行时均为 `0.4.0`，由 `tests/test_repository.py::test_release_version_matches_distributed_components` 逐处校验。线协议版本 `1.0`、MCP 工具集与 `robot.profile.v1` 不随软件版本改动。

## 本版范围

### 机器人工具层

27 个工具，25 个默认提供给 LLM；名字是蛇形、不带点，便于 function calling。命名空间只用于路由与归类。

| 命名空间 | 工具 |
| --- | --- |
| `robot.nav` | `navigate_to`、`navigate_to_pose`※、`explore_for`、`stop_navigation`、`get_current_pose` |
| `robot.arm` | `move_arm_to_pose`、`move_arm_to_joints`※、`move_arm_relative`、`home_arm`、`get_arm_state` |
| `robot.gripper` | `grasp`、`release`、`set_gripper_width`、`get_gripper_state` |
| `robot.perception` | `detect_object`、`get_object_pose`、`resolve_location`、`scan_environment`、`capture_image`、`get_robot_status` |
| `robot.skill` | `pick_object`、`place_object`、`fetch_object` |
| `robot.safety` | `emergency_stop`、`reset_safety_stop`、`set_speed_limit`、`check_collision` |

※ 标记为 `fallback`：仍然注册、可被上层编排调用，但默认不提供给 LLM，因为它需要坐标或关节角这类底层参数。

关键设计（完整理由见 [ADR](../superpowers/specs/2026-09-11-standard-robot-tool-layer-adr.md)）：

- **传输层不变。** 工具不是新总线，而是编译成既有 `ExecuteSkill` 调用，复用 lease、deadline、幂等、审批与安全 profile。工具层不实现安全，也不绕过安全。
- **能力集与动作集分离。** LLM 只看到语义参数（`location_name`、`x,y,z`、`force`、`width`）；关节名与执行器键由适配器构造，因为那些名字随型号变化，且 `safety.py` 只接受特定前缀与 `.pos` 后缀。
- **语义位置由服务端解析。** `navigate_to("厨房")` 的坐标来自可配置的位置表（`assets/home_locations.json`，缺省与已验收的四房间场景一致，有测试防止漂移），模型不接触坐标。
- **统一结果。** 所有工具返回 `ToolResult(success, error_code, error_message, recoverable, data, timestamp, tool_call_id)`，错误码是十个标准码；`recoverable` 由与 Go `core/closedloop` 相同的分类表决定，并有跨语言一致性测试防止两边分叉。运行时细粒度码保留在 `data.runtime_code`。
- **分布式行为在 `ToolExecutor`。** 按工具名解析节点（不硬编码地址）、心跳与 TTL 健康检查、有界超时（超时报告 `outcome_uncertain`，不谎称已停止）、取消、同节点写互斥。**写工具从不自动重试**：重复一个物理动作可能把它做两遍。
- **`tools.json` 由代码生成**，`make lint` 会校验它与代码一致，因此不会出现"提供给模型的工具"与"运行时能执行的工具"不一致。

### 任务全过程回放

工作台底部新增独立面板，选择任意任务后把这四个来源对齐成一份执行档案：任务与事件（`/v1/tasks/{id}`）、任务说明（`/experience`）、历史观测（`/observations`）、恢复状态（`/recovery`）。

面板自上而下：**任务是什么**（原始指令、系统理解、适配器、版本、总耗时、起止、拆解出的步骤）→ **执行链路**（每个工具步骤的中文名与原始工具名、状态、耗时、派发次数、是否改变世界，展开看调用参数与命令编号）→ **证据**（写步骤下直接给出确认它的同帧彩色与深度缩略图、采集时间、相对命令的时间偏移、来源、采集编号、字节数与 RGB SHA-256，并可打开原图与完整 JSON）→ **一致性检查**。

一致性检查把开发人员本来要手工比对的东西直接列出来，任一命中都会标出：写工具无证据（`MUTATION_WITHOUT_EVIDENCE`）、证据早于命令（`EVIDENCE_BEFORE_COMMAND`）、引用的采集不在历史中（`EVIDENCE_MISSING_FROM_HISTORY`）、采集登记的步骤与引用步骤不符（`EVIDENCE_BOUND_TO_OTHER_STEP`）、成功但写步骤未确认（`SUCCESS_WITH_UNCONFIRMED_MUTATION`）、任务结束却无任何工具活动（`TERMINAL_WITHOUT_TOOL_ACTIVITY`）、存在未知终态需要现场核对（`RECONCILIATION_REQUIRED`），以及说明性提示。

面板只读，不创建、批准或取消任务；任务运行时每 250 ms 节流更新、进入终态立即更新，且只在显示内容变化时重建。使用说明见[工作台文档](../frontend/console-v1.md#任务全过程回放)。

### 修复

- 工作台脚本必须列入 `web/embed.go` 的 `//go:embed`，否则内嵌控制台会漏掉新文件；`task_trace.js` 曾含 ESM `export`，在控制台的严格 CSP 下作为 classic script 解析失败并静默禁用整个模块。两处都由本版修复，并补了相应契约测试。
- 文档站点的内部链接检查原先只覆盖 `docs/production`，现扩展到全部现行文档（历史归档 `docs/superpowers` 除外）。

- 工具层：`.venv/bin/pytest -q tests/tool_layer` 覆盖契约、语义位置、每个工具、执行器故障模式与 `tools.json` 一致性；`make tools-check` 校验 schema 未漂移。

所有结果来自软件仿真与隔离进程，**没有实机、现场制动距离、标定精度或长期可靠性结论**。

### 笛卡尔机械臂控制的明确边界

本版**没有**对接 MoveIt 2，本仓库也不存在 `GripperCommand`：`deploy/robot/navigation/Dockerfile` 只安装 `navigation2` 与 `ros-gz`，CI 的 `ros-build` 不构建 MoveIt 2。当前平台的机械臂基线是关节目标 action chunk（`arm.move` + `action_chunk`），没有 IK 求解器。

因此 `move_arm_to_pose` 与 `move_arm_relative` 在实机适配器上返回 `IK_UNAVAILABLE`（投影为 `UNREACHABLE` / 不可重试）。这是**有意的失败关闭**：猜一组关节角去够一个笛卡尔点，等于让机械臂朝未经验证的方向运动。接入契约、`MoveGroup` 动作字段映射、依赖清单与验收步骤见 [MoveIt 2 适配契约](../development/arm-moveit-adapter.md)，其中每一项未验证的内容都标注为未验证。

`set_speed_limit` 是软件限速（缩放本适配器下发的速度参数并记日志），不是硬件速度寄存器。`force` 是尽力而为：该驱动器不回报实测夹持力，是否夹到物体以 `grasp` 返回的 `object_detected` 为准，且该判定来自新鲜观测而非动作回执。

## 升级与回滚

- 从 v0.3.0 升级无需数据迁移：SQLite 与 World 快照格式未变，版本号变更不需要迁移。`Result` 增加了可选 `payload` 字段（字符串到标量的映射，用于返回结构化失败细节），旧适配器不填即为空，行为不变。
- `tools.json` 与工具层是新增能力，不改动既有 task/runtime 契约；不使用它们时系统行为与 v0.3.0 相同。
- 回滚到 v0.3.0 会失去工具层与回放面板，既有任务的执行语义不变。
