# 躺营 v0.7.0

2026-10-10。正式发布由 `main` 上的附注标签 `v0.7.0` 和 [GitHub Release](https://github.com/SUSTechWLA/tangying-robot-agent-os/releases/tag/v0.7.0) 固定；软件版本统一为 0.7.0。9 月 22 日的候选集成记录保留为历史证据，本次正式发布纳入后续家庭导航与长程恢复改进。

## 当前发布状态

[PR #21](https://github.com/SUSTechWLA/tangying-robot-agent-os/pull/21) 已合入 main，合并提交 `16cdd105699aaebe9d3f9b745c6219fc223e5b4a`。原候选提交 `ac0fe5780dea8c233327041b3bae7766ce87faf2` 的 [12 项 CI 检查](https://github.com/SUSTechWLA/tangying-robot-agent-os/actions/runs/38021264919) 全部通过。发布包的实际提交、main 发布门禁、资产 SHA-256 和验证范围记录在 Release 附件 `release-manifest.json` 中；正式标签只在该提交门禁通过后创建。

装修家庭 Gazebo 中，一个自然语言任务完成标定读取、移动建图并启用新地图、卧室/卫生间巡检、厨房杯子抓放与返回、最终地图/定位报告：耗时 1159.459 秒，7 个能力阶段、23 个子步骤、6 次实际导航抵达。注入的一次只读 RPC 故障由 Task/Ops/Recovery 链路诊断、独立复验并重试原命令后继续完成；上下文压缩、因果绑定、命令 journal 和原始证据可回溯。详细失败过程与独立复验见[长程验收报告](../experiments/2026-10-10-long-horizon-protocol.md)及[验收索引](../experiments/2026-10-10-long-horizon-acceptance.json)。

任务中的暂停由操作员发起；末尾原始导航报告 `ready=false`（定位年龄 1078ms 超过 1000ms 门槛），任务完成后的独立交接查询为 ready。两者分别保留。Ops/Recovery 使用确定性规则，任务规划使用实际模型，不宣称三个独立模型共同决策。此前四工位验收见[历史集成报告](../experiments/2026-09-22-gazebo-stable-integration.md)。本次家庭路线依赖已声明场景、地图和标定，不证明任意场景、物品、无人值守可靠性或实体机器人长程验收。

## 获取与使用

使用正式发布标签获取版本；Release 附件提供版本、检查及校验和凭据。

```bash
git clone --branch v0.7.0 https://github.com/SUSTechWLA/tangying-robot-agent-os.git
cd tangying-robot-agent-os
make setup
make test-agent-system
make home-furnished
```

家庭仿真操作见 [装修家庭演示](../guides/furnished-home-demo.md)，Gazebo 入口见 [家庭仿真操作](../guides/gazebo-house-operations.md)。完整软件版本、Python 包、机器人运行时与 ROS 包统一为 `0.7.0`；线协议和既有 `*.v1` 数据契约保持各自版本。

## 核心变化

- **长程协作协议**：不可变事件与完整因果绑定、受预算约束的热上下文/冷证据索引、跨任务作用域隔离、原始规划请求持久化、只读故障自动调查与复验、云边完成回执和防旧领导者 fencing。
- **家庭物理闭环**：真实 RGB-D 新鲜度、建图等待期间零速度保持、杯子可见路径筛选、持物越盘沿净空验证及双臂同步抬升；原始抓放计划身份和碰撞约束保留。

- **机器人运行链**：默认 Gazebo Harmonic 8.15.0，原生近距离吸附、RGB-D 工位感知、收臂与底盘支撑、双物体顺序任务及物理 oracle。Gazebo RGB-D 与位姿桥接、注册服务、建图工作流、接触实验后端及机械臂参数生成。MuJoCo 和 Gazebo 复用相同机器人/服务边界；各后端的已实现能力按实际目录声明。
- **建图与标定**：自然语言建图请求、地图库存与选择、语义工作区、探索前沿与覆盖评测、导航后的作业条件判断、手眼/几何标定求解与可视化引导。
- **物理接地验证**：Grounded Contract Language、独立验证器、VERIFIED/FALSIFIED/UNKNOWN、证据引用和分类恢复建议。工具 SUCCESS 不替代物理证据。`TANGYING_GVF_ENABLED=1` 显式开启可选验证路径，默认关闭。
- **Agent 上下文**：版本化事实包、来源/时序/作用域约束、确定性 JSON/自然语言渲染与分阶段表达实验。`TANGYING_AGENT_CONTEXT` 默认 `legacy`；研究配置的模型/阶段适用性限制继续保留，不能用某阶段的准确率替代完整任务成功。
- **系统 Eval**：20 项能力、7 层评测、12 类公开工具、34 个基础指标，以及严格配对比较、缺测/不适用处理、簇级统计与三态研究门禁。见 [设计与使用](../architecture/agent-evaluation-system.md)。本版提供离线评测底座，尚未统一接入所有闭环和实机 runner。
- **监督与恢复**：包含 v0.6.0 之后主线上已合入的多 Agent 运行时、运维诊断、审批范围、恢复执行与复验、任务回放、问题聚合及控制台轮询修复。恢复不会绕过权限或将未知物理结果当作成功。

## 已知边界与升级

- 本版是有明确适用边界的软件版本，不是实机安全认证。新机器人、场景、标定和地图仍须按 [发布验收清单](../operations/release-checklist.md)完成对应现场测试。
- 历史实验存在规划、恢复和部分验证器判定的未通过结果；这些结果完整保留在报告中，不能因为代码发布而改称能力已通过。
- 系统 Eval 的示例门禁只覆盖一个主指标和一个风险指标，不代替完整发布/实机放行。历史回放也不证明新候选的物理闭环收益。
- 新增研究模块按需开启，保持已有默认路径。升级前备份任务数据库、机器人配置与标定；场景几何或标定变化后重新校验地图身份。回退使用上一稳定标签 v0.6.0，并先核对数据兼容性，不重放未知物理命令。
