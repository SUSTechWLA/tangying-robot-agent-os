# 躺营 v0.3.0

> 2026-09-11。标签、最终提交、逐项 CI 结果和制品校验值见本版 [GitHub Release](https://github.com/SUSTechWLA/tangying-robot-agent-os/releases/tag/v0.3.0) 的 `release-manifest.json`。

本版的主题是**把"物理写工具的完成判定"从约定变成契约**。v0.2.0 已经能完成单机器人自然语言任务并保存原始观测证据，但"这个动作算不算做完了"仍取决于计划里有没有恰好排入参考清单中的验证步骤。v0.3.0 把判据下沉到工具契约：会改变世界的工具必须由**命令派发之后采集、带观测标识的新鲜证据**确认，返回成功码本身不再构成完成。任何适配器新声明的写工具自动受同一约束。

软件版本与实机放行仍是两项独立结论。`v0.3.0` 不代表已完成真实 XLeRobot 的现场验收，也不替代现场 `PHYSICAL_GO`。

## 获取准确版本

```bash
git clone --branch v0.3.0 https://github.com/SUSTechWLA/tangying-robot-agent-os.git
cd tangying-robot-agent-os
make setup
make build
./bin/robot-agent version
```

`VERSION`、Python 项目、内置 Runtime、MuJoCo 运行时、ROS 包与适配器运行时均为 `0.3.0`，由 `tests/test_repository.py::test_release_version_matches_distributed_components` 逐处校验。线协议版本 `1.0`、MCP 工具集和 `robot.profile.v1` 不随软件版本改动。

## 本版范围

### 新增：物理写工具闭环契约

- `core/closedloop`：单次尝试状态机（`PENDING → EXECUTING → AWAITING_EVIDENCE → VERIFIED | RETRYING | ESCALATED`）、失败分类（瞬时／感知／规划／权限／资源／参数／未知终态／致命）、有界重试与确定性退避、完成门禁。未知物理终态**永不自动重试**，只能进入人工对账。
- `mutates_world` 贯穿 `core/skills` → `skills/manipulation` → `robot.proto` → 插件运行时 → MuJoCo 运行时 → Go 客户端，单一真源为 `contracts.mutates_world()`。写工具为 `manipulation.pick`、`manipulation.place`、`navigation.navigate`、`recover_to_safe_pose`、`arm.move`；`emergency_stop` 是物理工具但不是场景写（其效果是锁存停止状态）。
- Go Agent 在通用执行路径强制闭环：写工具返回成功后必须附上新鲜、命令后、可命名的证据，否则步骤保持 `STARTED`、任务进入可恢复失败，且不发出成功文案。
- 时间判据按运行时实际精度：派发时刻截断到毫秒，落在同一毫秒的观测视为命令后，前一个毫秒仍拒绝；`DispatchPrecision` 单点定义，`Gate` 与 `Track` 共用。

### 修复

- **相机路径从未发布 `verification_confidence`**：判定写在服务实例上，而对外 `robot_state` 来自世界对象，控制台与证据读取端在相机路径上一直看到 0.0，确定性路径正常。现在写入 world 并在场景捕获时发布。
- **固定工位入口可能启动错误世界**（v0.2.0 后续发现）：`make rgbd-start`／`rgbd-restart` 显式声明 `--scene tabletop`；省略 `--scene` 而沿用记录场景时会打印提示与切换命令，`status` 报告实际运行场景。
- **绑定失败不可诊断**：区分 `grounding absent` 与 `grounding ambiguous`，消息附带机器人、adapter、观测数量、可见实体与场景切换命令。
- **口语指示代词终点被拒**："右边那个盒子" 等说法解析为同一批已配置容器。

### 变更

- 旧真值调试运行时（`--perception ground-truth`）不为观测提供标识，因此其写工具稳定失败关闭。`scripts/demo.sh` 与 `tests/e2e` 的物理任务改在相机工作台运行；`scripts/demo.sh` 同时显式使用 `simulation` 安全 profile。真值模式保留只读调试用途。
- 删除无人引用的 `core/toolcatalog` 与 `controlplane` 包；工具与能力契约由 `core/skills`、`core/closedloop`、`skills/manipulation` 与运行时能力声明承担。

### 保留

- 单机器人双 RGB-D 闭环、可选 RTAB-Map／Nav2 导航、家庭与家庭移动操作参考场景、双机器人 RoboCasa 交接。
- 原始观测回看、工具边界暂停与恢复、未知物理结果禁止重放。
- 统一 MCP 接入与异构机器人 profile；新适配器的驱动、标定、策略与验收仍逐台进行。

## 发布身份与本轮验证

本轮全量验证在冻结工作区执行：

```bash
make build && make test && make lint
```

- Go：全部测试包通过，`gofmt` 无输出。
- Python：**1184 passed、35 skipped**（跳过为主环境缺少可选 RoboCasa 依赖），`ruff` 通过。
- Web：**225 passed**。
- 文档契约、安装契约、协议契约、MCP 与策略 sidecar 测试全部通过。

闭环契约的定向验证：

.venv/bin/pytest -q sim/mujoco/tests/test_world_mutation_contract.py tests/e2e/test_observable_sequence.py

相机工作台上的实机闭环证据（14 个已确认工具步骤、4 个物理写各自的命令后观测证据、16 条采集的 RGB SHA-256 校验）在 `artifacts/closure-verification/`，复现方式见该目录 README。

上述结果全部来自软件仿真与隔离进程，**没有实机、现场制动距离、标定精度或长期可靠性结论**。验证范围与剩余门槛见[V1 当前状态](../production/v1-release-status.md)。

## 升级与回滚

- 从 v0.2.0 升级：`VERSION`／包版本变更不需要数据迁移；SQLite 与 World 快照格式未变。第三方适配器需要满足新要求——写工具必须让自己的观测可被标识（`SkillEvent.observation_id` 与真实采集时刻），否则其写工具会失败关闭。要求与做法见[异构机器人适配器开发](../development/robot-adapters.md#会改变世界的工具必须能被新鲜观测确认)。
- 回滚到 v0.2.0 会恢复"只在参考验证步骤上检查"的旧行为；回滚后不要继续使用为 v0.3.0 采集的候选证据。
- 真值调试模式在 v0.3.0 下不能完成物理写，这是预期行为，不是回滚理由。
