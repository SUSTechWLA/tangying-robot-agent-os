# 家庭场景 Sim2Real 接入

家庭场景的 Sim2Real 目标是让同一条 Agent 链在实机上继续成立：RGB-D 观测 → 三维感知 → RTAB-Map 定位/建图 → Nav2 规划 → 底盘执行 → 新一帧 RGB-D 与位姿确认。替换的是 Runtime Adapter、驱动、标定和感知 provider；任务版本、审批、租约、幂等、证据和恢复语义保持不变。

## 实机输入

推荐使用两路相机：头部相机观察远处和操作区域，底盘相机覆盖底盘前方的低矮障碍与通行盲区。两路都必须提供对齐的 RGB、米制深度、CameraInfo、采集时间和 optical TF；底盘必须提供真实轮式 `odom → base_link`。系统不接受全局摄像头、预制房屋模型或仿真物体坐标作为导航输入。

坐标树应保持：

```text
map → odom → base_link → head_depth_optical
                         └→ base_depth_optical
```

RTAB-Map 只发布 `map → odom`。相机外参属于标定版本；重新安装相机、改变支架或重建地图都要生成新的 transform revision，旧观测不能与新地图混用。

## 对接步骤

1. **登记硬件。** 在 `robot.profile.v1` 中声明底盘类型、关节/末端、两路 `rgbd_camera` source、更新频率、freshness budget、动作限值和工具子集。工具名仍使用 `navigation.navigate`、`verify_arrival`、`emergency_stop` 等规范名称。
2. **完成标定。** 保存两路内参、RGB-深度配准、`base_link → camera_optical` 外参、轮径/轮距和 `odom` 方向。使用标定板或 AprilTag 在客厅和走廊两处核对平移、yaw 和时间同步。
3. **先只读接入。** 使用 `input_mode:=ros` 启动导航包，确认 `/camera/base/*`、`/camera/head/*`、`/odom`、TF 和 PointCloud2 都有真实递增时间戳；先禁止电机使能。
4. **建立地图。** 在客厅、走廊、厨房、卧室、卫生间之间低速走完全覆盖路线，保存 RTAB-Map 数据库。门、人和移动物体不应被当作永久静态结构；未知区域保持未知。
5. **定位回放。** 使用相同地图启动 `localization`，从不同起点重复路线，验证定位丢失时 `ready=false`、底盘停止且任务不自动重放。
6. **低速执行。** 只在软围栏和实体急停可用时接通 Nav2 速度通道。逐项测试取消、断网、相机断流、里程计异常、碰撞/限位和恢复；通过后再接入抓取和动作后验证。

## 用户如何判断画面

工作台里的 RGB、深度和点云只代表机载相机已经采集到的内容。深度黑色表示无效/未知，点云空白表示没有测到点，不能解释成“那里没有障碍”。地图是由历史 RGB-D 和定位融合形成的结果，仍需显示地图版本、定位来源和新鲜度。执行后的“到达”必须由新的底盘相机采集和独立位姿误差共同确认，旧画面或 Nav2 文本成功不能替代。

## 放行条件

家庭场景的第一版只放行单机器人、受监护、限定房屋路线。以下任何一项缺失都保持试点状态：真实相机与里程计、急停和刹车距离、完整地图与定位、低矮障碍覆盖、断流停止、任务暂停/恢复、到达证据、至少 30 次重复路线和连续运行记录。仿真测试通过不构成物理安全认证，也不代表通用家务抓取已经实现。
