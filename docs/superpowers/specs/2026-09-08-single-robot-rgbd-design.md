# 单机器人 RGB-D 闭环与恢复设计

首版目标是一个机器人完成受限工作台自然语言任务；保留 robotId、统一 Runtime、工具、观测来源和资源接口以扩展多机。用户已授权代码、测试、启动验证及详细文档。本设计按该范围直接实施。

## 验收边界

- 新 RGB-D 路线仅以机器人头部相机 RGB、对齐的米制深度、相机内参及光学坐标到世界坐标变换产生环境实体。机器人关节和末端位姿可用自身状态；不以模拟器实体位置、隐藏对象、动作收据代替环境感知。
- 保留旧仿真与 RoboCasa 路线，明确标注 sim_ground_truth；它们不能作为 RGB-D 闭环验收证据。
- 通用感知接口接受像素检测器输出，重建世界坐标点云、实体及来源。随仓库的颜色/几何工作台检测器是受限演示，不能宣称通用物体识别或已训练实机策略。
- 每个物理动作前检查新鲜观测，每个验证工具重新捕获图像；看不见、深度无效、位姿不符应失败，不可回退读取世界真值。
- 仿真物理引擎保留物体碰撞/附着模型，控制目标由相机感知提供。模拟附着不等于真实抓取动力学验收。
- 暂停在工具完成并持久化后生效；恢复重新观测并跳过已完成步骤；不确定物理动作不得自动重放，也不能通过新 revision 绕过。
- ROS 接口接收 Image/CameraInfo、原始采集时间、捕获时刻 TF，输出同一 RgbdFrame；感知和运动插件分离，连接或 action server 存在不代表可运动。
- 移动建图为可选扩展。首版固定工作台；相机点云融合可以消费已验证的定位，不能把它描述为已实现自主 SLAM/Nav2。

## 模块

1. `robot/gateway/.../rgbd.py`：帧校验、深度反投影、检测器接口、标准重建。
2. `sim/mujoco/.../rgbd*`：头部相机 RGB-D 捕获、受限工作台感知和反馈验证；与原仿真模式显式隔离。
3. 新 ROS RGB-D 适配入口：同步、编码、TF 与 strict PluginBackend。
4. Local Agent/执行日志：暂停、恢复、未知动作防重放、终态证据。
5. Local Web：任务历史、恢复原因、命令和观测关联、观测来源。

## 验证与交付

保存本轮基线与 RGB-D 全链路任务、故障恢复及视觉检查证据；为无效深度、过期帧、相机外对象、未知执行与回溯补回归测试。文档明确软件验证结果和实机现场仍需完成的标定、策略、实体急停及连续验收，不能仅因测试通过宣称完成物理生产认证。
