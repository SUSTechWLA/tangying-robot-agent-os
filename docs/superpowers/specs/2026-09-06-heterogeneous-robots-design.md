# 异构机器人接入与统一 Agent 契约

本轮按用户授权在现有 V1 候选分支实施。目标是让不同机械结构、传感器和驱动通过一致工具与三维感知契约进入已有 Agent、任务审批、Runtime 和世界模型。

## 方案与边界

采用版本化能力清单、可插拔本地适配器、传输无关 Runtime 和 MCP 任务桥接。仅增加厂商判断分支无法控制契约漂移；重写现有调度与 Runtime 会丢失已有持久急停/幂等/租约保证。保留既有执行链，新增严格接入模式。

- `robot.profile.v1` 声明设备/模型/适配器身份、机械关节与末端、传感器、工具子集、动作键及单位限值。
- `scene.reconstruction.v1` 规定世界坐标、米、XYZ+四元数 wxyz、采集时间、来源/序号/坐标变换版本、语义实体和受限点云。适配器负责真实识别、重建和坐标转换，系统拒绝无效输入；不声称自带通用 SLAM 或感知模型。
- 新 Runtime 通过可选 protobuf Struct 字段携带版本化 JSON 合同。新 profile 必须有合格 reconstruction；已有适配器保留兼容，明确标为 legacy，不能自动获得严格接入认证。
- SDK 工具调用继续经过 Runtime 的可用性、动作限幅、审批、deadline/lease、幂等日志、取消/急停与 fencing 检查。新型号动作键来自清单，旧 XLeRobot 保护保持。
- Go Agent 在遥测与 Ground 使用感知前重新校验；不将旧帧标成当前时间，不将实机感知伪装为仿真真值。World 消费统一语义实体，原始/稠密传感数据留在适配器。
- MCP 使用官方 SDK，向不同机器人提供一致任务与查询接口；创建任务保留人工审批，MCP 不提供自动审批或任意裸硬件调用。

## 验收

两类不同结构的参考适配器通过同一 Runtime 合同；无硬件示例明确标为仿真。验证非法机械清单、传感器身份漂移、旧帧/未来帧、NaN/无限值、错误四元数、来源关系、越界和未声明动作、不可用工具、MCP 真 stdio 客户端、真实 Go/Python gRPC 接入。修复既有三项 MuJoCo 交接回归。通过项目测试与文档检查后提交并推送。

真实设备的驱动、标定、感知模型、动作策略与现场停止验证仍是设备集成工作；新增能力清单不表示任意机器人已可运行任意任务。自然语言任务规划继续受已实现技能范围约束。
