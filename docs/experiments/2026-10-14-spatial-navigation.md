# 2D、地形与 3D 空间导航实验

日期：2026-10-14。基线：`f2794e345d9419bb07b23ab123790ee0b6496b20`。设计先见[实施计划](../development/2026-10-14-spatial-navigation-plan.md)，接口见[空间导航](../development/spatial-navigation.md)与[注册测量建图](../development/spatial-mapping.md)。本报告保留成功、失败、测试修正和未测层级。

## 问题与实验单位

本轮验证四个问题：能否保存完整 SE3 注册测量并获得保守三态空间地图；能否区分空中与地面的几何路径；完整位姿、地图版本与命令后定位是否贯穿 ROS 2 执行；旧二维与持久任务机制是否保持有效。

实验单位分别是一次地图采集/发布、一次拒绝条件、一次明确自然语言任务，以及一次命令/到达验证。它们不合并为统一“机器人成功率”。所有三维控制器运动都是记录式位姿更新，真实通信使用 ROS 2 Jazzy DDS 与 gRPC；本轮没有飞行、步态或碰撞动力学，也没有实体机器人。没有测量 SLAM 精度、漂移、ATE/RPE、控制跟踪误差、小时级可靠性或模型泛化。

主机运行 Go/Python；ROS 测试在隔离 Docker 容器中使用本地 `tangying-navigation:dev` 镜像、Linux ARM64 Local Agent 和 ROS 2 Jazzy。容器 `--network none`，只允许容器内节点通信；不接现有机器人。源码目录只读挂载，实验输出写独立目录。消息包和网关重新 colcon 构建；记录式控制器无需模型服务，模型调用数为 0。

## 预定任务与判据

一次提交完整自然语言：

> 从客厅出发，去厨房确认一下环境，然后去卧室，再回到厨房，再去卧室，再回到厨房，再回到客厅，再去厨房，再去卧室，最后回到客厅。最后回到出发点。

预定十个具名访问为：客厅 → 厨房 → 卧室 → 厨房 → 卧室 → 厨房 → 客厅 → 厨房 → 卧室 → 客厅，再返回独立的实测起点。起点 x=-0.5，客厅 x=0，避免两个目标重合掩盖回起点逻辑。具名顺序在脚本内固定，不能仅用解析器自己输出的列表作为判据。

每种 Profile 单独启动 Local Agent → gRPC Runtime → ROS 2 Profile Gateway → 记录式控制器；以控制台会话提交和批准这条测试任务。成功要求任务终态、11 次独立导航及 11 次到达验证、路径 ID、确切命令后观测、原始具名顺序和实测起点全部一致；不得引入地面 pre_position，不得重复物理命令。

导航图为明确标记的合成体素场景，分辨率 0.25 m、16×16×12 体素；包含低矮隔墙。测试包络半尺寸为每轴 0.04 m、margin 0.01 m，仅用于小场景程序验证，不是设备调试参数。无人车和足式使用显式单层平面支撑，需从墙端绕行；无人机的具名目标有不同高度，可选择空中路线。这个控制实验单独验证导航与执行协议，不把合成 free 体素称为真实传感器测量。另有独立注册测量→地图→规划实验验证自由证据来源。

## 建图与故障验证

最终本地检查：Go 测试包全部通过；重建 CLI 后的广泛 Python 回归 **3327 passed、40 skipped**，独立 Runtime 边界 **2 passed**，文档 Python **22 passed**；最后修改的空间/定位/桥接/采集与合图集合另外 **289 passed**；Web **517 passed**。`make build`、`make lint`、`make generate-check`、Go 文档和分类目录检查通过。集合存在重叠，不把这些数字相加当作独立实验数量。40 个跳过项未计为通过；20 条广泛回归警告来自既有 pytest 重写与 NumPy matrix 弃用提示，日志保留。

广泛回归启动后进行了最后的四元数归一化修正，因此最终该模块的依据是随后独立执行的 289 项集合和 run5 DDS 路线；不以之前已收集的用例替代最终修改检查。

注册测量测试使用 442 个记录式房间表面命中，通过记录式光心字段与命中点构造的射线得到 405 个自由体素。地图原子发布后，加载器核对文件、包摘要与测量重放结果，再生成高度 2.5→4.5 m 的路径。自由空间由射线产生，不直接修改体素数组来伪造这项判据。

新增 ROS 2 空间采集节点测试通过 DDS 接收同格式帧，覆盖 Trigger 保存与达到帧数自动保存；拒绝空包、未登记来源和动态切换仿真时钟。单元测试另覆盖姿态/高度、光心与底盘差异、重放/倒序/过期、版本漂移、近障碍遮挡、体素边界射线、存储失败冻结重试和重算摘要也无法掩盖的推导篡改。实际 DDS 采集结果以 JSON 索引中的 mapper 摘要为准。

执行故障验证覆盖错地图/世界/标定、低质量或 stale/lost 定位、回放不延长时效、控制器部署摘要错误、路径 ID 错误、路径中间点超 workspace、成功却高度/姿态未达到。真实 Runtime 服务的故障注入测试确认导航中丢定位产生 `SAFETY_STOPPED / EXECUTION_OUTCOME_UNKNOWN` 并调用登记的停止流程；该项为 CPU 服务测试，不写成实机急停距离。

## 失败与修复台账

| 尝试 / 发现 | 实际表现 | 处理与保留 |
| --- | --- | --- |
| 基线远程 CI | 镜像测试漏新 exchange 角色；两组 MuJoCo 模式切换触发持久 pin 冲突 | 更新逐角色预检断言；按场景/模式/seed 隔离仿真历史，保留 pin 严格性；原 CI 失败日志保留 |
| 第一条空间 UGV NL（run1） | 创建任务 422；解析器不识别末尾“回到出发点”，无导航派发 | 新增严格末尾回起点语法，拒绝夹带后续动作；保留 422 摘要 |
| 第二条 UGV NL（run2） | Task SUCCEEDED，10 次导航；验收要求 11 次而失败 | 起点原来等于最后的客厅，系统正常合并同一目标；改测试起点而非降低断言，保留这次实验失败 |
| 几何独立审查 | 公共 map/policy 可变；大的 maxStep 允许悬浮或跨谷捷径 | 地图/策略只读副本；起终点贴地、长线整段贴地、仅相邻地形过渡允许步高，保留谷底节点 |
| 姿态阈值独立审查 | 输入允许轻微四元数范数误差，直接点积会将实际 0.11 rad 误判进 0.10 rad 阈值 | 计算夹角前归一化两端四元数；新增 72 组尺度/符号/阈值边界回归，随后最终 run5 重跑三条任务 |
| 三维射线边界审查 | 负向面/棱/角出发时零长度接触可能错误形成 free | 仅认证正长度内部穿越，平行体素面不认证邻格内部 |
| 二维合图审查 | 旋转或非整格偏移经 round 可能错位写入 | 共同旋转晶格合图，不同 yaw / 半格偏移显式拒绝 |

| ROS2 mapper 接线尝试 | 自定义 `_parameters` 回调与 rclpy 内部字段同名，节点启动失败 | 重命名并增加实际动态参数拒绝测试，保留首次失败 |
| 回归命令初次路径错误 | 指定不存在的 `test_robot_workflow.py`，未执行测试 | 按实际测试路径重跑，保留 no tests 日志 |

## 复现与证据

原始证据位于 `artifacts/experiments/spatial-navigation-20261014/`。机器可读[JSON 索引](2026-10-14-spatial-navigation.json)保存任务摘要、环境/命令说明、源码和证据 SHA256；[逐次任务 CSV](2026-10-14-spatial-navigation.csv)保留所有 NL 尝试；[33 段路径 CSV](2026-10-14-spatial-navigation-paths.csv)逐段关联 task/command/plan/map/观测身份、航点数和几何长度。几何长度不是实体里程，也不能用不同目标高度的两种模式直接推导性能优劣。原始日志、任务数据库、地图包和大型二进制不默认随 Git 发布；摘要不是原始数据的替代品，论文复核需保管原始目录。

在已经加载构建后的 ROS 2 环境中复现（每次换新的输出目录）：

```bash
python3 tests/contract/spatial_scenarios.py --kind uav --output /tmp/spatial-uav-map
python3 scripts/run_ros2_edge_acceptance.py --binary /path/to/linux/local-agent \
  --kind uav --spatial-deployment /tmp/spatial-uav-map/deployment.json \
  --return-start --output /tmp/spatial-uav-task
python3 tests/contract/ros2_spatial_mapping_smoke.py --output /tmp/spatial-mapper-test
```

将 kind 改为 ugv、legged 分别运行。ROS 2 消息包两端必须同版；脚本不连接实际设备。Python/Go 回归结果、最终 mapper 摘要和文件摘要统一记录在 JSON 索引；实验后续扩展不得回写覆盖本次失败。

## 可支持的结论与下一轮

本轮证明该软件版本具备分开的二维、地形和三维几何通道，完整空间身份与定位证据进入边缘执行链，三个机器人 Profile 在记录式控制器下完成相同长路线协议。它尚不能证明任意机器人可执行任意地形/飞行任务，也不能证明云边通信实现了联合轨迹避碰。

下一轮应固定真实设备与控制器，在受控场景测量定位 ATE/RPE、目标位置/姿态误差、动态障碍拒绝、失联停止延迟、坡面/台阶可达性及不同地图规模的 P50/P95 规划延迟。再将小时级任务、断网、重定位和进程恢复纳入独立预登记。需要消融时，以相同测量数据比较二维投影与三维体素，不用不同场景的成功任务直接推导优劣。
