# 实验报告

本目录存放**有完整论文结构的实验报告**——即"问题 → 方法 → 对照实验 → 数据 → 结论与局限"齐全、
可以脱离开发过程单独阅读、并且**可以直接取用为论文素材**的记录。

**与 `docs/development/` 的分工**：`development/` 是开发过程记录（设计、计划、审计、缺陷定位、实现说明），
回答"我们当时怎么想的、改了什么"；本目录回答"**我们测了什么、数字是多少、能得出什么结论**"。
一份文档如果只有结论没有对照数据，它属于 `development/`；如果有可复跑的对照数据与结论，它属于这里。

**收录判据**（三条都要满足）：

1. 有明确的**被测问题或假设**，而不是"这一轮做了什么"；
2. 有**对照实验或量化测量**，且给出了可复跑的命令与数字；
3. 有**结论与局限**，包括被数据否掉的假设。

### 贡献 E：语义地图的表达方式与自然语言导航

> 核心论断一：**"厨房在哪里"至少有四种都说得通的答案，而它们的区别是"人要告诉机器多少关于这栋房子的事"**；
> **在地图完整时**，人在地图上点一个点（`seeded`）严格优于人写一个完整位姿（`static`）——
> 精度持平，人工输入少 25%，可操作余量高 52%。
>
> 核心论断二（同一篇报告的 §6.4.4，**限定论断一**）：**在地图欠巡检时这个优势会反转**。
> 在一张 36% 未知的真实巡检图上，`seeded` 命中 0/12–6/12，而 `static` 把机器人
> 成功送到了三个房间。所以最终建议是**条件式**的，判据是分割覆盖的可行驶面积占比。

| 报告 | 支撑的论断 | 关键数字 |
| --- | --- | --- |
| [**语义 SLAM 地图的表达方式与自然语言导航**](2026-09-20-semantic-map-representations-and-nl-navigation.md) | **主报告**：四种表达方式的对照实验 + RTAB-Map 代码审计 + 32 条自然语言表述实测 + **现场闭环**（真栈上"说话 → 驾驶 → 判定能否干活"） | Gazebo 上 `seeded` 最小净空 1.38 m vs `static` 0.91 m、人工输入 12 vs 16；**但真实巡检图上 `seeded` 命中 0/12，`static` 把机器人送到了 3 个房间** |

**这篇报告独有的四类素材**（其他报告没有）：

1. **一个被数据否掉的参数选择过程**——房间位姿的取点规则迭代了四次，前三次（质心 / 距障碍最远点 / 限制在核内）
   全部被 Gazebo 户型否掉，理由逐条记录在 §2.3。可支撑"阈值型参数该用什么单位"的方法学论断。
2. **一个真实的自然语言缺陷**——「厨房」能解析而「去厨房」不能（§5.1），
   且失败表现是 `NOT_FOUND`，读起来像"这个房间不存在"。这是把"多测几种说法"变成可引用发现的例子。
3. **一张参数敏感性曲线而不是一个点**（§4.3）——门宽半径 0.30→1.10 m 的六档扫描，
   说明"参数选对了"的判据不是某个覆盖率数字，而是**划出的区域数等于人会说的房间数**。
4. **两个只有写测试才会发现的缺陷**（§2.4、§2.5）——门宽阈值的文档写成"两倍半径"（实际是两次腐蚀之和
   `2 × (footprint + margin + door_radius)`，按错的选会让整栋房子变成一间房且不报错）；
   越界起点会静默关掉可达性过滤，把墙那侧走不到的房间发布出去。
   两者可支撑"'为它写测试'本身是一种审计手段，且抓到的东西与读代码不同类"这条论断。
5. **一次完整的现场闭环，连带四个只有真跑才会暴露的缺陷**（§6.4）——
   语义目标丢掉高度导致**每一个**目标在底盘动之前被拒；复合技能只下达一半偏航角；
   可达距离从基座原点而不是肩关节量；可操作范围漏掉底盘作业移动量，
   在现场表现为**一次假阴性**（判定说够不着，实际抓取成功）。
   另有**一处可复现的导航失败**（返程腿 `NAV_MODEL_COLLISION`）与
   **一个推翻前文结论的阴性结果**（§6.4.4）。可支撑"静态审计、单元测试、现场闭环
   抓到的是三类不能互相替代的东西"这条论断。

**引用这一篇时要注意**：

* §3 是**静态审计**（读代码与参数对照阅读），不是实跑测量；
  R11（OctoMap 是否编译进去）与 R12（高度带参考系）作者未能在仓库内确认。
* §4 的表达方式对比是在 **Gazebo 真值栅格**上做的，而 §6.4.4 在**真实巡检栅格**上
  得到了相反的结论。**引用 §4 的数字时必须同时引用 §6.4.4 的边界条件**，
  否则会把一个"地图完整时才成立"的结论说成无条件成立。
* §6.4 的闭环是**真实**的（真栈、真 gRPC、真运动），但只跑了 4 条腿、**其中 1 条失败**。
* §4、§5、§6.4 都可复跑，命令见该报告 §9。

## 三、写作时的注意事项

**可以直接引用的**：本目录所有报告中的对照数据表、复现命令、以及"被数据否掉的假设"清单。

**引用前需要复核的**：

1. **数字有代码版本**。每篇报告都注明了它测的是哪个提交/哪一版参数。跨报告拼表时先确认口径一致——
   本文档集里就出现过同一个常数改了单位、导致前后不可比的情况。
2. **两个覆盖率分母不是一回事**。运行中的调查报 `1 - unknownFraction`（分母是自己栅格的全部格子），
   评测台报 `mapped / coverable`（分母是可达位姿真正看得见的地板）。
   跨"仿真 vs 现场"比较时**必须先确认分母一致**，见实验报告 §5.4。
3. **仿真结论不自动等于真机结论**。每篇报告的"局限"一节写明了各自的适用边界，引用时请一并带走。
4. **阴性结果与阳性结果同等重要**。实验报告 §7.3 有一份"已经替后来者花掉的成本"台账，
   写相关工作或方法选择时可以据此说明为什么排除了某些方向。
5. **真值必须来自被测系统的同源物之外**。语义地图报告的四种表达方式是用**世界文件的隔墙拓扑**评的，
   不是用"人手写的位姿表"——否则 `static` 必然 100% 正确，对比就成了同义反复。
   同理，如果要用那个评测台评别的户型，需要**先写出那个户型的真值**，而不是换一个开关：
   评测台会主动拒绝在它没有真值的户型上运行。

**尚未解决、适合作为后续实验起点的问题**：见实验报告 §7.4；
语义地图表达方式报告的 §8.3 另有一份按优先级排的清单（现场闭环验证、SLAM 所有权、`approx_sync` 覆盖）。

## 四、复现环境

所有报告的实验都可以在本机复跑，不需要真机：

```bash
make setup && make build

# 跨仿真器覆盖率（每个约 12–15 秒，首次运行会栅格化真值并缓存）
.venv/bin/python scripts/exploration_survey_benchmark.py --truth mujoco --strategy baseline
.venv/bin/python scripts/exploration_survey_benchmark.py --truth gazebo --strategy baseline

# 拒绝鲁棒性（每种配置约 20–40 秒）
.venv/bin/python scripts/exploration_robustness_benchmark.py \
    --strategy baseline --refusal-rate 0.1 --refusal-rule step --seeds 5

# 现场地图与评测台同分母评分
.venv/bin/python scripts/score_live_map.py --map <地图包目录> --truth gazebo

# 语义地图表达方式对比（不需要仿真器：真值栅格已缓存；每个约 1 秒）
.venv/bin/python scripts/semantic_map_benchmark.py --truth gazebo \
    --json artifacts/semantic-map-benchmark/run-1/report.json
.venv/bin/python scripts/semantic_map_benchmark.py --truth gazebo --door-radius 0.90
```

现场实验（需要 Gazebo 栈）见 [Gazebo 家庭场景操作](../guides/gazebo-house-operations.md)；
跑之前必须清空上一轮的 SLAM 状态，理由见实验报告 §8。
