# 当前系统评估与追加任务实验协议

日期：2026-10-13（北京时间）。被测基线：`76b516a18a78402d257f624b11f46f475caada8c`。本文件先于本轮任务执行登记；结果及所有偏离另记，不以结果修改判据。

## 问题与条件

本轮检验：当前系统能否在现有 Gazebo 家庭场景完成顺序任务；单次只读传输故障能否经过 Task / Ops / Recovery 归因、调查、独立复验与有限重试；完整巡检建图、跨房间抓放及超过一分钟暂停能否保持任务与上下文身份；能力缺失和不明确指代是否在执行前阻断。

这是同一场景、同一 XLeRobot 的追加工程实验，不是独立留出集、多机器人、实体机器人或通用语言能力的统计证明。GOAL 使用已有私有模型配置，记录实际路由和保留的模型请求；不提交密钥。三个 Agent 是系统内责任角色，不据名称假定三个独立模型。

建立独立命名空间 `artifacts/experiments/system-20261013`，从当前代码重新构建 Local Agent，并保存二进制、源码和镜像摘要。新 Gazebo episode 从家庭初始状态开始；复用此前停机的同场景工作流地图、标定绑定及匹配的 RTAB-Map 数据库，记录每个来源文件 SHA-256；不复制任务库、导航命令库或机器人命令日志。episode 标号 13 不表示动力学确定性随机种子。Console、Runtime、故障代理分别使用 8907、50261、50262，避免操作其他部署。

首次只复制工作流地图导致定位模式启动拒绝；保留 `logs/startup-001-incomplete-map.log`，补齐匹配数据库后启动。此为实验准备错误，单列且不计机器人任务分母。所有正式任务从就绪门禁通过后执行。

## 数据和执行规则

使用生产 Console 创建、批准、暂停、继续、查询及必要取消，不直接调用底层运动 API推进正式任务。执行脚本本身授权仿真运动。旧或未知物理副作用不自动重放；不清空失败库、不覆盖旧任务、不放宽安全/新鲜度/净空门槛。发生未决物理动作时停止后续运动，先核查实际状态，记录操作员介入。

每任务保存原句、预算、草案/批准后计划、所有 HTTP 原响应、状态快照、终态、事件、不可变版本、观察与图像、模型路由、故障日志、验收报告和 SHA-256 清单。独立重验先验证文件摘要，再检查动作/观测身份、三值判据与上下文绑定。拒绝任务保存 HTTP 错误正文和 planning attempt；不能仅写“422”而丢掉原因。Token数量/调用费用/硬件故障没有采集器时写未测量。

补充契约回归覆盖 Agent 协议、上下文压缩/归档/跨域绑定、恢复授权、云边 completion/fence/重启。它们属于契约/组件层，用例数量不增加 Gazebo episode 分母。运行日志包含命令、开始/结束时刻、退出码和完整测试输出。

结果表同时给出计划能力数、已核验能力数、导航误差、用时、状态、独立验收、恢复链、模型轮次、上下文压缩/回读实测计数和未知项。记录安全停止与失败，但有限轨迹未见事故不等于事故概率为零。不给仿真结果外推实机或异构机器人协同保证。

## 停止与偏离规则

超时、计划拒绝、执行失败、UNKNOWN 和验收失败均保留原分母和证据。不能以新任务成功追改旧任务。需要环境或代码修改时冻结旧运行，另记修改、版本和新运行条件。本轮以至少一次完整任务实际尝试和预定边界/故障任务记录为交付标准；若全流程失败，交付失败定位及未覆盖阶段，不声称已完成未执行部分。

## 执行前条件修正 A1

R01、N01 的创建草案均为 `plan.source=llm`，预注册的 deterministic 门禁拒绝批准并取消草案，未发生运动。核对 `internal/capabilityagent/planner.go` 发现：配置 GOAL decider 时，所有目标由模型规划；离线整句语法仅在未配置模型时使用。这是本轮实验者的条件设置错误，不是系统任务执行失败。原报告及分母保留，单独标为“批准前验收条件失败”。

追加 R02、N02，原句、预算、预期物理结果与 R01、N01 相同，规划来源改为已配置的 `llm`；R02允许只读 `mapping.inventory` 等目录调用，不假定模型必须恰好输出三个调用，但至少覆盖原目标且没有物理副作用。其他预定任务不变。不依据规划来源门禁失败声称机器人可靠性下降，也不依据追加通过声称首次尝试成功。

## 缺陷后的追加协议 A2

L01 的 Task 自报 SUCCEEDED，但原执行验收及冻结检验器的独立重验均因 `arrival count differs from this frozen capability route` 拒绝。实际冻结子请求“去厨房拿杯子，把杯子放进收纳盘”使旧解析器将第二次名称引用加入 pending 列表，生成两个完整家庭抓放；观察到两个不同 step 的 pick/place，各非命令重传。原 L01 不改写、不计完整通过。

在没有运动任务运行时，先保存修复前的失败回归，再修复 pending 名称引用：相同完整对象列表的把/将放置子句引用已有 pickup；类别、属性、列表数量冲突要求澄清。已完成操作之后的明确第二次动作仍保留，不能全局去重动作。增加验收 `--expected-home-transfers`，批准前比较冻结子任务的操作数量，执行后核对实际 pick/place 派发数量。系统安全阈值、Gazebo镜像、地图和原失败账本均保持。

追加 P01：原句 `从客厅出发，去厨房拿杯子，把杯子放进收纳盘，然后回到客厅`；同一 world episode、L01 后位于客厅、杯子已在盘中；重新构建并重启 Local Agent，复用同一任务库和 Runtime journal，记录修复源码 diff 与二进制 hash。预算900秒、LLM来源、至少2次到位、独立抓放核验、**恰好1对pick/place**，故障arm关闭，不传递旧F01故障日志。P01是针对解析缺陷的仿真复验，不代表修复后完整L01已再次成功；初态也不与首次家庭取物相同。

故障日志是共享代理的全生命周期日志，L01原包包含发生在F01的旧记录。原独立重验先因路线不一致拒绝，尚未进入故障/上下文/暂停各项；另做明确标为“失败运行的子项审计”的补充报告，不删除旧故障或将F01恢复计为L01恢复。
