# Gazebo 默认引擎迁移与分层验收

日期：2026-09-22。基线提交：`906e5081b573d607248bf3fd2053a78500385fa9`。本轮在 macOS Docker Desktop、8 GiB Linux VM、软件渲染环境中执行；不是实机试验，也不是跨引擎物理精度排名。

## 问题与验收口径

将工作台默认后端从 MuJoCo 改为 Gazebo，要求相机、ROS 2 控制、地图、动作 journal 和进程管理使用同一运行路径。分开回答四个问题：场景是否真正启动；传感器与工具合同是否有效；运动与停止是否真实发生；完整业务任务是否成功。前一级通过不能推导后一级通过。

四个场景为 `home`、`tabletop`、`home_task`、`home_furnished`。同名不意味着两个引擎有完全相同的资产、动力学或任务物品。本轮新增的桌面夹具不是历史 MuJoCo 全任务结果的复制。

## 方法

- 由 `sim-stack.sh` 拥有实际 Docker/Gazebo 和 Local Agent 进程；评测经公开 gRPC/HTTP 运行，不用桩替代物理后端。
- 双相机检查 PNG、深度、至少 50 个实际深度点、来源身份、捕获身份和不超过 1000 ms 的采集年龄。
- 读取完整服务目录；当前位置到达检查成功，偏移 1 m 的目标必须拒绝，防止常量成功回执。
- 关节请求左肩旋转 0.15 rad，要求四个不同时间戳的反馈收敛至 0.04 rad 内，并检查实际位移超过 0.08 rad，然后回位。
- 取消测试等待实际关节运动，再取消，检查终态和停止后漂移。急停测试在独立命名空间锁存急停，验证建图运动服务被阻止；重启不得作为解除锁存的手段。
- Nav2 检查要求前方已探明且安全，目标为前进 0.15 m；必须同时有成功终态和至少 0.05 m 的实测位移。失败保留 ROS 日志和导航 journal 的 failure observation。
- 完整任务能力门禁独立于基础集成检查。缺少抓取工具时，`--require-full` 必须失败；工具齐全也不等于已经执行并通过完整任务。

## 修复与对照

| 观察到的问题 | 修改 | 证据性质 |
|---|---|---|
| Gazebo 只有独立入口，默认工作台仍启动 MuJoCo | 默认 engine、四场景组合、明确 legacy 开关 | 真实进程与 adapter 身份 |
| 请求头部图像时仍返回默认相机 | `Observe.source_id` 贯穿网关，固定一次捕获快照 | 来源/图片/世界变换测试 |
| 关节相对位姿误用为模型绝对位姿 | 从同一运动学表生成 parent-relative SDF | 两臂各链接 FK 误差不超过 2e-5 |
| ROS 没有完整关节反馈/命令桥 | 12 条目标话题和 `/joint_states` | 真实反馈收敛 |
| 动作结束把所有关节的下垂测量覆盖为新目标 | 成功保留目标值，失败/取消才保持当前位姿 | 桌面回位失败样本与复测 |
| 并发观测较早帧晚完成，被误报序号倒退 | 采集至序号校验为有序事务 | 并发回归；真实源倒退仍拒绝 |
| telemetry 缺 FaultReport 导致 Local Agent panic | nil 安全读取 | Go 回归测试 |
| 图像/建图 CPU 竞争造成旧捕获 | 数值线程限制、未使用原始点云惰性桥接 | 保留超时样本，未放宽采集门槛 |
| 全局地图边界裁切足迹，起点仍为未知 | 周围添加未知单元，保留原始网格全部值和坐标 | 原生 Nav2 足迹处理可工作，未修改未知禁行规则 |
| Nav2 健康 action server 未在 20 ms 内确认 | Gazebo 单独将 ACK 等待设为 1000 ms | 只调整通信确认；新鲜度、速度租约和任务 deadline 不变 |
| 世界配置变化可能复用旧 RTAB-Map 数据库 | 集成入口按场景及世界内容摘要分数据库目录 | 旧数据保留，新版本单独建图 |
| 工作台轮询重复下载 20 份历史点云，拖慢实时相机 | 增加显式 `history=false`，实时路径只取最新观测；400 ms 调度且不重叠请求 | 保留历史 API 和原采集时间；Go 合同与浏览器回归 |

ACK 参数单位及默认值参考 [Nav2 Jazzy 官方说明](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/core_servers/bt_plugins/actions/NavigateToPose/)。

## 渲染配置试验

装修家庭 320×240 配置可见 397 个当前帧视觉词，但一次导航因 RTAB-Map 处理年龄 2677 ms 超过 2500 ms 上限而停止。160×120 配置在一次现场读数中当前帧词数为 0，未达到 20 的最低质量要求，因而被放弃。最终试验配置为 256×192、关闭阴影；测得当前帧 222、词典 259，定位就绪。

这些样本用于定位瓶颈，不是随机化因果实验。模型、负载、地图历史、配置和软件修复均有变化，不能将差异全部归因于分辨率，也不能给出稳定成功率或最优参数结论。

## 四场景最终回归

同一构建镜像的四场景矩阵 **4/4 启动成功、32/32 基础检查通过**；每场景只有一次独立 episode，不作为长期成功率估计。每场景都执行两路相机、目录、正/负到达、关节回位、运动中取消和急停门禁。

| 场景 | 基础检查 | 两相机最大年龄 ms | 动作末关节误差 rad | 取消后所测关节漂移 rad |
|---|---:|---:|---:|---:|
| `home` | 8/8 | 371 | 0.011088 | 0.0004846 |
| `tabletop` | 8/8 | 378 | 0.004805 | 0.0000006 |
| `home_task` | 8/8 | 293 | 0.002799 | 0.0003921 |
| `home_furnished` | 8/8 | 317 | 0.010808 | 0.0006700 |

所有场景的急停后 `mapping.start` 均返回 `EMERGENCY_STOP_LATCHED`。矩阵关闭了自己拥有的容器和 Agent，未删除日志或锁存 journal。矩阵**不含导航路线和抓取任务**；报告字段明确为 `navigationRoutesEvaluated=false`、`manipulationTasksEvaluated=false`。

镜像源摘要：`4372ee8329f053d01e40325bbd14218a9d4d1a875e6320c2594b12a15b8e8f5c`。原始 `matrix.json`、四份 `report.json` 与图片/日志保留于本地 `artifacts/gazebo-migration/matrix-final/`，不纳入 Git。

软件验证：网关测试 834 通过、4 跳过；ROS/新部署回归 54 通过、1 跳过；Console、Local Agent、Robot Client 和文档 Go 测试通过；前端 477 项通过；全仓 Ruff / gofmt 检查通过。安装测试最终 174 通过、1 跳过（158.94 秒）。

安装测试首次在渲染负载下出现 4 秒启动窗口超时；另一次低负载回归暴露 demo 故障注入的竞态：只延迟第一个 `Observe` 请求时，并发订阅仍可提供有效观测，测试却错误要求此时不能创建任务。修正为在检查任务队列前阻塞所有观测订阅，保留“无新鲜观测不得开始”的断言。未删断言或放宽生产就绪检查。

## 装修家庭最终导航

应用地图边界处理、256×192 渲染和 ACK 超时修正后，在全新场景数据库上经 Runtime 的 `navigation.navigate` 执行前进 0.15 m。返回 `NAVIGATION_SUCCEEDED`，实测位移 **0.145200 m**，该项耗时 **10.262 秒**。两路相机年龄分别为 173 / 156 ms；关节运动、回位和运动中取消也通过，取消后所测关节漂移 0.004625 rad。此独立运行 8/8 检查通过，未锁存急停。

原始报告为本地 `artifacts/gazebo-migration/furnished-nav-final/report.json`。这是单次短程导航证据，不能外推为四场景全路线、跨房间导航成功率或完整移动操作验收。用户原工作台 `8897` 已接入 Gazebo 装修家庭，原 MuJoCo 地图和任务记录保留。


## 复现

```bash
make setup
make build
.venv/bin/python scripts/evaluate_gazebo_scenes.py \
  --output artifacts/acceptance/gazebo-scenes-1 --estop
# 单个已启动现场，增加 Nav2 位移测试
.venv/bin/python scripts/evaluate_gazebo_runtime.py \
  --runtime 127.0.0.1:50051 --output artifacts/acceptance/gazebo-route-1 --motion
```

每次输出目录必须不存在，避免覆盖旧实验。四场景矩阵使用独立端口和数据目录，逐场景启动与测量，最终只停止自己拥有的栈。它不包含导航路线覆盖或完整抓取任务，报告显式标记这两个范围未测。

## 局限与发布边界

当前缺少六项 Gazebo 工具：目标解析、抓取规划、拿取、放置、抓取验证、放置验证。检测器仍未提供任务实体，关节运动成功也不能证明真实接触抓取成功。因此不能宣布“全部业务场景已经调通”，不能用 MuJoCo 任务成功率填补 Gazebo 的空白，也不能据此发布完整功能通过的稳定版本。

后续完整操作验收必须具备：与机器人模型一致的固定/移动夹爪碰撞几何、传感器目标识别、碰撞安全的 IK/轨迹控制、接触与独立视觉验证、移动操作安全足迹，以及各任务多次独立 episode 的成功率和置信区间。本轮只报告实际测得结果，不声称最优引擎、普适稳定性或实机可迁移成功率。
