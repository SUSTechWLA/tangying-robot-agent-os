# Gazebo 经典控制与边缘任务全链路实验

日期：2026-10-18。基线：`cbd4ca2cedb711647fb0e608823c3507c737d1a3`。

本轮按用户要求使用 Gazebo Harmonic 8.15，不使用强化学习。实现见[变更记录](../development/2026-10-18-gazebo-field-validation.md)，学习路径见[教材补充](../../book/updates/2026-10-18-gazebo-field-validation.md)。实验过程中发现的问题、失败任务与修改后的复测分别保留，不能只以最终通过轮次估算系统成功率。

## 实验对象与证据边界

两台地面机器人使用有质量、惯性和真实碰撞的全向力驱动基座；无人机使用机体 Z 轴推力与经典姿态 PD。所有位移由 Gazebo 物理积分产生，无 `SetPose`、速度赋值或 Python 目标位置瞬移。地面模型分别接 UGV / legged ROS 2 Profile，但后者仅验证足式类别的系统协议，不含宇树关节与步态；无人机也不是大疆飞控。

自然语言任务真实经过 LocalAgent HTTP、gRPC Runtime、ROS 2 DDS、ProfiledExecute、带租约的仿真 hub 与 Gazebo。三个 LocalAgent / Runtime / ROS driver 独立运行；peer 避碰计算仍由一个测试 hub 集中协调，不是无线分区下的分布式自治证明。自然语言使用固定句式的 deterministic provider，模型调用数为零。

位置来源明确标为 Gazebo 机体真值代理。激光、IMU 和接触来自 Gazebo 传感器，避障点由真实极坐标激光返回计算，运行外参为显式仿真配置。离线估计的标定和地图配准单独验收，不把其误写成在线 SLAM 已闭环。保留约 0.1 仿真秒间隔的状态、周期性完整激光快照，以及接触主题的逐碰撞对累计记录；没有声称记录了每一帧完整点云或连续时刻的精确安全距离。

## 预定任务和判据

单条指令要求依次访问“客厅、厨房、卧室、厨房、卧室、厨房、客厅、厨房、卧室、客厅”，包含起点的导航及独立确认，共十组。各机器人有不同的三维位置绑定，地面路线包含交叉会车，无人机路线包含高度变化。每次导航后独立调用 `verify_arrival`，必须引用命令之后的新测量，位置误差不超过 0.12m、姿态误差不超过 0.15rad。导航 hub 的状态判据要求速度不超过 0.07m/s；driver 随后读取的导航/确认回执另要求不超过 0.08m/s。二者可能来自相邻物理帧，报告回执指标时使用后者，不能由回执单独证明前者。

轮次标签为 3、7、19，控制 stale-peer 注入时机；它们不表示三个独立地图或随机环境，7 与 19 的注入偏移相同。每轮向 ground-a 注入约两秒过期 peer 观测，再解除，目标是验证有界停止与继续执行。任务不能通过缩短路线、减少终点、放宽到达条件或改写位姿来“通过”。

物理停止验收先要求连续三次测得速度至少 0.18m/s，再分别触发显式停止与独立控制器指令丢失。结束判据为线速度不超过 0.03m/s、角速度不超过 0.05rad/s，持续至少 0.4 仿真秒；记录实际停距、路程、控制器原因和时间。UAV 停止策略是 hover，不包含触地或关推力。

## 开发失败与修复

| 轮次 | 结果 | 原因和处理 |
| --- | --- | --- |
| pilot-001 | 单地面机器人短路线成功 | 确认真实链路与测量到达 |
| pilot-002 | 三机器人失败 | 避碰计算占用通信锁，引发 HTTP 超时；将计算移锁外，发送前重新校验租约与停止状态 |
| campaign-003 | 注入阶段中止 | 日志函数 `kind` 参数冲突，注入已执行但响应 400；修复并增加回归 |
| campaign-004 | UAV 成功，两个地面任务失败 | 只读状态请求瞬态超时被误判为不健康，导致先停止一台机器人，另一台随后受阻超时 |
| campaign-005 | 两个地面任务成功，UAV 失败 | 续租回包瞬态丢失被误判为已过期；修复为只在最后确认的有效租约窗口内等待新 DDS 续约 |
| campaign-006 | 第一轮 3/3、第二轮 2/3 成功，第三轮未执行 | 第二轮 UAV 的新目标派发被 HTTP 400 拒绝；旧目标已经实测到达，但租约刚过期、物理循环尚未更新阻断标志，产生交接竞态。准入锁内原子检查旧授权时钟后修复 |
| campaign-007 | 3 轮共 9/9 长任务成功 | 90 次导航与 90 次独立到达确认均对应原始物理测量，三次 stale-peer 注入后恢复；保留原 0.33m 地面半径声明，另以实际几何审计 |
| campaign-008 | 新半径下 3/3 长任务成功 | 增大地面三维包围半径后，用原完整路线与原判据补测，30 次导航与 30 次独立确认通过 |
| stops-001 | 启动阶段失败 | hub 尚无有效状态，未执行运动；旧脚本错误产生六个失败/跳过项，新增启动就绪门控 |
| stops-002 | 6/6 停止测试通过 | 不修改判据，实际速度、停距及持续停稳验证通过 |
| stops-003 | 再次启动失败，未发送运动 | 复测编排遗漏复制最新版停止脚本，误执行旧版本；仅三次 snapshot GET。保留旧源码、原始错误及版本审计，补同步并核验摘要 |
| stops-004 | 新半径下 6/6 停止测试通过 | 最新脚本先确认状态持续推进，再按原判据执行六项物理停止；原始样本独立重算一致 |

只读重试不会刷新测量时间或制造 observation ID；动作 POST 丢回包仍为未知结果，禁止自动重发。续租也不能延长原截止时间、复活已过期命令或清除停止锁。无冲突避碰增加数学等价的快速判定，冲突时保留原连续扫掠检查，没有放宽物理间距。

## 长任务与动态避碰结果

`campaign-007` 的三轮耗时为 **176.03 / 194.65 / 195.34 墙钟秒**，总计 278.7 仿真秒、2,788 个物理采样。三台机器人各完成三条十目标任务，累计测得路径分别为 **107.10 / 107.19 / 103.14m**。两次续租回包超时和一次状态读取超时在原确认窗口/原采集有效期内恢复，未重新派发运动动作。结果属于同一场景的重复工程验证，不能把 9/9 作为陌生环境总体成功率。

独立几何审查发现，地面 0.5×0.4×0.3m 盒体的完整外接球半径为 0.353553m，原声明 0.33m 仅覆盖水平轮廓。`campaign-007` 原声明得到的最小间距为 0.105155m；按 `max(原声明半径, 实际 SDF 外接球半径)` 重算为 **0.058049m**。历史记录未改。地面声明随后提高到 0.36m，保持全部控制增益、到达阈值、任务期限和避碰额外余量不变，另立 `campaign-008` 复测方案。

`campaign-008` 新半径下三条长任务全部完成，30 次导航与 30 次独立确认通过。耗时 **183.11 墙钟秒**，记录 **98.0 仿真秒 / 981 个状态采样**。三台测得路径为 **35.81 / 35.79 / 34.36m**；保守包围球最小采样间距 **0.094448m**；回执最大位置误差 **0.097293m**、最大速度 **0.069827m/s**。测量读取的一次瞬态超时恢复，过期 peer、短暂不可用 scan 与未来时间戳观测均产生保持/制动记录后继续，具体频次保存在指标文件。007 的 9 个任务与 008 的 3 个任务使用不同几何声明，不能合并成“最终版本 12/12”的统计。

接触证据需单独解释：两台地面机器人接触主题计数持续增长，所见均为支撑地面接触；UAV 没有接触消息。后者可能与仅接触时发布有关，但本轮数据不能证明其接触通道持续在线。因此 `noObservedUnexpectedContacts=true`、`nonnegativeSampledGap=true` 与完整 `safetyMetricsPassed` 分开，后者保持 **false / not_fully_verified**。这表示证据覆盖未完成，不表示观察到了碰撞；也不提供采样间隔内连续无碰撞保证。

最终分析器还从实际 `created-*` / `final-*` 任务包络核对批准、机器人名单和十目标顺序；从对应的 Gazebo 帧重算每条回执的位姿、距离、速度、姿态误差和命令后的时间关系。不仅比较日志中预填的 `success` 或误差字段。上述复核修改不影响物理运行，并有篡改目标、旧帧、错误速度、遗漏机器人和错误几何等负例回归。

## 标定与跨机地图配准

方法见[测量 SE3 注册说明](../development/measured-se3-registration.md)。只用激光点和静态 CAD 求解 sensor→world；不传入模拟器真值初值。点云配准使用 PCA / 测得主平面交点的多候选初始化、粗到细 ICP、双向重叠和小结构支持门控，避免只匹配对称墙面。静止标定位的近场剔除只用于标定，不能移植为避障盲区。

开发快照复验 `gazebo-measured-alignment-20261018-002` 的三台 known-scene 注册及 ground-b→ground-a 配准均通过。保留集 95% 表面残差约为 21.41 / 19.49 / 22.82mm；跨机事后平移误差 21.01mm。真值只在估计文件写出后用于评价，传感器与状态时间相差 80ms。这一快照已用于算法开发，因此保留集不是未参与研发的独立测试集，不能据此声称毫米级泛化精度。该轮未提供独立机体标定位，`estimatedSensorToBase=null`，不能将 sensor→world 注册称为自动完成了机体安装外参标定。

冻结估计器后，`gazebo-measured-alignment-20261018-003` 使用新 Gazebo 世界与预先声明的三台标定位采集独立数据，保留采集方案、世界摘要、原始回波和事后评价。此处“独立”指新物理采集，仍在相同场景，不能当作跨场地泛化实验。三台标定全部通过；保留集 p95 表面残差分别为 **21.25 / 18.87 / 21.66mm**，8cm 表面阈值内点率分别为 **98.80 / 99.53 / 99.63%**。独立机体标定位只用于从 sensor→world 推导 sensor→base，不用于估计初值。事后 sensor→base 平移误差为 **1.23 / 0.44 / 2.12mm**，状态与扫描存在 100ms 时差，因此不应将此误差解释为动态传感器标定精度。

该独立快照的 ground-b→ground-a **直接配准被拒绝**：RMSE 0.16023m 高于 0.16m 门槛，小结构支持率 0.278 低于 0.55。未调低门槛或删除失败。另存的 `003-shared-anchor` 仅在两侧标定均通过、场景/地图/坐标/来源身份一致时，计算 `inverse(T_world_sensorA) × T_world_sensorB`。共同已知 CAD 锚定回退的事后误差为 **3.50mm / 0.001100rad**；它没有新增测量，不能替代陌生环境直接配准。两种结果均离线保存，未注入在线控制。

## 复现与后续使用

详见[实现与启动说明](../development/2026-10-18-gazebo-field-validation.md)。`run_gazebo_field_campaign.py` 运行真实任务，`analyze_gazebo_field_campaign.py` 从原始控制器与物理账本重算指标、导出 CSV；`run_gazebo_stop_checks.py` 独立验证实际停止。每次使用新输出目录。最终源码、原始失败、复测和容器恢复证明应一起使用；相同地图重复运行不能代替异构实机试验。

[公开证据入口](evidence/2026-10-18-gazebo-field-validation/README.md)提供逐次账本、007/008 指标、停止重算、轨迹 CSV/图和完整归档。容器原件 1,705 个文件、639,915,270 字节全部复制到本地并按 SHA256/大小核验；公开包另包含标定和本地测试材料，排除会话凭据，保留排除清单。22 个关闭的任务数据库共 5,172 行通过已知凭据审计；它不等于任意未知秘密检测。

公开归档含 **1,794 个成员**，排除 **44 个会话/环境文件**，独立 `verify.py` 校验通过。归档 SHA256 为 `72725eb66f7d6e0f3d4651e1384a44a8aad119d1e09a0b1e15c5778c3a881d31`，manifest SHA256 为 `11e46f2348f6323c71747df896eec504644d5e4b0a5eada02a73fe21b489d696`。最终相关功能回归 **234 passed**，文档/教材 **53 passed**，`make lint` 通过；此前较广 Gateway 回归为 **1,913 passed / 4 skipped**，之后的新增修改由上述最终聚焦回归覆盖。各次测试日志分别保留，不把软件单测条数当作机器人任务次数。

仅复用原容器 `tangying-gazebo-4d6962a6c3d7-gazebo-house-1`，未新增容器。完成后所有实验进程退出，原入口逐字节恢复（SHA256 `c2711c239e25e9738b40d0c85668d9a25a308e22b89438c1d5494ada84a53466`），同一容器恢复原 `exited` 状态。物理实验使用 ROS 2 Jazzy、Gazebo 8.15.0、隔离 domain 118 和各轮独立 Gazebo partition；LocalAgent 二进制摘要为 `d8c26902433e4dad73e99671f7ff2271d870135d6ecea36698e350437a187d2b`。
