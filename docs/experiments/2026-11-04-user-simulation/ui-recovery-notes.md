# 工作台状态与动作对账入口修复

## 现场触发的问题

本轮 Gazebo 用户界面试验发现两处状态与建议不一致：

1. 工作台已有机器人画面与地图，但顶部始终显示“已连接；正在读取可用服务与状态”。原因是文案只检查 `adapter` 是否存在，未检查真实连接或目录请求状态；服务目录实际只在标定、建图页面按需加载。
2. 任务进入 `RECOVERABLE_FAILURE` 后，创建成功时写入的“再批准物理动作”仍保留。该反馈是一次性文本，任务状态刷新只修改状态徽标，没有同步更新操作建议。

此外，后端已有 `POST /v1/tasks/{id}/reconcile`，工作台没有提交未知动作结果核查结论的入口。用户只能看到恢复说明，无法通过界面完成对账。

## 修改后的行为

- 顶部说明分别依据运行时连接、服务目录读取结果和已收到的机器人状态显示；连接不代表物理执行已获准。
- 创建成功的提示绑定具体 `taskId`，持续依据最新任务状态生成。`READY`、已批准但等待启动、执行中、需要恢复、失败、成功有不同说明；切换任务清除旧提示。
- 生成任务期间显示等待模型响应的说明与 `aria-busy`，不虚构百分比、不修改此前选中任务的状态、不重复提交。
- 恢复卡片按 `uncertainStepIds` 分别显示任务、步骤身份。每步核查结论不预选，核查者与环境、依据均必填。轮询不清空已填写内容。
- 允许选择 `HAPPENED`（已确认产生效果）、`NEVER_ACTED`（已确认从未派发）、`ABANDONED`（放弃此路径，世界可能已变化）。仅选择结论并不触发动作。
- 请求仅发送 `stepId`、`outcome`、`note`；核查者及环境写入 `note`，认证 `actor` 仍由后端产生。仿真核查应明确注明，例如“Codex，Gazebo 仿真核查，非实机现场人工核查”，不能冒充实机现场人工检查。
- 提交后重新读取任务、恢复条件及准备检查；不自动继续、重试或批准。接口失败保留依据，响应身份不匹配或网络中断时不盲目重发未知写入。
- 恢复接口返回的 `reconciliations` 作为独立记录展示结论、原始状态、认证来源、时间和依据。对账不改写原始 `STARTED` 等执行事实；已取消任务仍可查看这些记录。

### 页面验收后的增量修复

真实页面验收继续发现两个问题：下拉框不能稳定通过精确标签名称定位；旧的 experience 恢复建议仍可能要求“状态恢复后重新批准或更新任务”。因此增加如下修复：

- 每步的三个输入控件使用不同 `id`，独立 `label[for]` 关联，避免把下拉选项文字混入字段名称。
- `requiresReconciliation` 时优先显示逐步核查及对账说明，不显示通用的重新批准建议。已记录 `ABANDONED` 时明确说明不能沿旧路径继续，应核对现场并结束旧任务后再评估新任务。
- 增量定向测试 177 项通过。独立 Chromium 中实际运行 Playwright 的 `getByLabel(..., {exact: true})` 和 `getByRole(..., {name, exact: true})`，两步共六个控件全部匹配；按标签完成选择和填写、确认按钮由禁止变为可提交，但没有提交表单。
- 浏览器测试使用静态源码夹具、阻断所有网络请求，没有连接机器人服务，也没有操作本轮真实仿真页面。结果为 `artifacts/acceptance/user-sim-20261104-001/ui-accessibility-result.json`，可重放检查脚本为同目录 `tools/check_reconciliation_accessibility.js`。

默认 Playwright 插件浏览器曾因本机 Chrome/Edge 框架启动问题失败；实际断言通过已安装的独立 Chromium 测试浏览器完成，不把启动失败计为页面通过证据。增量修复完成后由主试验重新构建 Local Agent 载入，运行中的试验不再被此分任务的构建或测试干扰。

### 成功任务的证据类型说明

第三轮任务成功后，工作台的 capability 步骤仍直接显示 experience 的“等待环境证据”占位，而执行回放已正确识别能力契约复验。最后一组改动仅涉及前端展示：

- 工作台步骤和回放说明共用 `task_trace.capabilityStepEvidenceText`，根据精确步骤编号及版本匹配事件链。
- 只有完整、顺序正确、具有非空证据的调用/回执/`CAPABILITY_VERIFIED` 链才显示能力已复验；保留既有 `robot.task` 子步骤复验契约规则。成功状态本身不能提供证据，后续失败也不能沿用已复验文案。
- `calibration.get` 等能力显示结构化状态复验；`robot.task` 父能力提示查看物理子步骤的观测，不生成不存在的父级图像或回看按钮。
- 原始 experience 文本保持不变，展示层另附 `evidenceExplanation`。晚到的能力事件会刷新步骤卡片，不必等待另一份 experience 快照。
