## 被测任务与环境

> 依次执行以下完整家庭任务：读取整机标定状态；重新按家庭巡检路线完成SLAM建图并启用新地图；读取导航定位状态；从客厅出发，巡检卧室和卫生间，最后回到客厅；再从客厅出发，去厨房拿杯子，放进收纳盘，然后回到客厅；最后读取并报告当前地图和导航定位状态。每个地点都确认抵达，抓取和放置分别验证。

Gazebo `home_furnished`、同源 XLeRobot、ROS 2、Nav2、RGB-D，robot ID `gazebo-home_furnished`。真实 GOAL 服务使用已有私有配置的 `deepseek-flash`。Task 执行冻结计划，Ops 分类，Recovery 进行目录内只读调查及独立复验；这些参与者不等于三个独立 LLM 调用。

链路：Console `8897` → Local Agent（task/ops/recovery）→ 只读故障代理 `50162` → Gazebo Runtime `50161`。首轮创建独立 Agent 数据目录，后续部署始终复用该数据库，保留所有失败任务、事件及用户营销改动。既有地图及标定是前置条件，不宣称无图冷启动。本轮未复位 Gazebo 世界；所有代码和运行变化分别记录。

首次失败的 seq25 是 `mapping.build` 的 `CAPABILITY_FAILED`，阶段 `status`、`mutatesWorld=true`、`outcomeUnknown=true`，错误为 `operation ended: failed (RGBD_NOT_READY,JOINT_FEEDBACK_STALE,SUCTION_FEEDBACK_STALE,IMU_NOT_READY)`。旧任务保持失败，未删除 journal 或伪造完成。

源码复现发现 `readiness_blockers()` 在等待样本锁前采样时钟：等待期间传感器回调刷新时间戳后，年龄可能为负，导致新鲜样本误判过期。改为取得同一锁后采样时钟；所有 500ms/1s 阈值及负年龄拒绝保持。离线确定性回归修复前失败、修复后与关联模块联合 69 项通过。本次失败没有保留瞬时负年龄，不能断言这是唯一现场根因。详见 [传感器时钟修复](../development/2026-10-10-gazebo-readiness-race.md)。

首次恢复暴露另一实际 bug：压缩历史使 Loop 自动加入 `context_read`，单工具确定性诊断器将其算作第二个业务工具，拒绝执行。seq35/37/39 均 `executed=false, verified=false`，不能计为自动恢复。修复仅排除 Loop 保留的内部回查工具；真正多工具、有参数及物理动作继续保持原边界。大历史→业务读取→归档→完成→独立复验正负分支均有竞态回归。

## 协议和回溯变化

- [Agent 交互协议](../development/2026-10-10-agent-interaction-protocol.md)：版本化消息、固定发布身份及主题权限，task/revision/robot/step/command 和 source/anomaly/plan 的完整因果绑定。缺失身份保持未知，旧或混合来源不释放重试等待；冲突 ID 不能成为执行授权。
- [云边协议](../development/2026-10-10-cloud-edge-protocol.md)：精确完成回执与持久协调收尾。跨版本丢响应、协调端崩溃只重传完成及协调收尾；新 lease/world fence 不回退，未知物理动作不重放。
- 云端每次启动生成独立 leadership incarnation，配置 ID 仅作前缀，避免两个进程以同 owner 续同一 grant；生产模式要求共享 Redis。两实例/重启/fence 回归使用生产 MemoryManager 和 Coordinator 的真实接线，未启动 Redis/MySQL 部署；旧 coordinator 不理解 v2 pending，仍须部署层排除旧 leader，不能以租约修复代替 schema 门禁。
- 上下文归档和实际模型请求增加精确 JSON 字符串，避免事件库/HTTP 通用 map 重编码破坏源哈希。结构化字段保留兼容显示，但原始字符串是审计及回读来源；真实 SQLite 关闭重开→HTTP 测试覆盖排序和大整数舍入。
- GOAL 每轮实际模型输入写入规划轨迹，在成功创建的 Task 与不可变 Revision 中留存，错误轮次也保留。规划期尚无 task/revision，作用域只绑定真实 catalog robot，不补造执行身份；完全规划失败的非执行草案目前由调用者接收错误，并不自动创建失败任务。之后的恢复上下文只携带旧输入的 round/scope/SHA 索引，完整原文仍在版本记录；冻结调用、参数及规划工具事实保持，避免把旧模型上下文再次嵌入下一轮输入。
- 验收脚本保存故障日志、不可变 task revisions 和运行配置；独立重验脚本从原始 manifest 核对全部文件、实际任务/观测、物理结果与协议链，不覆写原报告。
- [监督成本与调查去重](../development/2026-10-10-recovery-observation-cost.md)：同库 6 个任务的计划/意图约 2.1MB，事件 JSON 约 492.7MB，其中反复自动诊断回执约 464MB。原观察器每 5 秒全量解码历史仅为读取 ID/状态；新 SummaryReader 只查标量索引，完整 Get/List/上下文来源不变。自动调查在取完整事实前持久预约，重复来源、时间抖动或重启不制造新诊断；新业务来源、告警关闭后重开或明确目录/策略版本变化可形成新调查。人工入口保留，原告警和物理未知继续显示。一次预约后崩溃或调查失败不自动假设成功，仍须新来源或人工介入。
