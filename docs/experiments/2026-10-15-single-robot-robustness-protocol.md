# 单机器人长程鲁棒性增量实验协议（2026-10-15）

类型：执行前登记的工程实验协议。基线为 `0d36aa127ad2132857775241478ac7689478e783`，承接[分层目标实验](2026-10-15-hierarchical-edge-objectives.md)。本文件登记问题和判据，不代表任务已经运行或通过；实际数据、失败及偏离另记报告。

## 问题与实验单位

检查单机器人在多代计划、多任务连续执行和故障之后，是否保持权限、已确认效果、预算、完成核验与回溯一致。一个软件任务、一个连续运行 episode、一次宿主重建和一次真实物理任务分别计数。脚本决策器、合同设备、HTTP 模型协议 fixture、实际模型、Gazebo 和实体机器人不能合并为同一成功率分母。

## 预定矩阵

| 条件 | 注入或变化 | 预定判据 |
| --- | --- | --- |
| 连续单机器人长路线 | 同一持久设备状态执行多个至少数十步目标，使用分段子计划 | 每站效果可对账；任务之间状态连续；不以每步重置设备算稳定运行 |
| 可恢复故障 | 明确未准入、只读错误、完成谓词暂未满足 | 有界重规划；保留已完成前缀；完成必须有最终观测 |
| 崩溃与重启边界 | 完成后重放、无在途动作检查点重建、存在待定动作检查点 | 完成后不重复写；安全检查点可续；待定写不能自动重放 |
| 云边消息故障 | 丢失进度、丢失最终结果返回、恢复后再交付 | 本地原始回执保留；只补传已确认结果；云端证据不足不能成功 |
| 授权与限额 | 预算不足、过期、撤销、目录变化、模型重复动作 | 拒绝越界；重启不能恢复额度；危险写结果未知时停止对账 |
| 实际 Gazebo | 先检查运行环境、活动任务、地图和模型，再选择可运行任务 | 记录原始自然语言、模型和软件身份、地图身份、逐步回执、图像/轨迹、真实故障与终态；环境不具备则记录未执行 |

单目标合同当前最多 8 代计划、128 个步骤，每代最多 16 个调用。更长运行使用多个明确独立的目标连续执行；不能通过绕过合同上限制造长任务。可恢复不等于无限重试；未知物理效果应停止，安全停止与业务完成分别统计。

## 数据与修复规则

保存命令、UTC 时间、操作系统/工具版本、基线提交、本轮源码摘要、完整测试 JSONL、每任务步骤/读/写/代数/耗时、故障类型与实际注入次数、重建前后动作计数。软件测试耗时不解释为机器人行驶时间或模型推理延迟。保留首个失败和修复后重跑，独立文件拒绝覆盖；只统计实际记录到的数据，缺失量使用 null 并说明原因。

先运行扩展矩阵，发现缺陷后最小修复并添加回归，再运行生产 Go 包清单、相关 race 与文档检查。工程测试没有随机抽样、独立机器人样本或策略对照，不能据此估计实机成功率、MTBF 或统计显著性。实际仿真不可用时，报告环境阻断，不替换为假 Gazebo 成功。
