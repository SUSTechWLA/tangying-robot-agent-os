# V1 架构评估与实机接入检查（2026-09-05）

## 结论

项目具备机器人 AgentOS 的有效分层和限定任务仿真闭环，可以继续发展为实机系统。
当前适合定位为 **仿真与集成候选版**；不能把它标为购买 XLeRobot 后即可上线的实机生产版。
本轮完成了运行时、安全、驱动输入与验收工具的缺陷修复，没有连接真实机器人，也没有部署生产服务。

它属于运行在操作系统之上的机器人任务平台。Go 负责控制平面和执行编排，Python 负责仿真、硬件适配与模型接口；它不提供硬实时控制内核。

## 本轮修复

- **重复与崩溃执行**：RobotRuntime 以前仅在执行后记录命令，并发相同命令可再次调用后端；现在串行准入，执行前持久记录。未完成记录在重启后返回 `EXECUTION_OUTCOME_UNKNOWN` 并锁存停止，不自动重放，也不会被终态历史淘汰。
- **日志故障与时间边界**：日志写入失败禁止发送动作；持久写入消耗完 deadline/lease 时，在进入后端前再次检查。文件替换后同步目录。执行结束释放命令占用，保留必要的安全锁存。
- **取消与急停**：取消结果先于后端停止通知发布，取消登记和终态选择同步；取消/复位期间阻止新动作；停车失败持久锁存；复位拒绝或并发急停不会被忽略；日志故障不能跳过停止调用。急停工具和急停 RPC 一样抢占运行中的动作。
- **真实动作校验**：整块校验后才发送，拒绝空动作、假关节、非有限值、布尔值、数字字符串以及无效限制配置。核对上游回执，异常时中断后续发送。停止时先设置软件锁存，并汇总底盘和两条总线的停车错误。
- **只读观测**：读取状态不再自动创建/连接机器人，因为上游 `connect()` 可能使能扭矩。尚未连接或处于急停状态时返回可观察的异常；连接与重新使能需独立的现场调试流程。
- **部署门禁**：真正检查 provider 可调用性，配置错误返回结构化失败，`--json` 始终输出单个 JSON 文档。明确它仅检查离线前置条件，不是实机授权。
- **验证覆盖**：`make test-web` 覆盖全部 Web 测试，默认 Python 测试包含实机驱动；lint 限定本仓库源码；RoboCasa 探测、子进程和启动脚本固定当前 checkout 的项目模块，避免 Conda 的其他 editable worktree 混入。
- **恢复验收竞态**：检查点测试曾在重启后约 5 ms 取到序号已前进的旧缓存，直到约 11 s 才出现真正的新鲜观测。现在等待条件同时要求正确位置、递增序号、`FRESH` 和重启之后的实体观测时间；没有降低超时或新鲜度要求。
- **并发启停**：生命周期锁等待曾误用服务启动超时，前一个操作仍在合法停机阶段时，排队的 stop/restart 就会错误超时。新增独立的 `SIM_STACK_LOCK_TIMEOUT`，默认根据完整启动/停机/回滚阶段推导；保持原启动超时、进程身份校验和精确 PID 停止逻辑。
- **演示进程回收**：`go run` 包装进程退出后曾遗留 Local Agent 子进程。演示现在编译临时二进制并直接持有其 PID；新增实际启动演示、退出后核对进程列表的回归验证。

相关回归均先观察失败再修复。未改写本轮开始前已有的 Fleet/Web 改动，未改动签名证据、信任锚或上游 XLeRobot 仓库。

## 实机上线仍存在的阻塞

1. **固定驱动与硬件版本匹配**：当前适配 `xlerobot_2wheels`，且禁止移动底盘。购买前须确认底盘版本、双臂关节、串口板、舵机、相机与计算设备；不同底盘不能视为等价替换。上游提供多种控制与策略路径，参考 [官方软件文档](https://xlerobot.readthedocs.io/en/latest/software/index.html)。
2. **上游兼容缺陷**：仓库固定提交的 `send_action` 用带 `.pos` 的动作键索引无后缀的当前关节位置；已通过提取真实方法、使用只读假总线复现 `KeyError`。配置流程还重复配置 bus2、遗漏 bus1。必须采用经过测试并重新固定的修复版本；本轮没有擅改外部仓库。[固定版本源码](https://github.com/Vector-Wangel/XLeRobot/blob/3d14695e40c9c68229c0aacffca6053c75cd3eb6/software/src/robots/xlerobot_2wheels/xlerobot_2wheels.py)
3. **感知/策略/验证 provider**：需要真实相机的标定、实体识别与位姿、机器人状态、抓取/放置确认，以及对应硬件的动作模型。可导入的函数不代表这些功能已实现。必须验证超时、陈旧数据、低置信度和返回 schema。
4. **硬件安全与恢复**：实体急停、限位、低速空载、持物安全、断网停车和重复命令试验尚未进行。软件锁存可及时设置，但切断扭矩仍会等待在途串口操作；没有硬实时停止证明。停止后 `reset_stop` 不自动重新使能扭矩，需要显式现场流程。
5. **持久化与 HA**：`fleet/worldhub/hub.go` 的快照/delta 仍为内存状态；跨重启 source sequence、业务事务中的 leader fencing 原子检查，以及 MySQL/Redis 资源转移恢复仍需补齐。当前单主部署不能包装成多副本自动故障转移。
6. **生产验证**：至少按已有手册完成 30 次真实试验，再补充限定任务成功率、24/72 小时长稳、备份恢复和故障注入。测试结果需要与实际固件、模型、标定和地图版本绑定。

## 可执行的晋级顺序

1. 固定第一版范围：单主控制平面、限定桌面任务、明确支持对象和目标；先交付仿真候选版。
2. 锁定所购 XLeRobot BOM 与驱动提交，修复上游兼容问题，通过无硬件总线契约测试和 no-motion 预检。
3. 接入真实感知、验证和策略 provider；先运行只读观测与 shadow inference，核对坐标系、关节、模型和标定 revision。
4. 现场完成实体急停与单关节空载试验，再进行轻物抓放、断网/重复命令/持物恢复和 30 次记录。
5. 单机器人受监护试点通过后，再晋级底盘运动、双机器人协作和无人值守。按实际部署范围补齐持久化、长稳和恢复演练。
