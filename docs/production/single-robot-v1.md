# 单机器人 V1：用户流程与上线准备

本版先服务一个机器人、一个经过配置和验收的工作台：用户用自然语言描述搬运任务，确认理解后执行，看到动作结果，并在中断后按可信记录继续。机器人型号、工具和观测来源保留扩展接口；多机器人调度、自主移动和通用家务不属于这条首版交付流程。

本文对应 2026-09-08 的单机器人升级。RGB-D 软件仿真任务、故障恢复和浏览器历史回看已完成本轮验收，见文末记录。软件接口实现与仿真成功都不代表客户实机已获生产放行。

## 第一版具体做什么

参考工作台的识别目录只有红色杯子、蓝色瓶子，以及左侧收纳盒、右侧收纳盒、前方交付托盘。可以从下面的描述开始：

> 把红色杯子放进右侧收纳盒，然后把蓝色瓶子拿过来。

这里的“拿过来”对应参考工位的前方交付托盘，不是跟随说话人移动。两项任务依次执行；每项包含观察、目标确认、抓取规划、拿取、抓取验证、放置和放置验证。增加物品、容器或动作，需要先扩展并验收感知与工具能力。

| 用户看到的能力 | 实际边界 |
| --- | --- |
| 自然语言生成任务 | 当前支持的语言会落到明确物品、目标和工具；不支持的内容不能靠界面润色变成已实现能力 |
| RGB-D 环境感知 | 环境物品与位置来自彩色图像和对齐深度；机器人自己的关节、末端和夹爪状态仍可作为本体反馈 |
| 三维结果 | 有来源、时间、标定版本和米制世界坐标的实体与有界点集；不是任意房间的完整稠密模型 |
| 红杯、蓝瓶识别 | 随附检测器使用颜色、几何和已配置的工位尺寸；不是通用视觉模型，也不是实机识别准确率证明 |
| 安全暂停与继续 | 在当前工具完成并保存结果后暂停；继续前核对历史、重新观察，无法确认的物理结果会阻止继续 |
| 历史与问题回溯 | 查看本地保存的任务、步骤、命令、观测证据和版本；打开历史不会重新执行动作 |

## 用户日常操作

1. **确认机器人和现场。** 使用交付方配置的启动入口，检查设备连接、工位、夹爪负载和实体急停。正常使用不需要选择厂商 SDK 或填写关节命令。
2. **看清观测来源。** 工作台会显示感知来源及观测是否更新。RGB-D 路线可切换“彩色画面”“深度图”和“观测点云”；“仿真调试画面（非机器人感知）”或“来源未声明”不能作为相机感知验收依据。画面只是现场核对入口，任务是否成功还要看动作后观测和验证记录。
3. **描述任务并生成。** 点击“生成任务”，检查“机器人理解成了什么”和目标顺序。看不到物品、目标有歧义或连接异常时，先修正场景或描述。
4. **确认后执行。** 理解正确且现场允许时，点击“批准物理动作”。批准不会增加设备尚未实现的能力，也不会绕过 Runtime 的安全检查。
5. **观察动作与结果。** 动作卡的“执行完成”表示工具返回成功，“已保存执行后观测”提供历史回看。是否拿稳或放好，还要看对应验证步骤与任务结果；未保存证据的旧记录不会被补成已验证。
6. **需要中断时安全暂停。** 点击“安全暂停”后，先等待状态确认。它不会承诺立即制动；现场有危险应使用实体急停。“取消任务”也不能替代实体急停。
7. **需要恢复时核对原因。** 只有服务允许时，“继续任务”才可用。若提示动作结果需要核对，交由维护人员处理；不要反复重试、复制任务或删除执行记录来寻求继续。
8. **从任务记录回看。** 选择已保存的任务，回到工作台查看步骤与恢复说明；在“回看当时的观测”或动作卡的回看按钮中，核对同次历史采集的彩色图与深度图。历史采集时间会明确显示，已清理的内容只保留追溯信息，不用当前画面代替。开发模式可筛选事件，并用命令、步骤、观测编号和任务版本定位问题；复制排查摘要不会包含登录凭据或模型密钥。

浏览器刷新、打开历史和服务重新连接都不会自动批准任务。Local Agent 重启时不会自行恢复中断的物理执行，必须再次读取恢复状态并显式继续。

## RGB-D 与旧仿真怎样区分

旧仿真直接从模拟场景状态生成实体，适合检查任务编排、工具调用和界面。新 RGB-D 路线从头部相机图像、深度、内参和相机到世界坐标的变换生成标准重建；物体不可见、深度无效或采集过期时，不能读取隐藏物体坐标来补齐结果。

主画面只显示机器人相机提供的彩色图、深度图或实测点云。深度图暖色近、冷色远，黑色表示未知；点云空白也表示未测到，系统不会用完整模拟场景补齐。过期或缺失数据明确显示不可用。开发模式的语义诊断单独标注用途。

RGB-D 点云逐点绑定同一对齐像素的 RGB 原色，参考桌面最多显示 4096 个测量点，并给检测物体保留采样预算。工作区取景和点大小经过优化，杯、瓶不再因背景占据大部分采样而难以辨认。无色来源和旧记录明确单色显示；颜色不能代替深度测量或物体识别置信度。

因此，下列证据不能相互代替：

- 任务状态为 `SUCCEEDED`：说明该执行流程达到了其定义的成功条件。
- RGB-D 观测编号与动作后验证：说明此次任务使用了可追溯的相机感知输入。
- 仿真物理结果：说明模拟工位中的物体发生了相应变化。
- 实机现场验收：说明指定机器人、控制器、工位和运行条件下的物理行为符合交付要求。

参考仿真仍使用理想抓取附着机制，以及仿真底盘/逆运动学调整。即使环境识别全部来自 RGB-D，这套控制器也不能直接迁移至实机；仿真抓取成功不能证明真实夹爪动力学、接触力或掉落风险已验证。

## 购买实机后谁负责什么

用户需要提供到货设备型号、硬件版本、工作台尺寸、允许处理的物品和现场运行条件。交付或集成团队将这些要求变成可验证配置，再交给普通操作员使用。详细接入流程见 [Sim2Real 上手](../sim2real/README.md)。

| 项目 | 上线前需要交付的内容 |
| --- | --- |
| 相机与数据输入 | 真实相机驱动；彩色/深度对齐；真实采集时间；正确深度单位；相机掉线、无深度及过期数据的拒绝行为 |
| 标定 | 相机内参、光学坐标到世界坐标的变换、手眼/末端标定；配置绑定标定版本，设备或工位改变后重新验证 |
| 识别与验证 | 适用现场物品的检测器；遮挡、光照和同色物体测试；真实抓取、放置和持物状态的判断，不能固定返回成功 |
| 机器人控制 | 型号适配器、关节与末端配置、动作范围、控制器或策略；实际反馈、超时、停止和错误处理 |
| 安全与使能 | 独立实体急停、软硬限位、现场支撑与防掉落措施；明确谁可以使能、复位及解除故障 |
| 运行与维护 | 受限网络、设备证书、日志和执行记录保留、备份恢复、版本回退、值班与故障处理流程 |
| 现场验收 | 指定任务的重复运行、各种摆放和遮挡、相机/网络/进程故障、持物中断及恢复；记录真实影响而不只统计 API 成功 |

ROS 2 可作为真实输入与驱动的连接方式，接入规范见 [ROS 2 RGB-D 指南](../development/ros2-rgbd.md)。安装 ROS、能读到 topic 或能发现 action server，都不等于机器人已具备安全搬运能力。

旧 XLeRobot 适配器不会因安装感知模块就自动成为严格 profile 适配器。新型号按 [异构机器人开发指南](../development/robot-adapters.md)接入，必须独立提供真实驱动、来源声明和工具实现。默认不使能运动；纯观察适配器也可以先接入验证。

## 从试运行到首版生产

先限定一个固定工位、指定物品与容器、受监督操作及经过验证的控制范围。第一阶段保持底盘禁用；新增自主移动、场景建图或新物体之前，分别验收对应定位、感知、规划与控制能力。

完成现场验收后，为实际部署的构建、机器人 profile、相机标定、控制器/策略和任务范围形成一套关联记录。传感器、硬件、标定或模型变化都可能使原验收失效。UI 的用户模式只是降低操作复杂度，不能替代后端授权、实体急停或交付签字。
