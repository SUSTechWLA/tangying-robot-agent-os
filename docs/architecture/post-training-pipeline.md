# 后训练流水线：不用 TrainAgent，用什么

上一轮结论是**不做 TrainAgent**（[评估](train-agent-assessment.md)）。这一份回答替代方案：
**用一条流水线**，以及它每一步的判据。

```bash
bin/training-export -db agent.db -out ./dataset
```

---

## 一、不用 Agent，用什么

| 需要的能力 | 用什么 | 为什么不是 Agent |
| --- | --- | --- |
| 读账本、统计、导出 | **确定性 CLI**（`training-export`） | 没有判断要做，只有读取与计数 |
| 判断数据够不够 | **量化报告 + 退出码** | 判据是数字，不是意见 |
| 判断 checkpoint 好不好 | **`train.Compare` / `Gate`** | 必须独立于训练方，见上一份文档 |
| 判断计划对不对 | **`orchestration/eval` + `make nl-eval`** | 同一套用例，同一把尺子 |
| 诊断失败运行、提议配置 | **LLM（可以是 Agent）** | 这里确实需要判断，且判断不影响判据 |

**分界线**：会**移动判据**的一律不许是 Agent。读数据、算指标、判卷——都是确定的，
所以都写成代码。

---

## 二、数据怎么量化

`training-export` 的核心不是导出，是**量化**。它先回答"有多少"，再决定"导不导"。

### 唯一规则：闭环确认过的才算正样本

```
改动世界的步骤 + 动作后有新鲜观测  →  verified
任务成功但物理步骤没有观测          →  unknown-outcome
```

**"步骤状态是 COMPLETED"不算证据。** 这正是 `core/closedloop` 的立场：
工具对自己成功的自述不是证明。**训练数据如果按"步骤报成功"来建，
教给模型的就是执行层拒绝相信的那个说法。**

三个桶的划分是刻意的：

| verdict | 进哪个集合 | 为什么 |
| --- | --- | --- |
| `verified` | SFT 正样本 | 唯一可信的正向信号 |
| `failed` | 负样本 | 可用于偏好对与挖评测用例 |
| `refused` | 拒绝样本 | 见下，**账本里不可能有** |
| `unknown-outcome` | **两半都不进** | 见下 |
| `unfinished` | 排除 | 还不是一个事实 |

### 为什么 `unknown-outcome` 两半都不进

当成成功 → 教模型去做**没人核对过的物理动作**。
当成失败 → 教它**回避那个效果没被确认的动作**，而"不再出现未确认效果"最省事的办法
是**偏好那些回报快的动作**——这是 reward hacking 的方向，不是安全性的提升。

所以它被排除，且**计数并写进 manifest**，因为它涨起来意味着证据门在响，这是另一个问题。

### 为什么拒绝样本**不可能**来自账本

**被拒绝的请求不会变成任务。** 服务在创建时就拒了，什么都不存。
所以账本里只有"系统已经答应要做"的请求——**恰好是最错的样本**。

一个只从账本建的训练集，教出来的是「**每个请求都有答案**」。
而"知道什么时候该说不"是蒸馏里**最先丢、最不能丢**的能力。

所以拒绝样本是**采**出来的（`HarvestRefusals`：拿解析器跑一遍语料），不是读出来的。
语料默认包含 `orchestration/eval` 里那 6 条必须被拒的用例——**安全样本不会因为
有人忘了传文件就消失**。

> **已知缺口（写在代码注释里，不藏着）**：今天没有记录被拒绝的请求。
> 所以"今天的拒绝集有多大"取决于**有人写了多少条**，而不是系统见过多少条。
> 补法很小（把被拒请求追加进账本），而它是**当前性价比最高的数据采集**——
> 拒绝样本没有任何别的途径能补回来。

### 去重按请求，不按行

参考部署里 **64 条任务只是 15 个不同请求**。按行计数会让四句话看起来像一个数据集。
所以指纹（归一化后哈希）去重，且**同一个请求同时成功和失败时，成功的胜出**——
模型没法同时学两个。

## 三、在真实账本上的结果

```
记录 64 条，其中不同请求 15 个
按可信度：  verified 23 / unknown-outcome 29 / unfinished 12
按计划来源：deterministic 59 / llm 5
可用正样本（已确认 + 真编排）：0 条

切分：SFT 0 / 拒绝 6 / 负样本 0
被排除：verified-but-no-plan 4、unknown-outcome 3、unfinished 8
```

**"0 条正样本"不是流水线坏了，是它正确地说了实话**，原因是两条具体的：

1. **23 条 verified 全是导航任务，且计划是确定性生成的**（空 bundle）。
   它们有结果、**没有编排信号** → 进 `verified-but-no-plan`。
2. **5 条 LLM 计划的全部没成功**——grounding 坏了，见 CHANGELOG 最近几条。

**所以现在的正确动作不是训练，是修执行链。** 流水线把这句话直接打在报告里，
而不是打印一张好看的表格让人去开训练任务。

## 四、完整的后训练体系

```
账本 ──training-export──▶ 量化报告（够不够？）
                              │ 够
                              ▼
                    dataset/{sft,refusals,negative}.jsonl
                              │
                     ┌────────┴────────┐
                     ▼                 ▼
              SFT/蒸馏          偏好/RL（暂不可用）
                     │                 │
                     └────────┬────────┘
                              ▼
                    make nl-eval（判卷，同一把尺子）
                              │
                        train.Compare/Gate
                              │ 通过
                              ▼
                    影子编排 → 放行
```

### 覆盖编排层与工具层

两层都已经是 LLM 驱动的，两层都有记录，**同一份导出同时服务两者**：

| 层 | 输入 | 输出 | 记录在哪 |
| --- | --- | --- | --- |
| **编排层** | 自然语言请求 | 技能图（顺序 + 依赖） | `task_revisions.content_json` |
| **工具层** | 目标 + 当前观测 + 候选工具 | 选哪个工具 + 参数 | `actionloop.Round`（`Candidates`/`Tool`/`Reason`/`Arguments`/`Verdict`/`Class`） |

**工具层那条是白送的**：`actionloop.Round` 里已经有
`Candidates`（当时有哪些可选）、`Tool`（选了哪个）、`Reason`（为什么）、
`Verdict`/`Class`（结果与失败分类）——**这就是一条完整的工具选择训练记录**，
而且它天然带"候选集"信息，能让模型学会**在什么情况下不选**。

### 什么现在能做，什么不能

| 目标 | 现在 | 前置 |
| --- | --- | --- |
| 编排层评测体系 | ✅ 已建 | — |
| 数据量化与切分 | ✅ 已建 | — |
| 拒绝样本采集 | ✅ 已建（语料规模有限） | 记录被拒请求 |
| 编排层 SFT | ❌ 无正样本 | 修 grounding |
| 工具层 SFT | ❌ 无正样本 | 同上 |
| RL | ❌ | 修 grounding + 正样本 + 影子编排 |
| VLA 后训练 | ❌ | 数据采集通路（本仓库有 MuJoCo/RoboCasa 通路） |

## 五、下一步该做什么（按价值排序）

1. **修 grounding**（`Observe(streams=["entities"])` 无数据）。在那之前一切训练都是空转。
2. **记录被拒绝的请求**（追加进账本）。小而高价值，且**没有替代来源**。
3. **扩大请求语料**：同一意图的多种说法。当前 15 个不同请求里，
   导航类占 4 条且都成功——**它们就是第一批可用的正样本**，
   但需要更多说法才能训出泛化。
4. **跑 `make nl-eval` 三方对照**（确定性 / DeepSeek / 本地），先量差距。
5. **SFT 第一版**：只做格式与域内说法，先看能不能追平；**拒绝样本必须混入**。
6. **最后才是 RL**，且奖励只能从闭环证据取。

---

## 六、一句话

**判据不能由被判者提供。** 账本量化、拒绝采集、评测、门禁——这四件事都必须是确定的代码；
LLM 只做它真正擅长的：诊断、提议、写代码。
**先把这条装上，再谈训什么**——否则训出来的东西会因为"无法判断好坏"而永远不敢上线。
