# TrainAgent 可行性评估：哪些"一切皆 Agent"成立，哪些不成立

问题是：**是否该实现一个 TrainAgent，统一负责编排层模型、VLA、强化学习、深度学习等训练，
定义好 train / eval / backprop，用 LLM 自己设计训练目标与过程？**

分三段回答：**成立的部分**、**不成立的部分**、**已经落地的那一块**（`train/` 包）。

配套：[编排层的后训练](orchestration-post-training.md)、[多 Agent 运行时](multi-agent-runtime.md)、
[恢复 Agent](recovery-agent.md)。

---

## 一、先看"Agent"在这套系统里到底意味着什么

现有三个 Agent 的权限是被结构性约束的，不是靠自觉：

| Agent | 能做什么 | 约束方式 |
| --- | --- | --- |
| `task` | 执行、改世界、改任务状态 | 走闭环门禁、审批、租约、fencing |
| `ops` | 只读观测 | 反射测试钉住"没有执行端口" |
| `recovery` | 只读事实 + 出计划 | 同上；执行走另一条通道 |

共同点：**观察—决策—行动—复验，周期是秒级，判据是独立的世界。**
`core/closedloop` 的全部力量来自最后一条——**世界不在乎策略想要什么，杯子要么动了要么没动。**

训练**两条都不满足**。这不是实现细节，是形状不同。

---

## 二、成立的部分（真的可以做成 Agent）

| 能力 | 为什么成立 |
| --- | --- |
| **观察训练运行** | 读 metrics、日志、显存、数据版本——与 `ops` 同构，纯只读 |
| **诊断失败运行** | 从日志判断是 OOM、数据脏、还是学习率炸了——LLM 在这里确实强 |
| **提议配置** | 超参、数据配比、增广、课程——提议，不是执行 |
| **写训练代码 / 写评测用例** | 写代码是 LLM 最扎实的能力之一 |
| **管理实验台账** | 哪个 run 用了什么数据、什么代码版本、什么结果——纯粹是账本 |

**这些合起来就是一个有价值的 TrainAgent**：它把"训练"从一堆散落的脚本变成
**可观察、可追溯、可复用**的过程。这与本仓库对 `task` 做的事是同一件事。

---

## 三、不成立的部分（做了会出问题）

### ① 时间尺度对不上

恢复动作秒级完成，租约（lease）与 fencing token 因此有意义。
一个训练 run 是小时到天级。**本仓库为短时物理动作建的整套安全机制在这里没有对应物**——
硬套会得到一个看起来统一、实际没有任何保护作用的架子。

### ② 判据不独立——这是最根本的一条

机器人闭环成立，是因为**世界是判据，且世界不受策略影响**。

训练里判据是 metric，而 run 正是优化这个 metric。
**被测量者和测量者是同一个系统。** 这不是"需要缓解的风险"，而是**默认结局**：
reward hacking 不是会不会发生的问题，是它本来就是优化目标。

所以：

> **LLM 可以设计训练的过程，但绝不能定义"什么算更好"。**
> 后者是它唯一也能移动的东西。

这句话是整个评估的核心。成功的判据必须来自系统外部——在本仓库里，
就是**机器人真的把任务做完**。

### ③ 失败形态不同，且更隐蔽

一个坏的机器人动作是**有界的**：有审批、有门禁、有复验、最坏撞一下。
一个坏的上线模型是**静默的**：它只是开始给出稍差的计划，没有人报警，
而评测分数可能还涨了（因为评测集也被同一过程间接影响了）。

**"坏得安静"的东西需要和"坏得响亮"的东西不同的机制。**

### ④ "一切皆 Agent"在这里会变成为了统一而统一

本仓库对这件事已有判例：`eval`、`experience`、`escalation` 只保留了接口与扩展点，
**没有实现**——因为把没接线的机制留在那里冒充已实现，比删掉更糟。

把 TrainAgent 硬塞进现有 Agent 抽象，等于宣称它继承了那套安全属性，
而它**结构上继承不了**。

## 四、已经落地的那一块：`train/` —— 把"训练"和"判卷"分开

真正可做、且现在就做完了的，是把上面第 ② 条**写成结构而不是记成纪律**。

```go
// 比较两份评测报告，决定 checkpoint 能不能替换在役模型
decision := train.Compare(train.Report{
    Candidate: "candidate-7b-r3", Incumbent: "deepseek-flash",
    Eval:     candidateScore,   // 候选
    Baseline: incumbentScore,   // 在役，同一套用例
})
```

**三条规则，都是结构性的：**

1. **Pareto，不是加权分。** 可执行用例与拒绝用例**都不许变差，且至少一个变好**。
   没有汇率。加权分会让"多规划几条"去买"少拒绝几条"——
   而一个什么都规划、什么都不拒绝的模型不是"好模型的 90%"，
   **它是一个会把否定句当命令执行的模型**。

2. **考试不能改。** `Compare` 拒绝比较"用例集不同"的两份报告（数量不同、成员不同都拒）。
   一个模型不能靠**改了考卷**来通过考试——这是最容易想到、也最致命的作弊路径。

3. **没测过 ≠ 考砸了。** 运行未完成的 checkpoint 既不上线也不丢弃，记为 `run-incomplete`。
   当成 0 分会因为一次掉线丢掉一个好 checkpoint；当成及格会上线一个从没测过的模型。

首次上线（没有在役基线可比）走**另一个**判断：`Gate{MinExecutable, MinRefusals}`
——绝对门槛，两半各自设线，理由与上面相同。
**"没有基线"因此不会变成"什么都能上"。**

### 验证过的守卫

去掉任一守卫，测试立刻变红（已实测）：

| 去掉 | 红在哪 |
| --- | --- |
| 拒绝不回退 | `TestPlanningMoreCannotPayForRefusingLess` |
| 用例集一致 | `TestASmallerCaseSetIsRefused`、`TestASwappedCaseSetIsRefused` |

而且**门禁读的正是 `orchestration/eval` 已经产出的报告**——
判卷的和训练的用的是同一个刻度，不是两套。

## 五、如果要做完整 TrainAgent，建议的形状

**不要**做成"又一个 Agent"。做成**两层**：

```
TrainAgent（观察 / 诊断 / 提议 / 写代码 / 记账）
     │  提议一次训练
     ▼
训练作业（外部进程，小时~天级，有 GPU 资源与独占）
     │  产出 checkpoint
     ▼
train.Compare / train.Gate（判卷，外部判据，训练方不可触碰）
     │  通过
     ▼
影子编排（与在役并跑，只有在役被执行）→ 放行
```

**关键点**：TrainAgent **不在**判卷链上。它可以写用例、提议用例，
但**不能改这一轮比较所用的那份**——用例集的变更需要一个独立于本次训练的版本。

### 各模块的可行性分级

| 目标 | 可行性 | 说明 |
| --- | --- | --- |
| 编排层 SFT/蒸馏 | **高** | 数据已在库里，评测已就绪，收益确定（成本/延迟/格式） |
| 编排层 RL | **中** | 需要 grounding 修好才有结果奖励；过程奖励可刷 |
| VLA 后训练 | **中** | 需要真机/高质量仿真数据；本仓库有 MuJoCo 与 RoboCasa 通路 |
| "LLM 自己设计训练目标" | **低（且不建议）** | 见 §3②；可以设计**过程**，不能定义**更好** |
| 自动 backprop 编排 | **不适用** | backprop 是框架的事，不是 Agent 的事；把它 Agent 化是包装 |

---

## 六、结论

**可行，但"一切皆 Agent"这个提法要收窄一句**：

> 一切**有独立判据、短周期、可复验**的工作可以是 Agent。
> 训练没有独立判据，所以它**不能**是——**除非把判据切出去。**

所以顺序是：

1. **判据先切出去**（`train/` 已做）。
2. **TrainAgent 只做过程**：观察、诊断、提议、写代码、记账。
3. **评测集版本的变更独立于训练**——否则模型可以改考卷。
4. **结果判据来自机器人真的完成任务**——在那之前不要谈 RL。

**一句话**：能建，且值得建；但它的价值来自"把训练变成可追溯的过程"，
不来自"让 LLM 自己定目标"。**后者是这套架构唯一不能给它的东西。**
