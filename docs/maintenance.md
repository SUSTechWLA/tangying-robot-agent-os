# 文档分类与维护规则

[返回文档导航](README.md) · [全量目录](catalog.md)

文档按工作用途提供入口，原始报告按版本保留。四条路线是精选导航，全量目录是文件清单；它们都不替代指南、接口合同或实验原文。

## 新资料放在哪里

| 内容 | 位置 | 写清什么 |
| --- | --- | --- |
| 学习路线、课程与阅读衔接 | `docs/learning/`；正式教材在 `book/` | 先修、顺序、学习产物、书籍版次与系统增量 |
| 用户怎样完成操作 | `docs/guides/`；界面专门说明在 `docs/frontend/` | 前置条件、执行角色、操作入口、结果判断与失败处理 |
| 安装、运行、排障和发布 | `docs/install/`、`docs/operations/` | 目标机器、部署方式、版本、数据目录、恢复/回滚条件 |
| 协议、架构与接口参考 | `docs/architecture/`、`docs/production/` | 权威来源、身份、参数、兼容边界及源码/测试位置 |
| 开发指南和模块扩展 | `docs/development/` | 修改入口、依赖、验证方法和对应当前指南 |
| 带日期的实施、审查、修复 | `docs/development/YYYY-MM-DD-topic.md` | 基线、原问题、选择、最终实现、测试和剩余项 |
| 实验协议、工程验收、对照研究 | `docs/experiments/` | 假设/预登记、方法、全部尝试、独立判据、指标、限制与证据路径 |
| 论文问题和资料路线 | `docs/research/` | 问题→方法→实现→证据；哪些结论能/不能支持 |
| 软件发布记录 | `docs/releases/` 与根 `CHANGELOG.md` | 版本/提交、范围、验证和未完成项 |
| 原始设计档案 | `docs/superpowers/specs/` | 保留原决策时点；后续实现另写记录并建立链接 |
| 原图、日志、数据库、地图、大证据包 | `artifacts/` | 来源、唯一运行目录、manifest、摘要、取得方式；通常不入 Git |

当前 `production/` 同时存放接口手册和历史验收快照，分类目录分别标识；名称中的“production”不表示已经完成真实硬件认证。已有重定向小文件保留旧引用，新内容写在目标报告中。

## 读者如何判断适用性

先确认**当前检出/部署提交**，再看文档覆盖的角色、引擎、硬件、地图和时间。软件发布、书籍版号、源码快照和实验 episode 是不同身份。

- 操作指南可随实现更新；发现与源码冲突，应核对路由、schema、配置和测试后修正指南。
- 带日期记录保留当时结论。新增验证写补充记录，引用旧失败，不用新成功覆盖原始尝试。
- 设计方案描述选择或目标；出现接口名字、未来清单或架构图，不等于功能已上线。
- 书籍按固定版本出版。当前增量先登记到[学习路线](learning/README.md#书籍与系统增量如何一起读)，需要新版出版时再按书籍流程更新正文、合订本和版次。
- 论文引用先核对提交、统计单位、原始证据和分母。没有原图/日志时明确仅核对摘要；`null`、跳过和未测保留原义。

## 每次变更的最小更新

1. 更新直接相关的操作/接口说明；实现与测试变化引用到该说明。
2. 写一份带日期的变更记录；产生实验时另存实验协议、结果及原始证据，保留失败。
3. 在对应的学习、开发、运维或研究入口添加必要链接。总导航只保留高频入口，避免重新堆成逐文件长表。
4. 运行分类目录生成与现有文档检查：

```bash
python3 scripts/build_docs_catalog.py
python3 scripts/build_docs_catalog.py --check
.venv/bin/python -m pytest -q tests/docs tests/test_repository.py
go test ./tests/docs
git diff --check
```

生成器只更新 `docs/catalog.md`，不移动或改写源文件。它列出 `docs/` 的 Markdown 和附件；旧 ADR 内部引用可能指向当时路径，应按历史用途阅读，不能让全量目录自动替它宣称可运行。

新增目录时显式加入生成器的分类；新增文件时再生成即可。目录中的“类型”按路径和少量明确规则保守标注，不代替内容审校。对新增导航的标题锚点、样例命令和关键能力描述另做人工/针对性核对；现有路径检查通过不意味着远程网页或所有锚点都已检查。

## 引用与归档

稳定链接是资料能长期使用的基础。优先新增导航而不是移动实验文件；必须迁移时保留旧地址指针，并同时检查书籍、指南、实验摘要和外部引用。

实验报告中的证据包应注明本地/远程位置、可获取性、大小和 SHA-256。不要把“本机生成了包”写成“已公开数据集”。接口凭据、私钥和会话令牌不进入文档或公开证据包。宣传材料使用可追溯出处，其数字不能反向成为研究或交付依据。

产物管理按 [清理与保留规则](operations/artifact-retention.md)执行。书籍新版先保存旧版恢复清单，再更新版次、源码快照、分章和合订本；出版器拒绝用不同来源覆盖已有输出目录。
