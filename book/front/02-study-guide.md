# 学习导读：知识地图与阅读方法

## 基础准备

本书适合已接触编程、操作系统与网络的读者。首次跨入另一行业时，不必先学习所有算法，先补齐下表中能影响系统判断的概念。

| 读者背景 | 建议补齐 | 能够回答的问题 |
| --- | --- | --- |
| 软件/Agent | 坐标、传感器时间、闭环控制、停止/保持 | 数值合法为何不等于物理可行？ |
| 机器人 | 事务、消息重复、版本、并发与故障域 | 丢响应为何不能自动重做动作？ |
| 科研 | 软件契约、设备边界、统计单位、留出评测 | 哪个假设决定实验可以外推？ |
| 新开发者 | Go/Python 之一、Git、命令行、接口与测试 | 一个任务跨过哪些持久对象？ |

数学只要求向量、矩阵、基本概率和计数。第 4 章明确坐标记号，第 12 章解释统计假设；本书不代替控制理论、机器人运动学或分布式算法的完整课程。文献入口在附录 E。

## 四篇知识地图

```text
第一篇：问题域(1) → 架构(2) → 完成契约(3) → 世界事实(4)
                                    ↓
第二篇：能力(5) → Agent(6) → 规划(7) → 一致性(8) → 单机(9)
                                    ↓
第三篇：设备集成(10) → 诊断(11) → 评测(12) → 运维(13) → 开发(14)
                                    ↓
第四篇：边界(15) / 软件对照(16) → 云边综合(17) → 上下文(18) → 案例(19)
```

箭头表达主要概念依赖，不强制每个人线性阅读。第 17–19 章把前文概念组合成当前系统；遇到术语回查对应基础章，不需要反复阅读全部正文。

## 按用途选择路线

| 用途 | 第一轮 | 深入与可检查产物 |
| --- | --- | --- |
| 第一小时建立全貌 | 2、3、17、19 | 一张职责图，三种成功的区别，一次失败的原因链 |
| 软件/分布式开发 | 2、5–9、11、18 | 实验 1–4；权限、去重、checkpoint 与作用域表 |
| 机器人接入 | 1、3–5、10、13、17 | 实验 5–7；本体接入包及物理后置条件 |
| 科研与系统评测 | 3、8、11、12、15、18、19 | 明确假设、反例、独立单位和复现材料的研究方案 |
| 新开发者上手 | 第一小时路线 → 14 → 源码 A → 实验 F | 追一条任务；提交一个有正反例的小改动 |
| 教学组织 | 四篇正文 + G + I | 课程目标、实验报告、综合项目及评价记录 |
| 工程查询 | 术语 D → 主题章 → 检查 B/流程 H | 按触发条件定位操作，保留依据与负责人 |

研究读者应同时检查实现和原始实验，避免只摘指标；工程读者应先理解权威状态和未知结果，再照模板操作。教师可以把 Tangying 换成另一实现，但保留概念、接口与反例要求。

## 每章的学习闭环

1. 按学习目标画出概念关系，注明先修知识。
2. 将通用原理、当前代码和历史测量分别标注。
3. 回答基础题 B，解释定义与差别；完成工程题 E，给出可检查产物；设计研究题 R，写出可证伪假设与方法。
4. 用附录 I 的评价要点检查遗漏，用附录 F 的软件/仿真实验验证适用部分。
5. 在新案例中复用方法，说明哪些条件不能迁移。

每章三题共 57 题。题目允许多种合理实现；评分依据是明确假设、正确语义、负例与证据，不是复述包名。教学可选择题目，不能将“完成所有作业”解释为具备实机放行资格。

## 贯穿案例与三张工作表

贯穿任务从客厅巡检、启用地图、抓取同一杯子、厨房放盘到返回。阅读时建立三张表：

| 工作表 | 最少字段 | 要解决的问题 |
| --- | --- | --- |
| 职责/权威表 | 对象、所有者、读者、更新条件 | 谁能决定继续？ |
| 身份/状态表 | task、revision、robot、step、command、持久阶段 | 这条事实属于哪次动作？ |
| 证据/覆盖表 | 来源、时间/序号、判据、制品、未覆盖项 | 为什么确认或停止？ |

先填写一个成功步骤，再填一次丢响应或旧证据。若必须猜测身份、以截图代替关联，或把未知填成成功，说明系统理解还缺一层。
