# 前言：用一条任务学会整个系统

机器人收到了“拿杯子”的命令，控制器接受请求，工具返回成功，用户目标是否完成？这三个问题不能用同一个布尔值回答。还要知道拿的是哪个杯子、是否稳固持有、是否放进指定盘，以及失败时谁有权决定继续。

本书以Tangying Robot AgentOS为案例，从一台机器人讲到云边和机群，解释如何把自然语言变成可审批的执行定义、可验证的物理步骤和可追溯的持久事实。数字版1.2.0同步软件v0.7.0及main复核快照11db0adb，书籍版本与软件版本独立。

## 从哪一页开始

第一次阅读，先用一小时走前言→第2章职责图→第3章完成判据→第17章云边通讯→第19章真实长任务。目标是能画出系统，并指出谁保存目标、谁执行、谁提供证据。

下一轮按需要学习：后端/Agent工程师读5–9、11、18；机器人集成工程师读1、3–5、10、13；研究者读3、11、12及附录C/D；要从零建设时按第14章和附录F的完成产物推进。

正文保留详细原理、事故和历史源码片段。第1–14章开头的“当前实现”学习段解释本版行为；后面的历史数据与实现按原时间阅读。第15–19章给出当前能力边界、机制对照、完整云边实现、长上下文和实际任务复盘。不要以旧版的缺口判断新功能，也不要把历史测量称为重新验收。

## 全书贯穿的流程

```text
用户完整目标 → 能力目录/语义状态 → 规划提案
                                      ↓
                         不可变TaskRevision与批准
                                      ↓
           Local执行器 或 Fleet→claim/Basis→Edge checkpoint
                                      ↓
                  Runtime权限、期限、journal与本机Backend
                                      ↓
                       制品读回 / 动作后物理证据
                                      ↓
                       步骤/任务完成与持久收尾
                                      │ 只读瞬时故障
                       Ops定位→Recovery计划→独立调查/复验
                                      │ 物理未知/冲突
                               停止 / 对账 / 新审批
```

长上下文从完整权威历史生成热guard和冷归档；跨域共享的是版本化执行依据，不是复制所有聊天。异构设备通过Profile/Backend/Runtime接入，机群交接还需要共同坐标、同物身份、新鲜稳定证据和资源owner/fence。

## 三个容易混淆的协作

| 概念 | 当前实现 | 不能推出 |
| --- | --- | --- |
| 多Agent | Local Task/Ops/Recovery分离执行、诊断、提案和复验责任 | 三个独立模型或任意自主物理补偿 |
| 多机器人 | Fleet按序意图与明确共享物料交接 | 任意DAG并行、自动最优分配与自动换机 |
| 异构接入 | 不同结构/传感器/能力子集共享规范Runtime边界 | 所有机型都有驱动或异构实机长程任务已通过 |

当前指定Gazebo家庭单自然语言任务完成约19分钟、7阶段、23子步骤、6次抵达，并处理一次只读故障。第19章保留操作员暂停、真实末尾ready=false、冷分页调用为0及全部失败过程，不把它们改写成更强结论。

## 每章怎么学

先读学习目标，自己回答自测，再看答案与源码入口。附录F的实验要求可检查产物：职责图、身份表、拒绝路径、checkpoint中断表或证据索引，不以“程序没报错”作为学会的标准。

在软件测试中看到fixture verifier成功，只能判断接线或契约。仿真成功只覆盖指定模型、地图、场景与故障。现场设备的控制、传感器、停止性能、负载和长期可靠性必须另行验证。

## 证据与责任

| 证据 | 支持的判断 | 实际限制 |
| --- | --- | --- |
| 单元/契约/集成测试 | 明确输入、协议、持久化与拒绝分支 | 不证明物理性能或全部故障 |
| 仿真闭环 | 特定物理场景的执行和证据链 | 不等于真实摩擦、标定和控制 |
| 模型测量 | 指定模型、任务集、参数下的表现 | 不保证其它模型或现网分布 |
| 受监护实机记录 | 这台设备和环境中的表现 | 不自动推广到无人值守或其它型号 |
| 负责人放行 | 明确设备、任务、环境与期限 | 不授权范围外动作 |

“已实现”“已测试”“已测量”“建议”“待验证”在书中分别使用。数据库事务包不住物理动作，TLS不证明观测正确，软件停止不替代经验证的实体停止系统。AgentOS是项目名，不能据此推断硬实时操作系统或认证安全控制器。

希望读者形成两个习惯：宣布完成时说明证据来源；声称机制有效时给出一个能使它失败的测试。
