# 前言：从系统问题到可验证的工程

机器人收到“拿杯子”的命令，工具返回成功，用户目标是否完成？还需要知道拿的是哪个杯子、是否稳固持有、是否放入指定盘，以及发生意外后谁有权决定继续。分布式机器人 AgentOS 的核心问题，是把目标、决策、控制、观测和责任组织成可以检查的系统。

本书面向软件工程师、机器人工程师、科研工作者，以及具备编程基础的高年级本科生和研究生。它同时承担三个用途：建立跨行业的系统知识框架；帮助开发者定位实现并逐步上手；为课程、工程评审与行业实践提供可改用的资料。读者无需先熟悉 Tangying 的全部包名。

数字版 2.0.0 将原来的项目技术专著重整为教材与工程参考版。通用原理在前，当前实现和可追溯案例随后；历史长源码、版本统计与修补过程归入旧版恢复入口。正文保留 19 个主题，统一学习目标、先修知识、术语、小结与分层习题，增加学习导读、课程设计、工程操作模板与习题指导。

## 本书如何讲清系统

第一篇建立物理约束、职责、闭环与世界模型；第二篇解释能力、Agent、规划、一致性与单机实现；第三篇讨论设备集成、诊断、评测、部署和开发；第四篇将扩展边界、软件 Agent 对照、云边协议、长上下文和完整任务连起来。

```text
完整目标 → 能力目录与语义状态 → 规划候选 → 冻结版本/批准
                                                   ↓
           Local 执行器 或 Fleet 协调器 → 边缘检查点/Runtime
                                                   ↓
                              本机控制/感知 → 独立验证
                                                   ↓
                            持久事实/回放 ← 完成、未知或停止
                                                   │
                   Ops 定位 → Recovery 提案 → 受控调查与复验
```

这张图同时贯穿单机、云边和多机情形。共享的是任务与执行身份、资源权威和证据语义；部署位置、控制周期、设备能力和故障域可以不同。长上下文不是把所有历史无限塞进提示词，而是从完整权威记录生成有界视图，并保留精确回查。

## 理论、实现与证据各有作用

本书使用 Tangying Robot AgentOS 作为能检查的实现案例，源码复核固定到 `11db0adb2be753e5ea04f6582032d925be8b95bb`；软件正式版本仍为 v0.7.0。通用模型解释为什么需要某个边界，源码说明本项目怎样实现，实验说明指定条件下实际发生了什么。三者不能相互替代。

例如多 Agent 是执行、诊断、提案与验证的责任分工，当前 Ops/Recovery 主要为确定性角色；它不自动意味着三个独立语言模型。异构接入让不同本体共享 Runtime 契约，多机任务还需要匹配、资源与物理交接。项目已有按序双机交接，通用异构调度和无人值守实机长程验收仍需扩展。

第 19 章分析一次约 19 分钟的 Gazebo 单自然语言任务：7 个阶段、23 个子步骤、6 次抵达，并处理一次只读故障。它保留操作员暂停、原末尾 ready=false、冷分页实际调用为 0 和先前失败。该案例适合学习完整因果链，不能用来估计全部机器人或任务的可靠性。
