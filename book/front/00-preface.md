# 前言：把命令回执与任务完成分开

机器人接受了“拿起杯子”的指令，工具返回 `success: true`。这可能表示命令已接收，也可能表示夹爪轨迹结束。它是否夹住了指定杯子、杯子是否仍然稳定在手中，需要进一步确认。

本书讨论的核心问题是：**系统依据什么证据宣布任务完成；证据不足时怎样停止、对账和恢复？** 工具可以返回经验证的观测，但裸露的成功布尔值不能代替后置条件。发起方并非“原理上无法知道结果”，而是必须有可靠的观察与判定链。

## 项目与读者

本书以开源项目 Tangying Robot AgentOS 为案例，面向会使用命令行、能阅读 Go 或 Python 的机器人、后端和 Agent 工程师。它从本地单机闭环讲到机群控制面，再到云端高算力与 Orin NX 边缘部署。

项目提供可检查的契约、测试、设计文档和失败记录，适合讨论工程取舍。它并未完成目标设备、真实机器人安全、长期高可用或数千机器人容量认证。本书的可发布状态是**出版物的完整与可复现状态**，不表示案例系统获得生产或实机放行。

## 贯穿全书的一条链

```text
用户目标 → 意图与规划 → 授权和范围校验 → 本机 Runtime 下发
                                              ↓
                         动作后观测 → 后置条件判定 → 完成
                                              ↓ 证据不足
                                   结果未知 → 停止自动重放
                                              ↓
                                   观测对账 / 人工处置
```

持久化记录让“命令可能已执行”跨重启存活；租约与 fencing 限制旧持有者；世界版本和证据基线帮助识别过时状态。每一种机制都要明确保护对象、故障假设和覆盖边界。数据库事务不能包住物理动作，软件停止也不能替代经验证的实体停止功能。

## 如何判断证据

| 证据 | 可以支持的结论 | 不能直接推出的结论 |
| --- | --- | --- |
| 单元、契约与集成测试 | 给定输入、协议和接线下的软件行为；`make test` 不仅含单元测试 | 实机性能、安全或任意故障覆盖 |
| 仿真闭环 | 指定仿真版本与故障场景中的执行、身份、恢复和证据逻辑 | 真实摩擦、传感器、标定和控制器表现 |
| 真实模型测量 | 指定模型版本、数据和评测方法下的结果 | 其他模型或现网分布上的可靠性 |
| 受监护实机记录 | 这台设备、这个任务范围和环境中的实际表现 | 无人值守、跨设备推广或自动安全认证 |
| 正式放行结论 | 负责人按适用要求批准的设备、任务、环境与期限 | 范围之外的通用保证或零事故 |

“至少 30 次试验”是项目现场流程的一项采样要求，不是安全认证定理。成功率、危险失败率、停止性能、独立性假设和风险责任须分别说明。附录 B 提供评审清单，附录 D 解释术语和假设。

## 内容与读法

- 第 1–4 章：时间、安全、带宽约束与闭环、世界模型。
- 第 5–9 章：工具、多 Agent、编排、分布式故障与本地状态。
- 第 10–14 章：仿真、观测恢复、评测、部署及从零搭建。
- 第 15 章：历史缺口与仍需验证的研究方向。
- 第 16 章：与 Coding Agent 的 33 项对照，讨论共同机制和不同风险。
- 第 17 章：共享决策内核的云端/边缘 Harness、模型路由与部署边界。
- 附录 A–E：源码导航、清单、实验索引、术语与参考资料。

第一次阅读可从第 1、3、16、17 章开始。自行搭建时，按第 14 章的八个阶段推进，并使用对应版本的安装指南。阅读实验时，同时检查日期、分母、配对单位、模型和适用范围。

## 方法与版本

章节使用源码标识符、项目文档与实验报告交叉核对。原始研究笔记保留在仓库 `book/research/`，作为写作历史，不纳入正式正文，也不作为当前能力的权威说明。出版复核修正历史叙事中的错误，但保留原有实验数字与失败记录，不把它们改写成新的实验结果。

第 1–15 章包含 v0.6.0/v0.7.0 演进案例；第 16–17 章按本版源码快照复核。完整版本边界见出版说明。示意代码用于说明机制，不自动构成可部署实现；复现实验应使用原报告注明的环境。

AgentOS 是项目名。本书讨论的是 Agent 运行时与机队控制面，不能从名称推断它提供硬实时操作系统或经认证的安全控制器能力。

希望读者带走两个习惯：每次宣布成功都询问证据来源；每次声称机制有效都询问哪种故障测试能使它失败。
