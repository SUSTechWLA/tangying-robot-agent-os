# 从协议成功走到物理闭环：一次 Gazebo 工程实验

日期：2026-10-18。本补充对应数字版 2.2.0 的第 3、8、10、12、13、17 章，不改变原出版快照。代码与修复入口见[实现记录](../../docs/development/2026-10-18-gazebo-field-validation.md)，实际成绩、失败尝试与证据见[实验报告](../../docs/experiments/2026-10-18-gazebo-field-validation.md)。

本节的学习目标是理解：同一任务的语言计划、执行协议、物理效果和测量证据分别由谁负责；为什么“已配置外参”“估计出了外参”“控制用到了估计外参”是不同结论；多台机器人同时运动又为什么不自动构成已部署的分布式群体智能。

## 沿着一次导航观察系统

假设给一台机器人下达“去厨房，再去卧室，最后返回客厅”。Local Agent 将命名目标解析为受批准的步骤，Robot Runtime 接收 gRPC 请求并检查命令身份、能力和期限，ROS 2 harness 通过 `ProfiledExecute` 把执行交给设备侧 driver。driver 把具体目标与剩余租约提交给实验 hub，局部策略生成速度目标，Gazebo 插件再把速度误差转成有界力和力矩。

关键区别在最后一步：控制器调用 `AddWorldWrench`，由物理引擎积分出下一时刻的位置、速度和接触。控制代码不能把机器人位姿直接写成目标值。随后读取的 link 状态返回 ROS 2、Runtime 和 Local Agent，形成命令之后的到达证据。这样才能研究控制延迟、制动距离、运动惯性和碰撞，而不仅是 action 字段是否正确。

本轮自然语言由确定性 provider 解析，控制与避碰均为经典方法，没有强化学习。学习者应先把这条可解释链路跑通，再讨论替换策略；更换模型不应同时改动完成判据。

## 停止是一个过程

“停止请求已接收”和“物体已停止”有时间差。运动中的刚体需要消耗速度，空中机器人还必须抵消重力。实验插件的地面停止为制动，空中停止为保持/悬停，不表示降落。

ROS `EnterSafeStop` 的 ACK 仅表示程序进入，诊断保持 `physicalStopVerified=false`。真正的停止实验要记录请求时刻、速度曲线、轨迹与持续静止窗口。实验报告还应标明使用墙钟还是仿真时钟；慢速渲染可能让一个仿真秒对应多个墙钟秒，二者不能混算延迟。

租约用于处理控制通道消失。每条 DDS 租约都属于一个具体命令；转发时扣除已经消耗的时间。hub 检查墙钟和单调时钟期限，物理插件检查仿真时钟上的控制命令间隔。driver 退出不能让最后一条运动命令无限有效。若执行结果未知，系统保留命令身份并停止对账，不能换一个 ID 再试。

一次续租没有收到回复，既不能证明命令已经失效，也不能证明续租已经成功。可用的依据是上一次 ACK 确认的截止时间：在这个有限窗口内继续接收新的 DDS 租约；窗口到期就停止，不因再次收到测量而清除续租故障。下一次续租必须仍绑定同一命令和原 deadline，晚 ACK 不能复活已过期命令。这一规则既避免无依据延长运动授权，也减少瞬态响应丢失造成的过早停机。

长程任务还会反复经过步骤交接。旧目标已经到达，不代表它的租约会一直有效；当新目标到来时，应在准入锁内依据实际时钟判断旧授权是否结束，不能只等待另一个线程更新“已过期”缓存标志。本轮实际暴露了这一竞态：到达校验通过后，新目标被误判为抢占旧目标。修复允许独立授权的新 command 接续，仍拒绝旧 command 重放，也不允许替换尚未完成且仍有效的活动目标。

## 测量比返回值更严格

重复读取一张图片不会产生第二次观察，重复读取同一仿真状态也一样。实验观测保存源序号、采集墙钟、仿真时刻和 observation ID。读取同一 snapshot 时复用原身份；物理暂停、序号回退、同身份内容变化都不能成为新鲜证据。

一次导航完成至少要关联批准目标、command ID、该命令之后的新观测，以及达到阈值的位置、速度和姿态。下一步 `verify_arrival` 重新观察，而不直接继承前一步成功。这里的定位来源明确为 Gazebo 真值 link 状态，它足以检查控制闭环，却不能用来评价 SLAM 的漂移或重定位能力。

这也解释了一个工程缺陷：为了记录更多信息而随意给 `robot_state_json` 增加字段，会被严格合同消费者拒绝。正确做法是保持已发布状态结构，将额外研究信息放入约定的诊断或 journal；需要扩展正式合同，则另行版本化并更新两端。

瞬态读取失败也不等于数据已经过期。在原有效期内，可以复用上一次真实 capture 并重试只读请求，但必须保留原 ID 和采集时刻；一旦年龄超限就停止，不能用轮询时间续命。这个规则只适用于读取。发送运动请求后丢失回复，仍然意味着物理效果未知，不能按同样方式自动重发。

持续轮询还会反过来影响系统。物理引擎尚未产生新帧时，重复读取同一帧增加线程与 HTTP 负载，却不增加信息。本轮在 50 ms 内合并 snapshot 请求，使用 100 ms 状态发布和 50 ms 执行轮询，并让租约回调独立于测量读取锁。优化的目标是减少重复工作；观测的原始时效、命令租约和完成标准均不改变。

## 同伴避碰与分布式协作

局部避碰读取本机和同伴的测量位置、速度、包围半径以及时间和坐标依据。对候选速度求整个预测区间的最小间距，检查途中是否相交。只比较起点与终点会漏掉“两台机器人在中间穿过彼此”的情况。再加入制动、反应时间和测量年龄余量，决定采用候选还是请求停止。

对称相遇容易造成同时向左、又同时向右的反复退让。本轮使用共同右侧通过偏好，并在交叉冲突时按稳定 robot ID 给出优先序。它使策略可解释、可复现，但不是所有窄通道都能通过的证明。走廊不够宽时仍需全局等待点、通道占用或退让路径规划。

同一个 Gazebo 世界中运行多个 Local Agent，可检查各自任务日志以及同时运动时的互动。本轮实验 hub 仍集中持有测量与步进权威，所以不能据此宣称已经解决了独立无线网络、跨机时钟漂移、各自地图环闭合和分布式所有权转移。已有 peer 覆盖建议是任务层数据，它也不能直接充当实时避碰授权。

对真实底盘还有一个重要约束：本轮地面 proxy 可以跟踪世界 XY 全向速度，差速 AGV 不能。接入差速车辆时，应采样满足转弯和加速度约束的控制轨迹，再做扫掠检查；先算全向速度、再删除横向分量，会改变被验证的轨迹。大疆飞控与宇树步态同样必须提供自己的可执行模型和停止语义。

包围体也属于协议语义。0.5×0.4×0.3m 的盒体可被半径 0.33m 的水平圆覆盖，却不能被同半径的三维球覆盖。若无人机直接使用这个地面半径，会低估机体高度产生的角点范围。本次将地面声明改为 0.36m，并检查实际 SDF 的全部角点。比较实验时应保留修改前的原声明，另用真实几何重算间距，而不是在历史日志里把半径替换成新值。

## 区分五种坐标知识

| 知识 | 来源与用途 | 可支持的结论 |
| --- | --- | --- |
| 仿真配置外参 | 世界生成时设置的 lidar 到机身变换 | 检查坐标变换接线与算法输入，不是估计精度 |
| 已知场景估计 | 实际 lidar 回波对独立静态 CAD 注册，保留点单独验证 | 在该场景与阈值下估计 sensor-to-world；还需独立底座测量才可推导外参 |
| 跨机器人点云对齐 | 两侧测量点、来源身份、地图版本和配准质量 | 得到需准入的相对变换估计；歧义、退化或低重叠应拒绝 |
| 共同已知 CAD 锚点 | 两机各自对同一测绘场景的已接受估计 | 可组合扫描时刻的传感器关系，依赖共同先验；不改变直接点云配准的拒绝结果 |
| 控制采用的坐标依据 | 已部署、版本化并在运行时校验的变换 | 只有实际进入控制链才能研究对齐误差如何影响导航 |

本轮主控制仍用配置外参和真值公共定位，注册与估计标定单独实验，没有自动将估计写入 TF 或驱动控制。估计过程不能用被检验的真实传感器位姿构造答案；保留验证点也不能在拟合失败后悄悄删除。动态回波造成的误差应留在报告里。

因此论文可以分别研究配准质量、控制鲁棒性和协议可靠性，但若要声称“跨机估计地图支撑了协同导航”，还必须真正接入估计、记录采用版本，并在受扰动的闭环中验证。摘要哈希证明数据未被修改，不证明来源身份可信，也不证明两个形状相似的房间就是同一地点。

已有共同 CAD 地图时，可用 `inverse(world_T_A) @ world_T_B` 组合两份独立接受的传感器定位估计。这个回退方法不需要把直接配准的拒绝改成通过，但依赖已知场景，不能据此宣称实现了陌生环境建图对齐。对同一份扫描做新的派生计算，也不会增加独立实验的样本量。

## 建议课堂实验

按[实现文档](../../docs/development/2026-10-18-gazebo-field-validation.md#复现与扩展入口)先做协议测试，再进入隔离 Gazebo 实验。保留初始状态、完整中文任务、批准包络、每步命令、观测 ID、速度与接触，以及失败和修复尝试。

1. 运行一条单机器人往返任务。沿 command ID 找到目标派发和命令后的测量，检查其位置、速度、姿态及时间是否满足完成条件。
2. 对运动中的机器人请求停止，再只切断控制命令。比较请求 ACK、控制器 watchdog 触发与实际停止时刻；空中保持与落地应分开评分。
3. 运行正面与交叉相遇，记录最小间距、完成时间、停等时间和避碰触发原因。再引入旧 peer 状态，检查停止是否由数据失效触发。
4. 分别使用配置外参和独立估计结果做离线点云变换，比较拟合与保留集残差。此实验不应直接改动正在运行的控制配置。
5. 选择一个失败样本，修改一个模块并重新运行。将修复前后证据并排保留，说明变化来自协议、控制、感知还是验收脚本。

讨论题：为什么相同代码、相同地图、不同故障时序不能自动算作独立场地样本？为什么“静止时准确”不能推出“运动时也准确”？什么证据能说明一次消息丢失没有造成重复动作？如果未来接入估计地图，哪些 frame、map revision 和有效期检查必须成为执行前置条件？

教学评分应分别检查合同正确性、物理结果、证据完整性和结论边界。不要把单测条数、任务成功率、覆盖率和地图对齐精度混成一个没有明确分母的总分。
