# 从单机 ROS harness 到异构协作：执行、建议与可观察性

日期：2026-10-18。本补充保持数字版 2.2.0 的原出版身份；配合第 8、13、17 章和[本轮实现记录](../../docs/development/2026-10-18-edge-swarm-readiness.md)阅读。

学习目标是区分三种容易混淆的事实：消息送达、控制器接受、机器人完成。通信层保存一次任务建议，不代表另一台机器人已看到目标；执行 action 返回成功，也不能代替命令后的独立观测。完整任务链需要分别记录 task/revision、command、observation、map/transform 与各条因果关系。

## 一台机器人先成为可靠执行单元

Local Agent 是任务入口，Edge Host 负责有界规划与验证，Runtime 维护命令日志与准入，ROS harness 负责将标准合同接到具体控制器。无人车、无人机、足式共享前三层，末端实现分别遵守轮式运动、飞控或步态约束。所谓复用 harness，是复用身份、期限、证据、停止和错误语义，不能推导出同一速度指令适用于所有机型。

考虑“导航命令已经下发，但是结果连接断开”。Agent 无法知道机器人有没有移动。正确行为是保存 command ID，阻止后续冲突动作，并请求该设备的注册停止程序。停止程序的 ACK 仍不是物理结束证明。重启后应从持久事实对账，而不是新建 command ID 再试一次。

首轮设备选择是大疆无人机、宇树足式与通用 AGV。工程接入通过外置型号绑定记录 ROS 2 接口、控制模式、坐标和停止语义，任务规划器不按品牌编写分支。大疆的 SDK 可用性依赖具体机型，宇树的高层运动服务不等于地图导航，AGV 的导航 action 成功也需要独立到达证据。配置预检只证明声明一致，现场控制与测量是否真实成立需要后续分层实验，见[设备接入指南](../../docs/operations/ros2-device-bindings.md)。

## 多机器人共享建议，完成仍有证据所有者

每台机器人持有自己的执行日志。edge-exchange 负责有身份的可靠数据投递，覆盖视图负责核对任务范围和地图依据，探索策略可以因同伴建议改变候选排序。但本机 CoverageLedger 只接受满足测量合同的观测，不能把“同伴说已经看过”写成本机实际看到。

这种边界允许更换信息收益、竞价、图搜索或学习策略，随后用相同输入和证据判据做消融。策略改变“优先做什么”；权限检查和独立验证决定“能否做、是否完成”。当前软件协调器采用有界串行执行，不提供真实并行机群的碰撞避免证明。

## 运维也需要完成判据

“没有收到新的故障”不等于“旧故障已恢复”。遥测中断、传感器过期、任务库暂时不可读时，Ops 应报告观察缺口并保留旧异常。只有来自对应权威来源的新鲜证据才能关闭它。新诊断合同列出每个 sensor 的观测 ID、序号、标定版本与年龄，使操作员能够查明究竟哪个数据源失效。

Ops 负责确定发生了什么，Recovery 提出允许范围内的处理，Host 审核权限、预算和未决结果。未知物理效果不能由模型推断或自动重启消除。

## 课堂实验与论文记录

先运行三种机型的记录式 ROS 2 控制器，观察同一自然语言路线如何经过 HTTP、gRPC、DDS action 和独立到达验证。再运行多节点回环通信和三形态未知地图探索，将网络、几何和设备控制证据分开。

保存全部成功、拒绝、未知、partial 和脚本错误，记录源码/二进制摘要、任务及故障输入、每个机器人贡献、观测覆盖、消息量和停机顺序。重复相同确定性场景能发现回归，但不是独立随机样本；未完成覆盖不能从分母删除。

练习：为什么收到 ACK 后不能标记任务完成？如果地图名称相同但 transform revision 不同应怎样处理？若传感器字段从健康报告中消失，为什么不能关闭它的过期告警？如何设计一组区分“协作建议有用”和“真的执行更安全”的消融实验？实际结果与限制见[实验总报告](../../docs/experiments/2026-10-18-edge-swarm-readiness.md)。
