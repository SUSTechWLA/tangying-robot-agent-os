# 3.2.0 后续阅读：长历史成本与规划经验

本页是当前系统增量，不覆盖已发行的 3.2.0 正文、源码快照或离线出版目录。结合第 8 章执行边界、第 17 章跨域一致性和第 18 章上下文/计算预算阅读。具体配置见[模型成本与任务经验](../../docs/production/model-cost-and-recipes.md)，代码、试验与限制见[实施记录](../../docs/development/2026-10-28-edge-scalability.md)。

## 1. 历史和当前状态为何需要不同读模型

假设 3 个机器人各在一个流中更新 500 次覆盖建议。审计历史有 1,500 条，当前候选只有 3 条。直接对历史取前 1,000 条，既没有读完历史，也不能知道哪些旧值已经被后续消息撤销。系统应拒绝用这个子集形成完整建议，而不是忽略截断。

改进是保留完整历史 feed，同时用永久序号高水位查每流当前值：

\[
H_s=\max\{q:\text{接收端已持久接受流 }s\text{ 的序号 }q\},\qquad
V_s=\text{body}(s,H_s).
\]

先找 \(V_s\)，再校验身份、TTL、任务与地图版本。若最新正文无效或已经清理，则该流无可用建议。不能改成“从历史里找最新有效正文”：那会让已失效的覆盖事实复活。新的查询上限约束当前保留流数；永久 cursor 和历史仍然需要容量与保留管理。

## 2. 保存每一条事实不等于重写每一条事实

若第 \(k\) 次 append 每次都读取并重写已有 \(k\) 条事件，连续 \(n\) 次追加的序列化量近似为：

\[
\sum_{k=1}^{n} k b = \frac{n(n+1)}{2}b,
\]

其中 \(b\) 是平均事件字节数。事件总量只增长 \(O(n)\)，写入工作的放大量却达到 \(O(n^2)\)。新的 append-only 端口在事务内获得写锁、分配序号、INSERT 单条事件，只更新任务时间，不用旧 Task 快照覆盖当前批准/版本/取消状态。调用方不需要完整历史时使用这个端口，原完整读取和回放仍保留。

这不是所有长任务成本都降为常数：授权检查仍读取当前状态，子任务 journal、证据和检查点仍增长。实验需分别测量事件追加、目标推进和完成回传，不能拿一个 microbenchmark 推导整机可靠性。

同一轮完整测试继续暴露 child 快照成本。局部优化采用一次 Host.Run 内的私有写快照，每次提交仍携带版本做 CAS；冲突时丢弃缓存，重新读取已提交事实。当前状态的读取从不走该缓存。派生显示事件仍持久化到 state/domain log，但不再额外写第二份完整 checkpoint；收据、验证和停止继续保存 checkpoint。这说明“缓存写入工作”与“缓存执行权”有不同风险，也说明 checkpoint 带版本很重要：它可以落后于当前 aggregate，恢复程序必须明确自己读取的是哪一层。输入和输出对象的引用隔离、重启后数字精度同样属于一致性测试，而非性能小节之外的细节。

## 3. 重复规划什么时候值得复用

缓存的对象是“候选计划 + 当时查询方式”，不是旧动作结果。统一用时间或折算后的费用衡量成本，不能把 token 数和毫秒直接相加。设正常规划的一组模型决策成本为 \(C_m\)，实时查询成本为 \(C_r\)，缓存查找和重新校验额外成本为 \(C_v\)，通过重新查询和冻结校验的精确命中率为 \(h\)。先假设两种方案的实时查询成本相同、未命中时的模型决策成本相同：

\[
C_{\mathrm{baseline}}=C_r+C_m,\qquad
E[C_{\mathrm{reuse}}] = C_r+C_v+(1-h)C_m.
\]

两式相减，预期节省为 \(hC_m-C_v\)，因此在 \(C_v<hC_m\) 时值得复用。实时查询在基线中也需要执行，不能重复计算成缓存方案独有的开销。若未命中还增加查询成本 \(\Delta C_r\)，条件变为 \(C_v+(1-h)\Delta C_r<hC_m\)。如果状态不断变化、参考提示反而增加决策轮数，简化假设不再成立，应直接比较完整规划的实测总成本。这些公式是实验设计依据，不是测出的商业费用。

系统把精确匹配与相似匹配分开：精确目标在相同机器人/模型/目录/授权/进度作用域下重读条件，成功相等后重新冻结草案；相似目标只给模型一个有界参考。一个“去厨房”和“不要去厨房”的高相似分数不应获得相同执行计划。否定、顺序、物体身份、地图修订和剩余进度都可能改变动作。

第一版经验来自验证通过的草案，而非完成任务后的技能抽象。它能减少重复编排成本，但不能据此训练或宣称成功策略；研究者要从原任务账本另外取得执行结局、拒绝与 unknown 分母。

## 4. 把缺失成本数据当成缺失

一个模型响应可以返回 `prompt_tokens=0`，也可以完全不返回该字段。前者是服务报告的零值，后者是不可观测。输出上限、输入字节、命中提示和本地复用次数都不能替代真实 usage。建议报告每字段的已知样本数、总调用数、失败/未结束调用、总用量与缓存份额；只有明确价格版本和计费规则后才计算金额。

课堂实验：在相同软件 fixture 下对比 `off/hint/validated`，然后改变一条语义观测、一个工具授权、一个目标否定词。检查请求数、实时读取数、规划 trace 和任务批准状态。最后关闭重开 SQLite，证明复用来自持久候选而不是残留内存；再注入读失败，验证它不会回退旧观测并继续。
