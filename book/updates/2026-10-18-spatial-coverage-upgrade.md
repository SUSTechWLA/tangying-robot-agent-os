# 补充：从未知探索到已知覆盖，怎样扩展异构机器人规划

日期：2026-10-18。配合第 4 章世界模型、第 10 章异构接入、第 12 章评测和第 17 章云边系统阅读。数字版 2.2.0 的固定正文与出版身份保持不变；本轮实现、接口和迁移见[开发记录](../../docs/development/2026-10-18-spatial-coverage-upgrade.md)，上一轮软件数据仍按[原报告](../../docs/experiments/2026-10-18-spatial-exploration.md)引用。

## 1. 知道环境，不等于完成巡检

首次进入环境，机器人需要探索 unknown。已经持有地图时，它可能需要重新检查所有规定位置、观察设备表面或确认某个区域的当前状态。如果只按 unknown 信息收益选点，一张完整地图会让策略立即停止，任务却没有被执行。

因此系统把“未知空间探索”和“已知地图覆盖”分成两个策略问题。前者问在哪里增加世界知识；后者在显式任务范围内选择观察位置和路线。两者可以共用地图、传感器、本体规划器和覆盖账本，不能共用一个含混的完成百分比。

已知覆盖有三种需要分别回答的结果：计划预计能看多少；按预算还剩什么；实际新观测证明看到了什么。生成完整路线只回答第一类问题。系统不得因保存了一份计划，就将真实机器人任务登记为完成。

## 2. 目标集合决定覆盖率的含义

任务先固定地图、共同网格、ROI 与目标集合，再选择位姿。图像中的一面墙、设备表面片和三维体素集合是不同评价对象；点云重建完整度、观测覆盖和几何路径成功也不是同一个指标。

若使用体素目标，应保存目标 ID 和网格依据；如果目标是表面，应另外定义观察距离、方向、分辨率、入射角和需要多少次独立观察。不能把“当前搜索没有找到的目标”从分母移除，也不能把有限候选无解解释成所有连续位姿都不可达。

规划器使用已知地图估计目标可见性，这是当前任务允许的输入。未知探索的环境真值仍必须与策略隔离。研究者应在方法节解释每个阶段已知什么，而不是用同一个“自主覆盖”标签省略信息条件。

## 3. 同一三维世界中的不同移动空间

无人机在自由体积内移动；无人车和足式机器人依赖支撑面。把地面机器人限制在单一 XY 高程上，无法表达桥上桥下或多层建筑；允许它随意在体素空间移动，又会把它当成可以飞行的机器人。

本次引入 `terrain_layered`：用多层支撑面和显式层间连接表达地面移动。上下层在同一 XY 位置相遇，不代表可以直接跳层。空中、单层地面和多层地面保留各自的准入检查，再共同参与目标分工。

层间连接只是几何关系。真实车辆转弯半径、楼梯通过能力、足式接触和承载力仍需设备控制器或专门规划器处理。当前扩展不代表系统已经能驾驶任意机器人穿过任意楼层。

## 4. 插件边界应围绕可验证合同

新增覆盖策略可以替换候选、收益和顺序；新增传感器可以替换可见性模型；新增机器人可以替换路径与执行适配器。这些替换保留地图/世界版本、目标身份、输出预算、合法路线和失败解释，不能修改旧观测来配合新策略。

`SpatialMissionRunner` 通过地图、驱动、报告和策略工厂连接任务。计划中的 `expectedObservedVoxelIds` 是预测目标，旧探索中的 `visibleUnknownVoxelIds` 是未知空间收益；新采集证据才进入实际覆盖账本。模型、协调器和规划器都不凭自己的提案取得动作权限。

本地规划 CLI 输出可复核计划。真正执行时仍通过 Runtime 的批准、lease、路径握手、定位质量和停止程序。对一份静态计划的验证，不能替代当前地图和真实位姿下的重新准入，也不能替代命令之后的独立观测。

上手可先读[空地互补请求](../../examples/coverage/mixed-air-ground.json)，再比较[房间 ROI](../../examples/coverage/full-room-coverage.json)、[坡道连接](../../examples/coverage/layered-ramp.json)和[断开的楼层](../../examples/coverage/disconnected-floors.json)，按[CLI 步骤](../../docs/development/2026-10-18-spatial-coverage-upgrade.md#6-本地使用与可回溯制品)输出到新目录。检查 `predictedCoverage`、`unresolvedVoxelIds` 与保持空值的 `observedCoverage`，解释为什么“预测完整”仍然没有机器人执行证据。

随后运行 `run_spatial_coverage_fixture.py`，通过实际 Runner 的软件驱动与新采集端口观察闭环；`--unknown-step 3` 可检查结果未知时的 fence、正向停止回执与后续派发。它与只读预测计划不同，但传感器、驱动和时钟仍是理想 fixture；虚拟时间和 stop ACK 不能当作物理控制或真实停止的测量。

## 5. 把协作机制拆开，才能解释实验

上一轮 `no_coordination` 同时改变分配重叠处理和共享覆盖收益指引。它能比较一套联合机制，却不能分别说明两部分各贡献多少。本轮将它们拆为独立对照，地图交换、安全检查和未知动作 fence 始终保留。

每次对照固定地图、起点、传感器、本体、预算和故障，分别报告预测覆盖、实际观测覆盖、重复观测、成功后新增观测、几何路程、计算量与通信量。相同占据结构的不同故障条件是不同任务块，仍不等于新的独立几何环境。

跨边缘机器人共享知识有延迟。事后从所有原始日志汇总的覆盖，可能高于协调器当时已收到的覆盖；新基准分别保存这两项，并将共享覆盖 ID 与占据地图作为显式消息计量。用事后全量数据评分没有问题，但不能因此声称调度器在决策时已经知道这些事实。

实验应包括遮挡、多层连接、能力互补与无解/预算耗尽情况。保留所有部分结果和故障 skipped 的理由，不能只统计成功任务。未测能耗、真实定位误差或实体碰撞时保留空值，不能用路程或软件 ACK 代替。

选择系统时比较 Pareto 关系并说明应用要求：巡检完整性、时间、续航、计算和通信之间可能存在取舍。更多模块或更复杂策略不自动产生更好的系统，小样本最优也不能外推到全部场景。

[本轮实际实验与证据](../../docs/experiments/2026-10-18-spatial-coverage-upgrade.md)分开保留四个预测规划案例、两次 315/315 的已知地图 Runner 软件闭环和 350 个未知探索对照。后者全部为 partial，不能因前者成功就说未知场景已完整覆盖。开发集有 16 个不同占据几何，留出集有 24 个且跨集无重复；同一门洞布局的故障条件按几何聚类。报告提供描述性 cluster bootstrap 区间，未作显著性判定，也没有实机或 Gazebo 新结论。

## 教学与研究练习

1. 设计一个“地图没有 unknown、巡检目标尚未观察”的例子，说明探索停止与覆盖完成为何不同。
2. 为桥上桥下建立分层支撑图，说明同一 XY 的两个节点何时允许连接，哪些验证仍属于车辆或足式控制器。
3. 为预测目标、实际观测、旧地图分类设计三个不同字段，写出把计划误作完成的反例测试。
4. 将联合协调消融拆为两项，列出需要保持不变的地图交换、安全与故障条件。
5. 为已知地图规划、软件闭环和实体覆盖分别写一个可支持的论文论断，指出其尚不能支持的结论。
