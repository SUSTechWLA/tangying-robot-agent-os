# 第 7 章 自然语言规划、任务版本与执行组织

**学习目标**：将目标转为可审查计划；区分通用规划模型和当前实现；控制循环与改版。

**先修知识**：第3、5、6章；状态机与基本图结构。

**关键术语**：目标约束、规划预算、TaskRevision、aggregate、claim、执行摘要

## 7.1 目标不是一组随意工具调用

目标需定义对象、顺序、地点、约束、完成条件和不确定项。“取杯返回”至少要表达取哪只杯、放哪里以及返回位置。歧义应显式澄清；不应通过挑最近对象让语法错误隐藏为感知错误。

系统提供两种批准对象。旧 `/v1/tasks` 在创建时读取目录与语义状态，校验候选并冻结能力计划，随后批准。新增 `/v1/objectives` 先保存粗目标和权限包络，创建不调用云端规划器、不自动批准；批准冻结父合同，边缘 Host 才读取本机事实并形成受约束子计划。现有自然语言页面和旧草案工具仍走旧通道，不能仅更换措辞就得到边缘目标委托。

## 7.2 规划模型与调度能力

一般任务可以表示为节点/依赖图，调度考虑资源和前后置条件。但本项目当前capability plan是一台robot/catalog上的有序调用，Fleet Intent也是按前序成功认领；不是任意并行DAG或异构最优匹配器。

说明当前边界有助于正确扩展：需要新节点契约、联合资源、并发完成及取消语义，而不是只令模型输出图。

## 7.3 规划循环的预算

| 一次能力Planner的GOAL边界 | 意义 |
| --- | --- |
| 10轮决策 | 阻止无限模型循环 |
| 6次Provider读取 | 限制一次规划内的现场查询 |
| 3次提案 | 有界修正与拒绝反馈 |
| 单提案最多16 calls | 有限执行定义 |
| 上下文/HTTP请求字节预算 | 避免在调用前丢硬约束或越窗 |

context_read计入总轮数，不变成物理调用；其他actionloop有自己的轮数边界。目标 Host 在它之外还有跨代持久预算：

| 父目标上限 | 计量单位与说明 |
| --- | --- |
| `maxPlans ≤ 8` | 生成计划的代数，失败/重启不返还 |
| `maxSteps ≤ 128` | 子能力调用尝试；单代仍最多16 calls |
| `maxReads ≤ 4096` | Host 管理的业务只读服务调用 |
| `timeoutSeconds ≤ 86400` | 首次接受起的期限，与绝对 expiresAt 取较早者 |

这些上限可由调用方收小。一次 `robot.task` 可能包含多个物理子步骤，内部观测、控制周期和遥测另有约束，不能把128理解为跨所有层的动作总数。预算先持久预留后工作；没有完成确认也不能靠重启取得新额度。必须保留状态超预算时拒绝或缩小明确阶段，不以截断目标凑计划。

## 7.4 三个版本维度

TaskRevision固定执行定义；aggregate version保护并发状态提交；claim version标识协调器认领提交。它们不能互相替代。

新增待批准提案可能提高aggregate而不改变active内容。执行摘要只覆盖活动批准定义；旧快照不能与新claim拼接。新目标需要新提案/批准，在允许安全点切换，旧物理结果仍需闭合。目标通道的父 TaskRevision 与授权摘要不随子计划代数变化；每代 `edge-child/<childId>` 保存独立计划与模型上下文，代数不是新的父批准版本。

## 7.5 成功与失败规划的记录

任务创建前尚无taskId，trace保留真实robot scope，不倒填未来身份。实际模型请求、候选、拒绝原因和归档引用能解释每轮决策；创建失败通过planning attempt保存，不产生可执行任务。

配置GOAL模型时主入口按能力目录规划；未配置时保留完整句式的离线语法。旧INTENT/PLANNING路线的后备策略不能概括所有自然语言入口。

## 7.6 工程案例：条件目标

“巡检后若地图可用则去卧室”先读明确可用性和地点条件，再提出完整序列。若目标需要的条件无法从目录语义字段判断，应澄清或拒绝，不能调用未注册工具或将原始信号解释当确定事实。

### 版本推演：提案不自动改变执行

假设 active revision=2、aggregate version=20。用户新增目标提案后 aggregate 可能变为21，但 active revision 仍为2；新目标没有执行权。旧步骤完成必须按其 revision/command 确认，不得把完成回执直接归到待批准 revision=3。

批准切换需要明确旧在途/未知状态与资源处理。当前云边成功收尾可按已批准待切换版本重入激活，但不能把未批准提案偷偷激活。图形工作台显示最新版文本时，也应区别“正在执行”和“正在编辑”。

## 7.7 规划器的算法边界与目标覆盖

下面是教学伪代码，用于组织评审，不是项目 API：

```text
读取完整目标、已知约束、目录和适用世界
在有限预算内：
    构建有界上下文；必要状态无法容纳则拒绝
    接受模型的只读查询或候选序列
    校验 Schema、能力/版本、效果/资源与参数
    核查每项用户要求是否有步骤及完成判据
    有歧义则等待澄清；有越界则拒绝并记录
冻结候选内容 → 用户批准 → 生成执行身份 → 每步准入与验证
```

目标覆盖可用需求矩阵表示：每一行是对象、地点、条件、顺序或最终状态，每列连接对应能力及 verifier。若用户要求“返回客厅”，只完成厨房放杯不能满足整任务；若要求“发现障碍则改路”，必须有感知依据和合法分支，不能把条件省略。

当前能力计划主要是有限按序调用，不提供任意条件 DAG、无限分段或通用异构节点分配。规划器可拒绝无法表达的完整目标，而不是静默将长目标缩成最后一句。更复杂计划需要新增显式语义、批准和验证合同。

### 目标通道怎样保留已完成前缀

Host 只把完成条件、完成总数/摘要、最近8项确认调用和当前诊断投影给下一代 Planner；完整子账本保留全部完成效果。写调用按工具与业务参数确定效果键，默认同一调用只允许一次；有意回访同一地点须在原grant显式设置 `maxExecutions`。变化的 LegacyIntent 观测元数据不产生新效果额度。

完成条件尚未成立时可以在剩余预算内生成后续计划。明确未准入或无副作用读取失败可以提出剩余任务重规划；未知写先对账。v1仅允许已绑定机器人的 `robot` 资源，电梯、共享物品、空域或跨机器人分工不能靠扩写goal取得授权。超过单目标上限时，由上层提出新的有完成条件目标，不能隐式续期或无限分段。
