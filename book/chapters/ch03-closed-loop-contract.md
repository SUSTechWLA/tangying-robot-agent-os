# 第 3 章 闭环契约、证据与完成判定

**学习目标**：定义前后置条件；用三态结果处理证据不足；建立拒绝路径和恢复分类。

**先修知识**：第1–2章；状态机。

**关键术语**：前置条件、后置条件、证据基线、Unknown、失败分类

## 3.1 从目标推导前后置条件

一个技能的前置条件说明何时允许开始，后置条件说明完成后必须满足什么。杯子放盘的前置条件可包含批准、目标绑定、有效观测和持物；后置条件包含同杯已释放、在目标盘内且稳定。

在给定证据与契约下，判定可表示为：

```text
输入身份/权限合法 AND 证据有效 AND 后置条件满足 → 确认
输入或证据明确不合法 / 条件明确不满足        → 拒绝或失败
动作可能发生但证据不足                    → 未知，先对账
```

Unknown和False不同。没有观测不能推出杯子不在盘内；也不能推出它已被放好。

## 3.2 证据需要什么身份

| 字段/属性 | 用途 |
| --- | --- |
| task/revision/step/command/robot | 指向本次执行尝试 |
| observationId/sourceId/sequence | 指向实际采集，识别重复/倒退 |
| captured/observedAt、动作前基线 | 判断是否来自命令之后 |
| frame/transform revision | 避免坐标或标定错用 |
| targetId/relation/质量状态 | 判断指定对象与后置条件 |

墙钟排序要考虑语义和误差；同毫秒桶或“刚收到”不充分证明动作后采集。当前Gate与设备验证器并不统一估计跨机时钟误差，集成时需说明来源/序号/采集屏障的实际保障。

## 3.3 制品验证与物理验证

地图生成需要独立读回mapId、revision、标定绑定、保存与激活状态。导航需要定位到达和误差约束。抓取/放置需要同物持有、释放及空间关系等实际证据。

同一种工具SUCCESS可以触发不同验证器。Validator必须避免直接引用执行器自身的成功布尔值作为全部判据；所谓独立性要说明输入、代码路径、传感器或样本层面的具体含义。

## 3.4 失败分类决定允许的下一步

Transient、Perception、Planning、Permission、Resource、Validation、UnknownOutcome和Fatal分别表达不同处置范围。分类需要来源码与真实派发状态，不能靠模型把物理unknown改名为网络瞬时错误。

已证明只读的查询可有有界重试；物理写失败要先确定是否派发及产生效果。Unknown时不能通过换commandId重新执行同一动作。取消请求、停止ACK、实际停止和可重新授权也要分别记录。

## 3.5 验证器的测试设计

最低测试集合包括：正确身份/新鲜证据的正例；错目标/错命令/旧revision；命令前观测；过期来源；重复帧；缺字段；明确未满足和未知；数据库/观测读取失败。

对稳定样本，还要判断是否来自不同采集，而非同帧重发。固定场景的5样本/200ms是该验证器参数，不是通用安全定理。

## 3.6 案例：工具成功但证据陈旧

机器人完成放置RPC后，验证器收到一张放置前图像。正确响应是拒绝用它确认，保留真实动作记录并获取合格新证据或对账；错误响应是把HTTP到达时间写成采集时间。失败关闭要求停止进一步依赖该完成状态的物理步骤。

### 判据推演：导航完成

教学例子设目标位置为 g、有效动作后定位为 p，平面距离为 `d=√((p_x−g_x)²+(p_y−g_y)²)`。合同可要求 `d≤r`、速度低于约定门槛、观测与命令身份匹配，且指定时间内来源有效。r、速度与时限由设备/任务确定；这不是项目默认阈值。

若位置估计有可信误差上界 e，保守条件可取 `d+e≤r`；若没有可靠误差模型，不能把置信度字段当确定误差界。d 很小但来自命令前定位，仍不能确认本次到达。判据同时包含数值、来源和因果条件。

## 3.7 Gate 的判决顺序与加强层

当前 `core/closedloop.Gate` 的顺序可以用以下缩写解释，完整代码以固定源码为准：

```text
若 manifest 或 Runtime 声明改世界：需要闭环证据
否则：不要求物理后置证据
需要证据时：先检查派发时刻，再检查证据存在，再检查来源新鲜度
拒绝时：返回稳定 reason，不用自由文本决定可重试性
```

两处效果声明取“或”，避免某一端少声明就绕过门禁。但只读工具仍需身份、权限、返回正确性和故障处理，不是完全免检。

基础 Gate 检查证据 ID、时间及来源标记；它接受整毫秒同桶，不自行证明语义谓词、跨机误差或传感器真实性。更强的 Harness/设备验证器应检查对象、关系、稳定、来源序号和命令前基线。把“基础 Gate 通过”写成所有物理条件被证明，是对保障范围的扩大。

面向新设备的验证器合同应把输入可信条件与世界谓词分开，并输出确认/明确不满足/缺证据、原因和引用。验证算法可以复杂，但判定过程需可回放，不能用模型重答替换原判据。
