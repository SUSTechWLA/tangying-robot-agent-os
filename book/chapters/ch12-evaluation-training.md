# 第 12 章 评测体系与后训练：先有刻度，再谈自训

> **版本口径**：本章包含 v0.6.0/v0.7.0 演进案例。代码片段、计数与实验按原时点解释；出版复核修正论证，不表示历史缺口均为当前状态。当前云边能力见第17章，来源与证据边界见出版说明。

> **本章的核心命题**
>
> **判据不能由被判者提供。**
>
> 一个能修改自己评分标准的系统，它的分数没有意义。

---

## 12.1 一句方法论：先有刻度，再谈自训

这个原则来自 commit `505af6577` 的标题本身：

> **编排层评测体系：先有刻度，再谈自训**

同一条原则在 `docs/architecture/post-training-pipeline.md` 里被写成一句话：

> **判据不能由被判者提供。** 账本量化、拒绝采集、评测、门禁——这四件事都必须是**确定的代码**；
> LLM 只做它真正擅长的：**诊断、提议、写代码**。

**为什么顺序不可选？** 因为收益和风险的分布不对称：

| 后训练能改善 | 后训练会恶化 |
| --- | --- |
| 成本、延迟、格式、离线可用性 | **域外与歧义处理明显更差** |
| | **拒绝的准确性风险最高** |

而**用 API 输出蒸馏会丢掉"该拒绝时拒绝"**——那恰恰是风险最高的那一项。

**所以顺序必须是**：

```
先评测（已做）→ 再蒸馏 → 最后才是 RL
```

### 一个重要的架构决定：脚本只是 CLI 外壳

`orchestration/eval/` 是这些脚本的实现仓：

| 子目录 | 内容 |
| --- | --- |
| `context_eval/` | 22 个模块：`runner`、`scoring`、`factorial_*`（10 个）、`stage_*`（5 个）、`gate.py`、`archive.py`、`episodes.py`、`report.py`、`client.py`、`dataset.py` |
| `system_eval/` | `engine.py`、`adapters.py`、`report.py` |

**评分逻辑在库里，不在脚本里。**

**为什么这条重要？**

> **门禁与训练读的是同一个刻度，不是两套。**

如果门禁脚本自己实现一遍评分，那么"训练时的分数"和"上线时的分数"会**漂移**——而漂移的方向通常是"上线时的更宽松"。

### ⚠️ 两个"没接线"的事实

**① `gate_agent_context` 在 Makefile 里没有任何匹配。**

```bash
grep -n "gate_agent_context" Makefile     # 无匹配，exit 1
```

**门禁脚本只能手工跑。** 全仓非 artifacts 引用只有三处（文档两处 + `orchestration/eval/context_eval/report.py`）。

**② `train/` 与 `training/` 不在 `Makefile:4` 的 `GO_TEST_PACKAGES` 里。**

所以 `make test-go` **不会跑**这两个包的门禁测试——它们是"**建好了但没进 CI**"的模块。

**教学要点**：这是"**没通电**"的第四种形态（前三种：无生产调用点、产物无消费者、数据无消费者）。

| 形态 | 例子 |
| --- | --- |
| 有实现，无调用点 | `agentruntime.RequestMutation` |
| 有产物，无消费者 | `deployment-policy.json` |
| 有传输，无解释者 | `remedyOutcomes` |
| **有测试，不在 CI 里** | `train/`、`training/` |

**第四种最隐蔽**——因为它看起来"有测试覆盖"。**而测试不在默认命令里跑，就等于没有。**

**可用的审计问题**：

> **这个测试，`make test` 会跑它吗？**

### 命名分工是一套纪律

| 前缀 | 含义 |
| --- | --- |
| `test-*` | **回归测试**（Go + pytest） |
| `eval-*` | **跑评测 / 报告** |
| `*-replay` | **离线重放已有响应，不调用模型** |

**最后一行是关键**：`eval-agent-context-replay` 让你在没有 API key 的情况下复现实验结论。

**教学要点**：**"跑评测"和"重放已有响应"必须分开命名。**

因为一个会调用模型的评测，它的结果**不可复现**（模型会更新）；而重放同一批响应，结果**逐位可复现**。

**把两者混在一个命令里，你就无法区分"结论变了"和"模型变了"。**

### 三条极有价值的引用

`docs/architecture/agent-evaluation-system.md` 里有三条对写评测系统的人极其重要的论证。

**① 零事故不等于充分安全证据**（`:283-291`）

对独立同分布的簇级事件，零事件时一侧 Clopper–Pearson 上界简化为：

```
p_upper = 1 − (α')^(1/n)
```

| 要把上界压到 | 至少需要独立同分布单位 |
| --- | --- |
| 1%（α=0.05，无多重比较） | **299** |
| 0.1% | **2995** |

> **五个种子即使全无事故，上界仍约 45.1%。**

而文档立刻划了边界：

> 这里的事件是**按给定暴露协议定义的簇级事件**，
> **不能转译成实机每动作事故率**。

**教学要点**：这是本章最重要的一条统计纪律。

**"我们跑了 5 次都没出事"给出的上界是 45.1%** —— 也就是说，真实的失败率可能高达 45%，而我们什么都没看到。

**② `demo` 命令不能直接当发布门禁**（`:353`）

> `demo` 成功完成报告生成则返回 0，**即使其中候选正确地被判 FAIL**。

**可以用的门禁是 `compare`**：

| 退出码 | 含义 |
| --- | --- |
| `0` | PASS |
| `2` | FAIL |
| `3` | INCONCLUSIVE |
| 非零 | 契约或输入错误 |

**教学要点**：

> **同一个 CLI 里，"命令跑完了"和"被测对象通过了"是两件事，必须用不同退出码区分。**

如果 `demo` 返回 0 被当作"通过"，那么一个**被判 FAIL 的候选**会被当作可上线——**因为报告生成成功了**。

**③ 维护者要看的三种页面**（`:353`）

| 页面 | 看什么 |
| --- | --- |
| **能力矩阵** | 阶段 × 层级 × 版本 |
| **实现比较** | 效应 / 成本 / 风险 / 证据 |
| **失败回放** | 事件 → 证据 → 独立判据 → 修复 |

（本次只提供 Markdown/JSON 文件视图，Web 工作台集成为后续工作。）

### 配对比较（这一节的关键）

| 比较 | 差值 | 95% CI | Holm p |
| --- | --- | --- | --- |
| JSON − 旧摘要 | **+65.83 pp** | [+51.67, +79.17] | **0.000092** ✅ |
| JSON − 分节 NL | +6.67 pp | [+0.83, +14.17] | **0.132812** ❌ |
| JSON − 决策排序 NL | +12.50 pp | [+1.25, +24.58] | **0.132812** ❌ |

原文特意写：

> 本报告采用**预定校正检验**，**不据正区间宣称 JSON 显著优于 NL**。

**教学要点**：这是本章最重要的一个方法论细节。

看第二行：**+6.67 pp，CI [+0.83, +14.17]** —— 这个置信区间**不包含 0**，也就是说在 95% 水平上"有差异"。

**但 Holm 校正后的 p = 0.132812，不显著。**

**为什么？** 因为做了多次比较。原文的处理是：**不因为 CI 不含 0 就宣称显著**。

**这个纪律比那个结论更重要**：一个做了 3 次比较的研究，它的显著性阈值必须收紧。**否则你会在 3 次比较里以约 14% 的概率至少误报一次。**

### 多轮行为实验：效率收益 ≠ 成功率提升

`context-episodes.v1`：**8 类问题 × 5 种子 × 4 表达 = 160 条独立轨迹**，最多 10 轮。

| 表达 | 安全完成 | 每任务轮数 | 无进展轮数 | 平均总 token |
| --- | --- | --- | --- | --- |
| 旧摘要投影 | 100.00% | 5.375 | 0.875 | **3849.1** |
| JSON 事实包 | 100.00% | 4.500 | **0.000** | 7789.7 |
| 分节自然语言 | 100.00% | 4.500 | **0.000** | 7538.9 |
| 决策排序自然语言 | 100.00% | 4.500 | **0.000** | 7540.7 |

**四组最终完成率没有差异（配对 p=1）**；轮数差 −0.875，族级 95% CI [−1.000, −0.625]，探索性 p=0.015625。

原文的结论：

> **本轮证明了该沙箱中的效率收益，没有证明最终成功率提升。**

**教学要点**：这是"**负结果也报**"的一个实例。

100% vs 100% 意味着**这个实验在成功率上没有任何区分度**。而作者没有把它包装成"我们的方案达到了 100% 成功率"。

**真正有区分度的是 token 消耗**——而 JSON 事实包的 token 是旧摘要的 **2 倍**（7789.7 vs 3849.1）。

**所以这一轮的净结论是**：JSON 更好，但**贵一倍**。而"更好"体现在**轮数和无进展轮数**上（0.875 → 0.000）。

### 消融（探索性）

从 `nl_decision` 删除 `attempts` 后能力仍 **61.67%**，差 **0**，p=1。

**原因**：验证语句仍明说"两次相同参数失败"，**历史信息存在冗余**。

同时删除记录的 scope / 时间 / supersedes 后，能力从 61.67% 降到 **52.08%**，差 **9.58 pp**，p=0.105469，**未达 0.05**。

**教学要点**：第一个结果说明**信息有冗余**（删一个仍有另一个）；第二个说明**有些信息组合起来才起作用**（但样本量不足以证明）。

## 12.5 第二轮：按决策环节选择表达

### 数据

`stage-cases.v1`：**640 案例**（train 160 / dev 160 / test 320），8 环节，每环节 train 4 族、dev 4 族、test 8 族，各 5 种子。

种子：`104729`、`130363`、`155921`、`196613`、`262147`。

**五组对照**：JSON / 分节 NL / 决策排序 NL / **无损混合** / **元数据标注混合**。

> **⚠️ 第五组不是等信息的纯格式组**——它是"确定性预处理增强，增加了推导结果"。

**这张表是本章最好的一张教学材料**，因为它展示了**表达能力是环节相关的**：

| 环节 | 最好的表达 | 最差的表达 | 差距 |
| --- | --- | --- | --- |
| 证据判读 | 元数据标注混合 80.00% | 决策排序 NL **5.00%** | **16 倍** |

**结论**：**没有一种"最好的表达"。"最好的表达"是环节的函数。**

**⚠️ 而这里有一个必须指出的危险信号**：

| 策略 | 危险提议率 |
| --- | --- |

| 策略 | 准确率 | 危险提议率 |
| --- | --- | --- |
| 元数据标注混合 | 85.00% | **0.31%** |

**"分环节策略"多出的 2.19 个百分点准确率，代价是危险提议率涨了 7 倍。**

**四条结论**：

**① 语法主效应在两个模型上都不显著**（+0.55 / +1.17）

**② 排列效应在两个模型上符号相反**（flash **+4.30**、pro **−4.30**）

点估计符号相反，但排列效应均未通过这里的 Holm 0.05 门槛，不能断言两模型真实效应相反，也不能仅凭一显著一不显著判断模型间差异。表达策略应按模型、任务和数据分布分别验证。

**③ 在语法、排列、标注三个表达因素中，只有 Pro 的标注项通过本轮 Holm 门槛（+5.08 pp）**；完整性因素也显著，见④。

而理论解释是：

> 确定性注释 `A = f(X)` **不增加信息**（`I(Y;X,A) = I(Y;X)`），
> 但**可降低有限模型的计算难度**。

**教学要点**：这是一个"**用信息论解释工程发现**"的漂亮例子。

从一个纯信息论的角度，`A = f(X)` 不提供任何新信息。但**模型不是理想决策器**——它要**计算**。

所以"把推导结果直接写出来"能帮到它，而**帮多少取决于模型的算力**。

本实验没有隔离算力、训练数据或架构因素，不能据此解释模型差异。信息论等式只说明确定性标注不增加信息；是否降低特定模型的计算难度仍是需要独立实验的假设。

**④ "删掉必要字段"是压倒性的**（+73.55 / +65.51）

**信息完整性比表达格式重要一个数量级。**

### 六个数学命题：把"能证明什么"划了界

这是本书里**把工程直觉形式化的难得样本**：

| # | 命题 | 边界 |
| --- | --- | --- |
| 1 | **无损表达对理想决策器等价**（下确界相等） | **但实际实验固定 π_θ** |
| 2 | **删掉必要信息会产生不可消除的错误**（上限 ≤ ½） | — |
| 3 | 相对确定问题集可定义**最小充分语义** | **不能由此推出最优措辞** |
| 4 | **通用最优表达不能仅从信息论推出**（构造两个决策器可使排序相反） | — |
| 5 | 有限候选集的条件性最优误差界（Hoeffding + union bound） | 见下 |
| 6 | **单轮上下文充分不自动保证长期闭环** | `\|V_H − V̄_H\| ≤ Hε_r + H(H−1)/2 · R_max·ε_p` |

**命题 5 的数字**：

本轮每环节仅 **4 个留出族**、**K=8**、**δ=0.05** 时，`2ε ≈ 1.70`——**截断到损失范围后仍是平凡界**（即这个界没有任何信息量）。

> **要使分布无关界 ≤ 5 pp，在该界和独立采样假设下，4,615 个独立族是保守的充分样本量估算，不是必要下限或实际功效分析。**

**教学要点**：命题 5 是本书里第三次遇到"研究者自己算出功效不足"（前两次：第 6 章的两轮、第 11 章的零事故上界）。

**三处共同的做法**：

> **把"我这个实验不足以证明什么"写成报告的一部分，而不是留给读者去发现。**

**命题 6 是留给未来的**：它说的是**单轮上下文充分，不保证长期闭环**。

而它的界 `|V_H − V̄_H| ≤ Hε_r + H(H−1)/2 · R_max·ε_p` 说明：

> **误差随轮数 H 增长，而且第二项是 H² 量级。**

**教学要点**：这是一个重要的警告——**单步误差较小不等于长期可靠**；这个上界含二次项，但不是实测误差必然按二次增长。若每一步真正无误，则不能用误差累积解释失败。**

### 最后一条边界（必须写进书）

> **"这是合成决策集和确定性工具沙箱上的真实模型测量，不是现网 OpsAgent 准确率，
> 也不是新增 Gazebo 或真机物理成功率。"**

---

> **统计补充**：重复轨迹不自动统计独立；不显著不证明无效，一显著一不显著不证明组间差异。上述公式依赖原报告的损失范围、采样与模型假设；误差上界不能当成实测性能。零失败与样本相关性的解释见附录D。

## 12.7 后训练流水线：`train/` 与 `training/`

### 两个包的职责完全不同

| | `train/` | `training/` |
| --- | --- | --- |
| 文件 | `gate.go`（268 行）、`gate_test.go` | `export.go`（283）、`quantify.go`（312）、`quantify_test.go`（179）、`refusals.go`（80） |
| **职责** | **晋升门禁**：比较两份评测报告，决定 checkpoint 能不能替换在役模型 | **量化与导出**：读账本 → 统计 → 切分 → 写 jsonl |
| 关键 API | `Compare(Report) Decision`、`Gate{MinExecutable, MinRefusals}` | `Ledger`（只读打开 SQLite）、`HarvestRefusals` |
| 判据 | Pareto + 用例集一致 + run-incomplete | 计数与桶划分 |

### 为什么不用 TrainAgent：一段值得全文引用的论证

`train/gate.go` 的包注释：

> A robot's closed loop works because **the world is the judge** and the world does not care what
> the policy wanted: either the cup moved or it did not.
> A training run is judged by **a metric**, and the run is **optimised against that metric**.
>
> **The thing being measured and the thing doing the measuring are the same system.
> That is not a risk to mitigate; it is the default outcome.**

**"被测量的东西和做测量的东西是同一个系统。这不是一个需要缓解的风险，这是默认结果。"**

评估把结论收窄成一句可引用的判词：

> **"LLM 可以设计训练的过程，但绝不能定义『什么算更好』。后者是它唯一也能移动的东西。"**
>
> "一切**有独立判据、短周期、可复验**的工作可以是 Agent。
> 训练没有独立判据，所以它不能是——**除非把判据切出去。**"

**另外两条不成立的理由也很有说服力**：

**① 时间尺度对不上**

> 恢复动作**秒级**，租约与 fencing 因此有意义；
> 训练 run 是**小时到天级**，"本仓库为短时物理动作建的整套安全机制在这里**没有对应物**"。

**② 失败形态更隐蔽**

| | 坏机器人动作 | 坏上线模型 |
| --- | --- | --- |
| 可见性 | **有界、有审批、有门禁** | **静默** |
| 表现 | 撞东西 / 停下 | "**只是开始给出稍差的计划，没有人报警，而评测分数可能还涨了**" |

**"评测分数可能还涨了"** —— 这句话点出了自证的核心危险。

### 「把判卷从训练里切出去」的三条规则

`train/gate.go`：

**规则 1：Pareto，不是加权分**

可执行用例与拒绝用例**都不许变差**，且至少一个变好。

> **"没有汇率。"**

原文：

> A weighted score lets a gain in "plans more requests" pay for a loss in
> "refuses requests it must refuse" …
> **A model that plans everything and refuses nothing is not 90% of a good model;
> it is a model that will execute a negation as an instruction.**

**"一个什么都规划、什么都不拒绝的模型不是好模型的 90%；它是一个会把否定句当指令执行的模型。"**

**规则 2：考试不能改**

`Compare` **拒绝比较用例集不同的两份报告**（数量不同、成员不同都拒，`ReasonDifferentCases`）：

> **"一个模型不能靠改了考卷来通过考试"**——这是最容易想到、也最致命的作弊路径。

**规则 3：没测过 ≠ 考砸了**

未完成的 run 记为 **`run-incomplete`**（`ReasonRunFailed`），**既不上线也不丢弃**：

> **当成 0 分会因为一次掉线丢掉一个好 checkpoint；
> 当成及格会上线一个从没测过的模型。**

**教学要点**：这三条规则各对应一种**具体的作弊/失误路径**：

| 规则 | 防的是 |
| --- | --- |
| 1 | **用一个维度的收益换另一个维度的损失** |
| 2 | **改考卷** |
| 3 | **把"不知道"当成"失败"或"通过"** |

**第三条与第 3 章的三值逻辑、第 6 章的 `run-incomplete` 是同一条原则。**

### 首次上线走另一条路

没有在役基线时，`Compare` **先于用例集比较**就返回：

> **"没有在役基线可供比较；首次上线的准入由绝对门槛决定"**

理由（`gate.go:126-135`）：

> 把"没有基线"报成"用例数不同"，会把读者引去找**谁篡改了用例集**。

**准入交给 `Gate{MinExecutable, MinRefusals}`——两个绝对门槛各自设线。**

> **"'没有基线'因此不会变成'什么都能上'。"**

**教学要点**：这是一个**错误信息设计**的细节。

"没有基线"和"用例集不同"是**两个完全不同的情况**，但它们的**技术表现**（无法比较）相同。

**如果报同一个错误，读者会去查错方向。**

### 去掉任一守卫，测试立刻变红

（已实测）

| 去掉 | 变红的测试 |
| --- | --- |
| 拒绝不回退 | `TestPlanningMoreCannotPayForRefusingLess` |
| 用例集一致 | `TestASmallerCaseSetIsRefused`、`TestASwappedCaseSetIsRefused` |

### 门禁脚本只有 32 行

`scripts/gate_agent_context.py`（32 行）：

**调** `orchestration/eval/context_eval/gate.py:compare_runs`

**参数**：`--baseline` / `--candidate` / `--baseline-format` / `--candidate-format` / `--output` / `--min-ability-delta`（默认 `0.0`）/ `--max-token-ratio`（默认 `2.5`）

**退出**：`sys.exit(0 if r["passed"] else 1)`

> **判卷逻辑不在脚本里**，脚本只是把**库函数接到 CI 的退出码上**——
> 这与"判据必须是被测者碰不到的确定代码"是同一条原则的两种表述。

> 流水线把这句话直接打在报告里，**而不是打印一张好看的表格让人去开训练任务**。"

**教学要点**：这是本书里"**工具应该说出坏消息**"的最好例子。

一个"友好"的流水线会打印：

```
✓ 处理了 64 条记录
✓ 生成 SFT 数据集
```

而它实际上是**空的**。

### 五个桶的划分：闭环契约贯穿到数据层

| verdict | 进哪个集合 | 为什么 |
| --- | --- | --- |
| `verified` | **SFT 正样本** | 唯一可信的正向信号 |
| `failed` | **负样本** | 可用于偏好对与挖评测用例 |
| `refused` | **拒绝样本** | **账本里不可能有**（被拒请求不落库），只能采 |
| **`unknown-outcome`** | **两半都不进** | 见下 |
| `unfinished` | 排除 | **还不是一个事实** |

**`unknown-outcome` 那一格的解释是本章最深刻的一条**：

> 当成成功 → **教模型做没人核对过的物理动作**；
> 当成失败 → **教它偏好回报快的动作，这是 reward hacking 的方向**。

**教学要点**：这与第 7 章奖励设计的第 2 条规则完全一致：

> **`UNKNOWN_OUTCOME` 既不给正分也不给负分，而是屏蔽该样本。**

**两条理由合起来是一个完整的论证**：

| 选择 | 后果 |
| --- | --- |
| 给正分 | 教模型"没人核对过的动作是好的" |
| 给负分 | 教模型"回报快的动作是好的"（**reward hacking**） |
| **屏蔽** | **不教任何东西** ✅ |

**"结果未知"的样本不能用来训练，因为它的标签是"不知道"。**

### 唯一规则

> **改动世界的步骤 + 动作后有新鲜观测 → `verified`；
> 任务成功但物理步骤没有观测 → `unknown-outcome`。
> 『步骤状态是 COMPLETED』不算证据。**

原文：

> 训练数据如果按"步骤报成功"来建，**教给模型的就是执行层拒绝相信的那个说法**。

**"教给模型的就是执行层拒绝相信的那个说法"** —— 这句话把第 3 章和本章连起来了。

**训练数据的判据必须是闭环契约的判据，不能是执行层的自述。**

### 两条已知缺口

**① 今天没有记录被拒绝的请求**

所以"拒绝集有多大"**取决于有人写了多少条**，而不是系统见过多少条。

补法很小（**把被拒请求追加进账本**），而它是：

> **"当前性价比最高的数据采集。"**

**② 去重必须按请求不按行**

参考部署里 **64 条任务只是 15 个不同请求**。

而同一请求同时成功和失败时，**成功的胜出**：

> **"模型没法同时学两个。"**

### 一条与门禁同源的纪律

`training/export.go`：

```go
dsn := "file:" + path + "?mode=ro"    // 只读打开
```

注释：

> **An export that could write would eventually be run against production**,
> and a training pipeline must never be able to change the record it is learning from.

**"一个能写入的导出，最终一定会被拿去对着生产跑。"**

**教学要点**：这是一个"**能力的防御性设计**"。

即使 `export` 今天的代码只读，它的连接**有能力**写入——而"有一天会被误用"是可以预见的。

**把只读性写进 DSN，让"误写"在结构上不可能。**

（这与第 6 章 `OpsAgent` 不持有执行端口、第 8 章 `Command` 没有来源字段是同一种手法。）

## 12.9 跨机学习：走到哪一步了

**这一节是本书里"已宣称 vs 已实现"最典型的一处。**

### 先纠正一个容易产生的联想

`tasks/experience.go`（639 行）**不是**跨机经验学习模块。

它是**面向非技术用户的任务体验投影**：`TaskExperience` / `ProjectExperience` / `ToolActivity` / `PolicyEvidence` / `RecoveryGuidance` / `ProfessionalDetails`。

做的是把技术任务 ID、意图状态和审计事件翻译成：

```
"机器人理解为…" / "现在在做什么" / "还能做什么"
```

**入口**：`GET /v1/tasks/{id}/experience`。

它对应的四个用户问题是：

> 1. What did the robots understand?
> 2. What are they doing now?
> 3. Which robot capability is being used, in ordinary language?
> 4. How can I change the task without losing completed work or creating an unsafe distributed race?

两个关键设计：

**① 版本化任务 + 保留已完成工作**

`tasks/reconcile.go BuildChangeSet` 把新计划与旧修订逐步骤比对，分成：

```
Added / Retained / Changed / Paused
```

"兼容"的判据是：

```go
prior.SemanticFingerprint == step.SemanticFingerprint
```

且对已 `StepSatisfied` 的步骤还要求 `basis.EvidenceValidity[prior.StepID]`。

**正在跑且发生变化/被移除的步骤进 `Paused`**（`:38-44`）——这就是第 3 章 `WAITING_SAFE_POINT` 的实现。

**② `SelectExperienceRevision`**（`experience.go:199`）保证：

> "**已批准但等待物理安全点的修订**比仍在执行的基础修订**更值得给人看**"

而**执行归属仍在 `CurrentRevision`**。

### 宣称在哪里

`docs/architecture/why-distributed.md` 把这一条列在分布式运行时架构的**优势**清单里：

> 多机协同、**跨机学习（A 机解决的故障 B 机受益）**

与"断网可用""安全本地闭环""数据留在本地"并列。

### 实现不在：五处证据

**① 三项能力被明确标为 reserved**（`core/agentcontract/contract.go`）：

| 能力 | 留给谁 |
| --- | --- |
| `completion.verification` | EvalAgent（可能否决完成声明） |
| **`experience.recording`** | **ExperienceAgent**（"consolidates skills and memory"） |
| `escalation` | EscalationAgent（"owns the human approval queue"） |

**② `core/agentcontract/memory.go` 自陈**：

> 三层记忆……**"Declaring them now is the whole of the forward-looking work for ExperienceAgent"**
> ——**"前瞻性工作的全部"就是声明它们。**

**③ `memory.go:88`**：

> "an ExperienceAgent fills; this version ships only an **in-memory** implementation"

**④ `agentruntime/opsagent.go` 的字段注释用的是未来时态**：

> "Ledger and Beads exist **for a future ExperienceAgent**."

**⑤ 组合根的设计目标**（`cmd/local-agent/agentruntime.go`）：

> "adding EvalAgent, ExperienceAgent or EscalationAgent later means adding a file here and a name in
> configuration" —— 即三个 Agent 都**还没有被添加**。

`grep -rn "ExperienceAgent" --include=*.go` 的全部命中**只有注释与接口声明，没有任何实现类型**。

而恢复 Agent 的"仍然不做的事"清单最后一条（`docs/architecture/recovery-agent.md`）：

> **"不跨机器人。** `edge-worker` 有云端事件上报但没有本地任务服务，**机队级监督需要新的云端 RPC**"

### 唯一存在的跨机路径是运维级的

`TANGYING_INCIDENT_DIR` 可以指向共享卷，"让一个诊断流程扫全部机器人"，配合 `diagnose_task.py --sweep` 得到**全机队的故障族分布**。

**而它共享的是「诊断知识」（故障族表 + 覆盖测试指针），不是「经验」（某次故障的处置结果）。**

### 诚实的分级结论

| 能力 | 状态 |
| --- | --- |
| 单机故障 → 事故包 → 分类 → 覆盖测试指针 | ✅ **已实现并实测** |
| 单机只读步骤自动执行 | ✅ **已实现并实测**（52 任务 27 条执行记录） |
| **故障族知识跨机共享**（同一份 Python 表） | ✅ **已实现**（靠代码分发，不靠运行时同步） |
| **事故包跨机汇总**（共享目录 sweep） | ✅ 运维级可用，**无代码强制** |
| **处置结果**（哪个动作真的修好了）跨机复用 | ❌ **未实现** |
| **跨机监督 / 机队级恢复** | ❌ **未实现，且文档自认需要新 RPC** |

**书里应写成**：

> **同一条学习路径上，「知识共享」已通，「经验共享」未通。**

**而未通的根因恰好是第 11 章那个空着的 `Verify`**：

> **没有独立的复验，就没有"这个动作在某些条件下真的有效"的可信记录，
> 也就没有可跨机复用的经验。**

**教学要点**：这是一个**跨章节的因果链**。

第 11 章的 `Verify` 端口留空 → 没有"动作是否有效"的记录 → 第 12 章的跨机经验无法积累。

**而第 11 章留空它的理由是"一个读不懂效果的复验器比没有复验器更糟"。**

**所以这是一个"诚实的留空"造成的"能力的缺失"** ——而这比"有一个错误的复验器"好得多。

## 12.10 训练数据导出与 `datasets/`

### `cmd/training-export`

**契约**写在包注释（`main.go:1-20`）里，是**三个问题按顺序回答、遇到坏答案就停**：

> 1. What is in the archive, in **distinct requests rather than rows**?
> 2. How much of it is actually usable — **confirmed by the closed loop**, and carrying a real orchestration plan?
> 3. What does the split look like, and **what is missing from it**?

### 退出码语义：最值得引用的一处设计

| 退出码 | 含义 |
| --- | --- |
| `0` | **写出数据集** |
| `1` | **账本还不足以支撑训练** |
| `2` | run 本身失败 |

原文（`main.go:16-20`）：

> The middle case is the common one and **it is not an error**: it means "collect more data",
> and **a pipeline that reported it as a crash would be ignored.**

**"把它报成崩溃，这个流水线就会被忽略。"**

**教学要点**：**这是"把状态编码进退出码"的教科书例子。**

| 做法 | 后果 |
| --- | --- |
| 数据不足 → 退出码 1（错误） | 每天都有一个"失败"的构建 → **被加入忽略列表** |
| **数据不足 → 退出码 1（一个正常状态）** | CI 可以区分"要收更多数据"和"流水线坏了" |

**"一个每天都会报警的告警等于没有告警"** ——这与第 3 章"从不消失的告警会被忽略"是同一条。

### 用法与格式

```bash
bin/training-export -db agent.db -out ./dataset
```

**参数**：`-db`（必填，**只读**）、`-out`、`-corpus`（每行一个请求，用于采拒绝样本）、`-provider`（默认 `deterministic`）、`-base-url` / `-api-key` / `-model`。

**导出格式**：

```
dataset/{sft,refusals,negative}.jsonl     # 每份带输入、参考输出、来源、评分版本与奖励维度
training/manifest.json                    # 各桶计数与被排除项
```

### ⚠️ `datasets/` 里有什么

**本次实测：只有 5 个 0 字节标记文件。**

```
.tangying-robocasa-assets-fixtures-complete
.tangying-robocasa-assets-minimal-complete
.tangying-robocasa-assets-objs-lw-complete
.tangying-robocasa-assets-tex-complete
.tangying-robocasa-env-complete
```

**真实数据不在仓库里**（`docs/operations/fresh-deployment.md`）：

> RoboCasa 仿真线（双机厨房）`make robocasa-install` → 会下载约 **4.2G** 到 `datasets/`。
> **本项目已清理掉这份数据**，需要时重新下载。

**书里引用 `datasets/` 时必须说清这一点**，否则会让读者以为仓库自带数据集。

**教学要点**：**"5 个标记文件"是一个很好的设计。**

它让"这些资产是否已准备"**可检查**（存在即为已下载），而**不把 4.2G 放进仓库**。

### 一道可以从表格下手的练习

给学生这张表（第二轮留出矩阵的一部分）：

| 环节 | JSON | 决策排序 NL | 元数据标注混合 |
| --- | --- | --- | --- |

问：**这两行说明了什么？如果你只能选一种表达方式给全部环节用，你会选哪个？为什么这个选择是错的？**

<details>
<summary>答案要点</summary>

**说明了什么**：

**同一个内容、同一批模型，换一种表达方式，通过率可以差 16–18 倍。**

| 环节 | 最好的 | 最差的 | 倍数 |
| --- | --- | --- | --- |
| 证据判读 | 80.00% | 5.00% | **16×** |
| 断点交接 | 92.50% | 5.00% | **18.5×** |

**而这两行的"最好"是不同的表达**：

- 证据判读：**元数据标注混合**最好
- 断点交接：**元数据标注混合**最好，但**决策排序 NL 也很好（87.50%）**

**如果你只能选一种**：看总体，**元数据标注混合 85.00%** 最高。

**为什么这个选择是错的**：

**因为"统一格式"在有些环节上非常差。**

| 策略 | 完整字段通过率 | **危险提议率** |
| --- | --- | --- |

| **开发集最佳统一格式** | 85.00% | **0.31%** |
| 开发集分环节策略 | **87.19%** | **2.19%** |

**"分环节策略"多出 2.19 个百分点准确率，代价是危险提议率涨 7 倍。**

**所以真正的答案不是"选哪个"，而是要问**：

> **这 2.19 个百分点的准确率，值不值 7 倍的物理风险？**

**加分点**：指出报告自己给出的最终做法——**逐环节选择 + 门禁回退**。

而"工具结果"环节的开发锁定候选（决策排序 NL）**未通过门禁**（82.50% vs JSON 100.00%），于是**保留 JSON**。

**这就是 `stage-policy.json` 里 `gate_passed.tool_result = false` 的来源。**

**再加分**：指出这个门禁的存在意味着——**"按环节选表达"不是"每环节都选分数最高的"，而是"每环节都选通过了门槛的"。**

### 五道练习题

**练习 1：为什么"报得更多"不能补偿"拒得更少"？**

> `train/gate.go` 用 Pareto 而不是加权分。原文说：
> "A weighted score lets a gain in 'plans more requests' pay for a loss in 'refuses requests it must refuse'…
> A model that plans everything and refuses nothing is not 90% of a good model; it is a model that will execute a negation as an instruction."
> 请展开这个论证，并说明它和一个"总分"指标的根本区别。

<details>
<summary>答案要点</summary>

**核心论证**：

**"多规划"和"少拒绝"不是同一维度的量，它们之间没有汇率。**

| 做法 | 后果 |
| --- | --- |
| 加权分 | 一个模型可以靠"多规划"补偿"漏拒" |
| **Pareto** | **两个维度都不许变差**，且至少一个变好 |

**为什么"什么都规划、什么都不拒绝"是最危险的**：

原文的判词是：

> **"它是一个会把否定句当指令执行的模型。"**

具体的：用户说"**不要**把杯子放到桌上"，一个不拒绝的模型会把它规划成"把杯子放到桌上"。

**而这是物理后果**——杯子真的会被放上去。

**与总分指标的根本区别**：

| | 总分 | Pareto |
| --- | --- | --- |
| 前提 | 各维度**可换算** | 各维度**不可换算** |
| 失效模式 | **用安全换覆盖率** | 无（拒绝一切改善） |
| 代价 | 危险 | **可能无法上线任何改进** |

**这是一个真实的取舍**：Pareto 更安全，但更严格。**而这个项目选了严格。**

**加分点**：指出"**没有汇率**"这三个字是这个设计的完整表达。

一个"汇率"的存在，意味着系统承认"覆盖率比拒绝率重要 x 倍"——**而这个判断不该由评测系统做，该由产品做（如果真要做的话）**。

**再加分**：指出去掉守卫后 `TestPlanningMoreCannotPayForRefusingLess` 会变红——**这个测试的名字就是这条规则的表达**。

</details>

**练习 2：为什么"未完成"既不上线也不丢弃？**

> `train/gate.go` 把未完成的 run 记为 `run-incomplete`，**既不上线也不丢弃**。
> 原文："当成 0 分会因为一次掉线丢掉一个好 checkpoint；当成及格会上线一个从没测过的模型。"
> 请说明这与项目里哪两条原则是同一条，并给出一个"三态"的通用模式。

<details>
<summary>答案要点</summary>

**同源的两条原则**：

1. **第 3 章的三值逻辑**：`UNKNOWN` 不等于 `FALSE`。"证据不在"和"事实不成立"是两种答案。
2. **第 12 章的训练数据分桶**：`unknown-outcome` **两半都不进**——当成成功会教模型做没人核对过的动作，当成失败会教它偏好回报快的动作。

**三态的通用模式**：

```
TRUE  → 采纳
FALSE → 拒绝
UNKNOWN → 挂起（不采纳、不拒绝、可重试）
```

**它在项目里出现的位置**：

| 位置 | 三态 |
| --- | --- |
| 世界谓词 | `TRUE` / `FALSE` / `UNKNOWN` |
| 训练门禁 | PASS / FAIL / **INCONCLUSIVE**（退出码 0/2/**3**） |
| 训练数据 | 正样本 / 负样本 / **都不进** |
| 训练 run | 上线 / 丢弃 / **`run-incomplete`** |
| 恢复复验 | `verified` / 失败 / **"已执行但未确认"** |
| 门禁 | 通过 / 拒绝 / **"没有在役基线"** |
| 对账 | `HAPPENED` / `NEVER_ACTED` / **`ABANDONED`** |

**加分点**：指出 `ONCONCLUSIVE` 需要一个**独立的退出码**，不能复用 PASS 或 FAIL。

`demo` 命令返回 0 即使候选被判 FAIL——**这正是"把状态压成两态"会造成的错误**。

**要教的是**：**"我不知道"必须是一个能被表达的状态，而且必须有一个与之对应的动作（挂起）。**

</details>

**练习 3：0 条正样本说明了什么？**

> 训练流水线的实测输出是 `可用正样本 0 条`，而原文说"**所以现在的正确动作不是训练，是修执行链**"。
> 请说明这两条具体原因，并解释为什么"0"是一个**有用的**输出。

<details>
<summary>答案要点</summary>

**两条原因**：

**① 23 条 verified 全是导航任务，计划是确定性生成的（空 bundle）**

→ 有结果、**没有编排信号** → 进 `verified-but-no-plan`

**② 5 条 LLM 计划的全部没成功**

**为什么"0"是有用的**：

因为它**指向了一个具体的行动**：

| 一个"好看"的输出 | 一个诚实的输出 |
| --- | --- |
| "✓ 处理了 64 条记录" | "**可用正样本 0 条**" |
| 让人去开训练任务 | **让人去修执行链** |

原文：

> 流水线把这句话直接打在报告里，**而不是打印一张好看的表格让人去开训练任务**。

**教学点**：

> **一个数据流水线的价值，不只在它产出了什么，还在它敢不敢说"我没产出什么"。**

**加分点**：指出这两条原因还各自给了一个改进方向：

- 原因 ① → **让 LLM 计划的任务真的跑成功**（修执行链）；
- 原因 ② → **补上被拒请求的采集**（原文称"当前性价比最高的数据采集"）。

**"0 条正样本"是一个诊断，不是一个失败。**

</details>

**练习 4：跨机学习为什么没通？**

> 「A 机解决的故障 B 机受益」被列在架构优势清单里，但实现不在。
> 请给出至少四条代码证据，**并指出它没通的根因与第 11 章的哪个设计有关**。

<details>
<summary>答案要点</summary>

**四条代码证据**：

1. `core/agentcontract/contract.go`：`experience.recording` **明确标为 reserved**。
2. `core/agentcontract/memory.go` 自陈：**"前瞻性工作的全部"就是声明它们**。
3. `core/agentcontract/memory.go`：**"this version ships only an in-memory implementation"**。
4. `agentruntime/opsagent.go`：**"Ledger and Beads exist for a future ExperienceAgent"**（**未来时态**）。

（还有第 5 条：`grep ExperienceAgent` 的全部命中**只有注释与接口声明，没有任何实现类型**。）

**根因与第 11 章的关系**：

**第 11 章的 `Verify` 端口在生产组合根里是空的**（`cmd/local-agent/main.go` 只设置 `Registry` / `Observer` / `Decider`）。

于是：

```
没有独立的复验
   ↓
没有"这个动作在某些条件下真的有效"的可信记录
   ↓
没有可跨机复用的经验
```

**所以跨机学习未通的根因不是"没写 ExperienceAgent"，而是"没有产生经验的数据"。**

**而第 11 章留空 `Verify` 的理由是**：

> "一个读不懂效果的复验器**比没有复验器更糟**，因为它会把'没看出问题'说成'已恢复'。"

**教学要点**：

> **这是一个"诚实的留空"造成的"能力缺失"——而它比"有一个错误的复验器"好得多。**

**加分点**：指出**知识共享（已通）与经验共享（未通）的区别**：

| | 知识 | 经验 |
| --- | --- | --- |
| 内容 | 故障族表 + 覆盖测试指针 | 某次故障的处置结果 |
| 传播方式 | **代码分发** | 需要运行时同步 |
| 状态 | ✅ 已通 | ❌ 未通 |

**知识可以随代码走，经验必须由运行时产生。**

</details>

**练习 5：为什么训练数据导出必须以只读打开数据库？**

<summary>答案要点</summary>

**注释原话**：

> **An export that could write would eventually be run against production**,
> and a training pipeline must never be able to change the record it is learning from.

**"一个能写入的导出，最终一定会被拿去对着生产跑。"**

**两个论证**：

**① "最终一定会"是一个关于人的判断**

即使 `export` 的代码只读，它的连接**有能力**写入。而"有一天有人会拿它对着生产跑"是**可以预见的**。

**② "训练不能改变它的学习对象"是一条原则**

如果训练流水线能改账本，那么：

| 后果 | 说明 |
| --- | --- |
| **自证** | 它可以"修正"不利于自己的样本 |
| **不可审计** | 你无法确定账本是不是原始记录 |

**实现**：

```go
dsn := "file:" + path + "?mode=ro"
```

**教学要点**：这与第 6 章 `OpsAgent` 不持有执行端口、第 8 章 `Command` 没有来源字段是同一种手法：

> **把约束实现为"结构上不可能"，而不是"检查后拒绝"。**

**加分点**：指出同一个包里的另一个设计也是同源的——**"去重按请求不按行"**（64 条任务只是 15 个不同请求）。

因为**同一件事被记了多次，不代表它是多件事**。

</details>

### 学生最容易误解的四个点

| # | 误解 | 纠正 |
| --- | --- | --- |
| 1 | "上下文表达方式（JSON vs 自然语言）是关键" | **语法主效应在两个模型上都不显著**（+0.55 / +1.17）。**"删掉必要字段"是压倒性的**（+73.55 / +65.51）。**信息完整性比表达格式重要一个数量级** |
| 2 | "准确率最高的策略就是最好的" | 分环节策略准确率 **87.19%** 但危险提议率 **2.19%**；统一标注混合 **85.00%** 而危险提议率 **0.31%**。**多 2.19 pp 准确率，代价是 7 倍物理风险** |
| 3 | "0 条正样本说明流水线坏了" | **它正确地说了实话。** 两条原因指向一个具体行动：**修执行链**，不是开训练任务 |
| 4 | "跨机学习已经实现了" | 架构文档把它列在**优势清单**里，而代码里 `experience.recording` **标为 reserved**，注释自陈"前瞻性工作的全部就是声明它们"。**知识共享已通，经验共享未通** |

## 12.12 本章小结

1. **判据不能由被判者提供。** LLM 可以做诊断、提议、写代码，但**不能定义"什么算更好"**——"后者是它唯一也能移动的东西"。

2. **三轮实验最硬的结论**（12,484 个请求 / 31,716,142 tokens / 0 协议失败）：**语法主效应两模型均不显著；排列效应两模型符号相反；信息完整性 +73.55/+65.51 pp 压倒性。** **规划环节在全部候选上 0.00%。**

3. **报告自己算出功效不足**（每环节 n=4，最小非零 p=0.125；要 ≤5 pp 需约 **4,615 个独立族**）。**零事故的上界是 45.1%（5 个种子）。**

4. **分环节策略准确率最高但危险提议率是统一策略的 7 倍。** 这个取舍**必须由产品决定，不能由分数决定**。

5. **"不能用最高候选分数掩盖这个负结果。"**

6. **训练门禁的三条规则**：Pareto（**没有汇率**）、考试不能改、**没测过 ≠ 考砸了**。

7. **0 条正样本不是失败，是一个诊断。** "现在的正确动作不是训练，是修执行链。"

8. **`unknown-outcome` 的样本两半都不进。** 当成成功 → 教模型做没人核对过的动作；当成失败 → **reward hacking 的方向**。

9. **知识与经验是两件事。** 故障族知识靠代码分发（已通），处置经验需要运行时产生（未通）——而未通的根因是**没有独立的复验**。
