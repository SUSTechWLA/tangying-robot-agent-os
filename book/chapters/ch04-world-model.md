# 第 4 章 感知、坐标与世界模型

**学习目标**：从采集构造语义事实；区分当前投影、历史与地图；处理跨机器人坐标和身份。

**先修知识**：第3章；向量和坐标变换基础。

**关键术语**：坐标变换、来源、语义实体、投影、地图修订

## 4.1 世界模型是一种受约束的投影

原始信号经标定、同步、重建和识别形成带来源的观测，再投影为实体、机器人、地图或资源状态。投影不消除测量误差；保留质量、缺失和时效比填零或猜实体更重要。

```text
采集 → 时间/内外参对齐 → 几何与语义 → 规范观测
                                         ↓
                      来源序号/版本校验 → 世界投影
                                         ↓
                       grounding / 完成验证 / 控制台
```

事件账本描述过去发生了什么；World描述哪些来源目前支持事实；地图保存空间制品及标定身份。三者更新频率和失效条件不同。

## 4.2 坐标变换的基本约定

用`T_AB`表示把B坐标变为A坐标：`p_A = T_AB p_B`，齐次坐标下连续变换按路径相乘。书中采用该记号解释，不改变具体SDK命名约定。

ROS tf2管理坐标随时间的变换关系，使用时仍应核对目标/来源frame、采集时刻和变换链。[官方tf2说明](https://raw.githubusercontent.com/ros2/ros2_documentation/jazzy/source/Concepts/Intermediate/About-Tf2.rst)是概念依据；变换可查询不自动证明标定质量。

项目重建契约使用world/m和`[x,y,z,qw,qx,qy,qz]`；已在world的实体不再施加一次部署偏移。底盘本体状态的局部到world变换另处理。毫米/米、xyzw/wxyz或两个局部odom混用，都可能生成数值合理但空间错误的计划。

## 4.3 语义对象与地图地点

点云不是任务对象目录。抓杯子还需要实体ID、类别、关系、置信度和可操作条件；房间名称也不是从未知几何自动生成的事实。

保存地图的版本、标定、区域与目标点提供导航依据；动态物体观测提供当前操作依据。将旧物体记忆直接用于当前抓取，可能把地图和传感器两个时间域错误拼接。

## 4.4 来源、一致性与冲突

| 异常 | 处理原则 |
| --- | --- |
| 同序号不同帧 | 拒绝身份修改，不当新观测 |
| 新序号但复用旧采集ID/时间倒退 | 检查回绕/启动纪元或拒绝 |
| 标定版本变化 | 不在旧任务中热换身份 |
| 相同实体在不同坐标被报告 | 核对来源与变换，不简单按最新到达覆盖 |
| 缺来源/位置/关系 | 保留缺失，按任务判定是否可继续 |

World revision增长不等于指定目标发生了正确变化。验证器还要核对该实体、机器人及其命令前来源基线。

## 4.5 跨机器人交接

A与B必须对同物料和共同坐标达成可核对解释；物体在交接区、稳定、A已不持有与来源新鲜是不同谓词。资源监护权由owner/fence维护，不能只根据物体位置猜测谁拥有执行权。

双机交接是可检验场景，不是任意多机器人世界共识。多传感器融合、动态实体关联和空间语义长期记忆需要各自的算法与评测，schema不会代替它们。

### 变换推演：平移与旋转不能交换

教学例子用 R 表示绕 z 轴正向旋转 90°，t=(1,3,0) 米。局部点 p_B=(2,0,0) 变到 A 为 `p_A=R p_B+t=(1,5,0)`。若错误地先平移再旋转，得到 `R(p_B+t)=(-3,3,0)`，结果不同。

实际链通常包括 sensor→body→odom→world，每条变换需对应采集时刻和标定版本。明确已在 world 的实体无需再施加 body/部署偏移；本体局部状态则按它自己的链转换。对同一物料，跨机器人位置比较先统一 frame，而不是先比较数值。

## 4.6 世界快照的数据结构与读取边界

当前 `world.snapshot.v1` 用 Robots、Entities、Resources、Sources 表达不同对象，并带 worldId/revision、eventCursor 与健康信息。

| 对象 | 关键语义 | 使用者 |
| --- | --- | --- |
| RobotState | 位姿、活动、持物、停止、故障与证据 | 准入、规划与控制台 |
| EntityState | 对象身份/类别/关系、姿态、稳定计数与证据 | grounding、抓放和交接验证 |
| ResourceState | owner、fence、期限与来源 | 协调和执行权检查 |
| SourceState | 采集/接收、来源序号、变换版本和异常 | 新鲜度、重复和冲突判断 |

“未知”可存在于字段缺失、来源状态或关系不确定中；不能统一用零位姿和空持物解释。机器人没有报告 held 与它明确报告未持物，是不同情况，设备合同需保留区别。

读取快照时先确定要回答的谓词，再选择对应对象和来源。规划可能允许低频地图知识，抓取必须使用适用当前观测；资源 owner 与物理持物也应分别读取。一个快照容器并不让这些事实具有相同刷新率或相同一致性。

实现见[世界类型](../../core/worldmodel/types.go)。几何融合、物体识别、关联和动态地图算法需要独立实现；规范数据结构只提供共同表达。
