# 第 5 章 能力目录、工具契约与设备适配

**学习目标**：设计可验证能力；分清描述、可用性和授权；以语义边界接入异构本体。

**先修知识**：第2–4章；接口与schema。

**关键术语**：能力契约、effects、catalog revision、Profile、Backend

## 5.1 从函数调用到能力契约

工具不是任意可调用函数。可靠工具要声明输入、输出、版本、effects、资源、取消/期限、操作身份及验证方式。描述“这个函数会抓取”不足以说明它何时可用、是否产生副作用、失败后如何判断。

| 契约项 | 示例问题 |
| --- | --- |
| 输入/目标 | 是哪个实体、在哪个坐标和场景？ |
| 效果 | 只读，还是改变世界/配置？ |
| 资源 | 需要哪台机器人、物料或空间的独占权？ |
| operation | 长操作如何命名、查询、取消、持久恢复？ |
| verification | 哪个独立读回或后置条件证明结束？ |

能力目录是规划可见范围，不是审批凭据。安全字段由确定性层生成和校验，模型只产生受约束业务候选。

## 5.2 描述、available与执行准入

Profile.tools表达型号承诺实现的集合；Runtime.available反映当前handler、反馈、使能与故障条件。执行时还要满足批准、目录版本、目标、资源、deadline、lease及安全profile。

```text
可描述 → 当前可用 → 已批准 → 执行前仍有效 → 结果已验证
```

这五个状态不能合为READY。缺handler或physical_ready未成立时，PluginBackend不会将物理工具开放。

## 5.3 模型可见的状态

planningFields只投影规划需要的结构化语义信息。原始图像、IMU、点云和栅格在设备/专用服务处理；适用的模型可以读取选定证据，但不是把所有原始流追加进上下文。

Schema拒绝未知字段、非法数值及不支持组合；Schema合法也不代表目标可达或契约已满足。参数、grounding、实时就绪与验证是后续独立门禁。

## 5.4 异构Profile与Backend

RobotProfile保留robot/adapter/model身份、原生关节及SI限位、末端、传感器/标定、动作键和工具子集。Backend把语义调用转换为本机SDK/ROS/控制器，不把厂商类型传播到任务层。

一个固定臂不必冒充移动机器人；传感器平台可以只提供观察与停止接口。构造factory、读readiness或发现设备不得顺便使能运动。IK、碰撞、载荷与制动仍是型号实现责任。

## 5.5 长操作与动态能力变更

建图可能跨多次采集，operationId需要稳定，完成制品需可读回。取消请求只表示请求停止，operation终态和实际停止反馈仍须核对。

目录或标定在任务期间变化，应使旧批准内容失效或停止重新登记；不能让新handler承接旧目录哈希的命令。新增工具不只改一句描述，也必须增加验证、拒绝、未知与停止路径。

## 5.6 工程案例

为“更换夹具”接入新Profile时，先闭合旧持物/任务状态，再更新末端、驱动、动作限值、标定和验证器，重启登记与重新规划。直接修改工具名字而沿用原TCP和抓取验证，可能让软件协议看起来成功而实际目标错位。

## 5.7 工具执行通道的逐层责任

可以将一次调用分为候选、业务参数、grounding、批准定义、执行身份、Runtime 准入、Backend 实现、结果和验证。不同层拒绝的原因应分别记录。

| 阶段 | 应拦截的例子 |
| --- | --- |
| 模型可见目录 | 未授权工具、观察者可写工具 |
| 参数/Schema | 错类型、未知字段、夹带安全字段 |
| grounding/计划 | 不存在的目标、错坐标、目标覆盖不足 |
| 批准/执行定义 | 超出批准动作、目录或参数漂移 |
| Runtime/资源 | 错设备、旧 fence、超期、缺反馈 |
| Backend/验证 | 不支持/实际执行失败、未知、陈旧证据 |

统一语义接口不禁止设备内部使用坐标或低层动作。关键是模型可见层与受信执行层的边界：模型选择业务能力，执行层根据实际设备和观测物料化低层命令，并承担准入与证据责任。

外部 Agent/MCP 桥接也应继承这条通道。暴露一个工具名称不自动暴露电机接口；网关身份与批准范围不能由外部文本伪造。审查新桥接时同时看目录、调用实现和拒绝测试。
