# 第 16 章 机器人 Agent 与 Coding Agent：33 项工程对照

本章比较风险与机制，不把两类系统划成“文本可逆”与“物理不可逆”两个绝对类别。Coding Agent 可以操作网络服务和生产数据，机器人也可以执行只读诊断。**重试、授权与证据要求应由工具效果决定。**

## 16.1 33 项对照

表中 Coding Agent 是常见工作情境，不代表某个产品的统一能力；机器人栏描述本项目机制及其边界。第1–15章包含历史案例，当前云边机制见第17章。

| # | 维度 | Coding Agent 的考量 | 机器人 Agent 的考量 | 本书章节 |
| --- | --- | --- | --- | --- |
| 1 | 世界对象 | 文件、进程、网络服务及用户业务状态 | 机器人、物体、人员与环境 | 1 |
| 2 | 状态来源 | 读取文件获取当次字节；服务状态也需观测 | 传感器投影只能部分描述世界 | 4 |
| 3 | 观测成本 | 读取通常便宜；大型扫描、远程查询也有成本 | 传感器带宽、遮挡、采集时延和主动观察成本 | 1、10 |
| 4 | 新鲜度 | 并发修改、缓存和快照仍会过期 | 采集时刻、序列与来源健康须显式记录 | 3、4 |
| 5 | 缺失含义 | ENOENT 表示该路径在当次查询中缺失，不代表外部对象不存在 | objects=0 可能是遮挡、grounding 或地图身份问题 | 4、7 |
| 6 | 可逆性 | 已记录文件常可回退；发布、通知和迁移可能不可逆 | 抓取、相对运动等可能不可逆；也存在可恢复动作 | 3 |
| 7 | 重试成本 | 消耗资源；外部副作用须审查 | 可能重复已完成动作，带来碰撞或掉落 | 1、3 |
| 8 | 未知结果 | 网络写入、部署超时同样可能结果未知 | 下发后失联尤其需要对账，禁止自动重放未知物理动作 | 3、8、9 |
| 9 | 幂等性 | 按具体工具定义，不能由“文本操作”概括 | 需明确逻辑命令、效果、参数和去重持久性 | 5 |
| 10 | 并发范围 | 工作区、文件和外部服务需要相应锁 | 引用的运动锁覆盖一个 Executor/身体，不是全机群，也不自动覆盖驱动后台运动 | 5 |
| 11 | 超时语义 | 超时不一定终止远端服务效果 | 调用期限收紧工具期限；取消回执仍需确认控制器停止 | 5、8 |
| 12 | 完成判据 | 测试与业务验收；测试也可能覆盖不足 | 动作后证据确认后置条件，并保留判定来源 | 3 |
| 13 | 声明与权威 | 工具元数据和外部验证是两层 | Runtime 的 MutatesWorld 声明约束门禁，但不是独立传感器可信性的证明 | 3、4、5 |
| 14 | 不知道 | 缺失信息和三值逻辑同样适用 | UNKNOWN 与 FALSE 分开，避免把没看见误当未发生 | 4 |
| 15 | 失败分类 | 部署/数据系统也按恢复动作分类 | closedloop 的八类提供保守处置，未识别物理失败不得乐观重试 | 3、11 |
| 16 | 人工处置 | 权限、发布和数据损坏也可能要求人决定 | StepReconciliation 记录一次性对账；软件记录不能代替现场观察 | 3、9 |
| 17 | 状态寿命 | 开发任务可跨会话，服务状态可长期存在 | 长期任务需持久化、迁移和重新验证物理状态；不是已证明“运行数年” | 8、9、13 |
| 18 | 崩溃恢复 | 文件可能持久，外部副作用可能未知 | 从持久账本恢复 Uncertain，不能从进程重启推断身体复位 | 3、9、11 |
| 19 | 不执行记录 | 拒绝、审批和审计也有价值 | 记录观察后不动作、缺证据和禁止重试，避免沉默被误读 | 6、11 |
| 20 | 多 Agent 动机 | 上下文、并行、权限与独立评审 | 同样考虑这些目标，尤其限制物理写权限与证据职责 | 6、17 |
| 21 | Agent 交互 | 事件、消息或直接调用均是设计选择 | 第6章 agentruntime 采用事件；第17章云端 Assist 是另一条受限接口 | 6 |
| 22 | 隔离边界 | 工具白名单、权限、进程与网络隔离 | 字段白名单防误接线；恶意代码隔离还需进程/凭据/网络边界 | 6、17 |
| 23 | 观察者失效 | 监控沉默也可能被误读为健康 | 启动扫描持久记录并暴露 DEGRADED；仍需外部监控 | 6、11 |
| 24 | 危险建议 | 建议须通过权限与发布约束 | AutomaticRetryForbidden 不应在下游被软化 | 3、6 |
| 25 | 规划依据 | 工作区、依赖、服务和用户约束可能不完整 | Plan 结合 request、intent 与 world，不能只复用旧位置 | 7 |
| 26 | 规划后变化 | 其他用户或进程可修改文件与服务 | 人员或物体可改变世界；执行前重新核验版本和前置条件 | 7 |
| 27 | 身份 | 路径、链接、容器及版本须辨别 | 物体/房间/地图/机器人身份与已委托位姿分开 | 4、7 |
| 28 | 失败传播 | 配置错误也会伪装成下游错误 | 计划、地图、绑定问题都可能以 objects=0 出现 | 4、7 |
| 29 | 安装与启动 | 安装通常不等于服务已经可用 | 项目实机安装等待证书、配置和标定；仿真路径另有启动入口 | 13 |
| 30 | 健康检查 | 服务常区分 liveness/readiness | 安全停止可保持存活但禁止新任务，不能因急停反复重启 | 13 |
| 31 | 检查清单 | 发布和变更评审同样需要 | 清单是证据索引，不是按分数自动认证 | 13、附录B |
| 32 | 发布与放行 | 部署还可能需要业务/权限/合规验收 | 软件发布与实机放行独立；30次试验不自动授予 PHYSICAL_GO | 10、13 |
| 33 | 失败处置 | 可涉及服务中断、数据丢失或外部损失 | 可能持物停住、通道受阻；现场负责人需有明确处置路径 | 11、13 |

## 16.2 三组需要分清的边界

### 工具回执与证据

工具可以携带证据引用。问题不在于返回者“属于工具”，而在于证据有没有可信来源、采集语义、身份和独立于动作自述的判据。Runtime 元数据决定门禁是否需要证据，不能单独证明传感器没被伪造。当前 Gate 的同毫秒接受策略也不能证明严格因果顺序（第3章）。

### 代码约束与运行隔离

`TestOpsAgentHoldsNoExecutionPort` 一类字段测试帮助防止受信代码误接线。它不阻止同一进程中的恶意代码导入其他包、读取密钥或发网络请求。需要对不受信工具或插件隔离时，还须配置进程身份、设备访问、文件权限和网络策略，验证具体绕过路径。

### 软件一致性与物理一致性

数据库 CAS、Outbox 和 journal 分别保护不同对象。事件只有一条不表示执行器只动一次；数据库回滚不撤销物理动作。跨进程测试验证被注入的故障时序，不能证明任意掉电与失联情况下的效果恰好一次。

## 16.3 设计评审的五个入口

1. **完成判定**：回执、采集序列、后置条件和判定者分别是谁？缓存和同桶时间能否伪造成功？
2. **未知结果**：动作可能已执行时怎样持久阻塞重放、重新观测和对账？重启是否清掉禁令？
3. **审计恢复**：能否关联任务、版本、步骤、命令、证据、授权和恢复动作？能否区分拒绝与未考虑？
4. **模型权限**：工具白名单、schema、作用范围和最终准入由哪层执行？模型文本能否伪造审批身份？
5. **失效隔离**：观察者失联、模型超时、设备重启和旧持有者恢复后会发生什么？哪些现场状态必须由人处置？

这些问题没有经过验证的综合评分阈值。逐项记录代码、测试、未验证条件和负责人；不能凭“五问通过”宣布生产安全。测试应覆盖实际接线，必要时在隔离仿真中故意移除约束，观察是否导致具体错误，而不是只检查测试数量。

## 16.4 选择部署形态

| 场景 | 可选形态 | 必须保留的责任 |
| --- | --- | --- |
| 单机、现场监督、有限任务 | 本地 Agent 与 Runtime；逻辑分层可同机部署 | 授权、结果未知、证据与实体安全 |
| 单机但有复杂推理 | 本地执行闭环 + 本机小模型或云端 Assist | 网络失效策略、数据最小化、云端返回无新增物理权限 |
| 多机统一任务和审计 | Fleet 系统 Agent + 每机器人 Worker/Runtime | 单写、资源所有权、持久对账和跨域恢复 |
| 安全关键或无人值守 | 由风险评估和设备要求决定 | 本书机制不是完整的安全认证方案 |

多进程增加部分失败与运维成本，高算力增加推理能力；两者都不能代替闭环。使用同一决策内核的两套 Harness，可以复用机制并保持权限差异，具体见下一章。

## 16.5 教学要点与练习

- 共性：两类 Agent 都需要按副作用判断幂等、未知结果、审批、持久化与隔离。
- 差异：机器人将这些机制连接到持续变化、部分可观测的物理身体，停止和恢复需要现场证据。
- 限制：受信代码的结构约束、传感器可信性、数据库一致性和实体安全是不同责任。

**练习**：部署工具超时后，服务可能已经更新；抓取工具超时后，杯子可能已拿起。设计共同的命令身份与未知结果状态，再列出各自的对账证据。

**答案要点**：两者都持久化命令 ID、目标版本、下发状态和回执，阻止盲目重放。服务对账可查询实际部署版本与流量健康；抓取对账需当前持物和物体位置观测，不能从历史成功或重启推断。若对账仍未知，继续阻塞并交由相应负责人。
