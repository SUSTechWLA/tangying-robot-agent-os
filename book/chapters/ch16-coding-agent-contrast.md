# 第 16 章 软件 Agent 与机器人 Agent 的设计比较

**学习目标**：按工具效果比较系统；迁移通用工程机制；识别物理特有证据与控制要求。

**先修知识**：第3、5、6、8、12章。

**关键术语**：工具效果、可逆性、最小权限、权威、证据、机制迁移

## 16.1 比较对象与适用口径

软件Agent可以改文件，也可以操作部署、数据库和外部服务；机器人Agent可以运动，也可以只读诊断。因此不能简单将软件归为可逆、物理归为不可逆。比较的单位应是工具效果、权威对象、恢复方法和证据。

本章是设计对照，不是任何产品当前功能表；具体产品或SDK应另核对版本。项目借鉴的接口和历史审计仍保留在原报告。

## 16.2 可迁移机制

| 机制 | 软件场景 | 机器人场景 |
| --- | --- | --- |
| 目录/最小权限 | 限定文件、API和业务工具 | 限定能力、设备和效果 |
| 不可变批准范围/版本 | 固定变更、部署或工具权限范围 | 冻结具体能力计划，或冻结允许边缘细化的目标包络 |
| 有界决策循环 | 限制调用/成本与反复修正 | 加上期限、资源和物理就绪 |
| 归档/回查 | 保留完整结果与来源 | 同时保留Unknown和禁止重放guard |
| 幂等/日志 | 查询既有提交或远端效果 | 查询journal并按现场证据对账 |
| 角色协作 | 分离实现、测试、评审责任 | 分离执行、诊断、提案、独立复验 |

迁移机制时要保留原权威边界。例如模型摘要能帮助解释，但不能成为正式部署版本或持物状态的独立真相。

## 16.3 证据与重试的差别

文件变化可用diff/测试校验；部署要核对实际服务与流量，网络响应丢失也可能留下未知结果。抓取则需要当前持物、对象与来源证据。

工具越过外部副作用边界，越不能凭超时盲目重试。持久化请求和回执是必要材料，是否可重发还取决于幂等语义、实际效果和对账接口。

## 16.4 共享上下文不是共享权威

不同角色可以使用不同长度的模型视图，却引用同一不可变定义和证据作用域。归档哈希发现内容变化，不是审批签名；恢复会话也不赋予重放未知物理命令的权利。

目标委托可类比软件Agent在批准的工作范围内自行拆解：父目标不变，每代子计划和效果有独立身份。机器人还要把重复写次数、未知动作、到达/持物证据与实时claim确定性校验。给模型最近8项进度是输入策略，完整历史用于额度和恢复的事实不能一起截短。

本项目managed projection、作用域context_read、ModelRequest原文和cloud-edge Basis分别处理输入、一致性、审计与执行身份。将它们只称“记忆”会隐藏实际职责。

## 16.5 系统评审问题

指出每个工具效果、允许范围、失败分类、证据来源、版本及重试条件；指出隔离是字段门禁、同进程权限还是进程/网络边界；指出哪一层能拒绝或实际停止。

这些问题适用于两类Agent，但机器人还必须交付型号感知、控制、负载和停止验证。LLM规模和角色数不会替代这些工程责任。

## 16.6 用故障场景检验机制迁移

设软件 Agent 部署服务时远端已切换流量，但回执丢失。它应查询既有部署身份和当前状态，而不是立即重复创建新部署。机器人抓取后回执丢失也需要查询 journal/观测，但当前持物、负载和停止条件使对账更具体。

| 共同问题 | 可迁移方法 | 机器人附加条件 |
| --- | --- | --- |
| 超时 | 保留命令身份与效果未知 | 同物、当前位置与控制反馈 |
| 多角色协作 | 提案/执行/验证分离 | 观察者无运动权限，实际停止路径 |
| 上下文过长 | 完整来源、有界视图与回查 | unknown、冲突、资源/世界基线 |
| 版本变化 | 不可变内容与兼容判断 | 目录/标定、夹具、本体和地图 |
| 回滚 | 恢复可解释的软件状态 | 不撤销实际物体位置或载荷 |

设计比较时固定工具效果和权限，再讨论组织差异。把分角色系统的额外传感器/预算优势全部归因于 Agent 数量，会得到错误结论；反过来，也不能仅凭相同模型判断两个系统等价。

因此软件和机器人团队能够共享日志、协议、测试和上下文工程；实际完成判据及控制/证据实现仍需各自领域知识。
