# 第 1 章 分布式机器人 AgentOS 的问题域与基本约束

**学习目标**：区分任务、决策、控制和安全；从物理效果推导系统分层；识别可迁移的软件机制。

**先修知识**：进程、网络请求与基本物理量。

**关键术语**：后置条件、控制周期、物理副作用、失败关闭

## 1.1 从业务目标定义系统

机器人 AgentOS 将用户目标转换为受约束的决策与执行，并记录足够证据解释完成、停止和恢复。这里的 AgentOS 是系统组织方式：任务服务、决策运行时、设备运行时及机群控制面；它不等于硬实时操作系统或安全控制器。

软件工程师关注状态、并发与恢复；机器人工程师关注感知、控制与物理效果；研究者关注假设、判据与实验。三者围绕同一个问题协作：系统依据什么宣布目标已满足？

贯穿例子是“从客厅到厨房拿杯子，放入盘中，再返回”。业务目标至少包含对象、目的地、顺序、完成条件和权限。只发送一次pick请求无法表达整项业务。

## 1.2 四个容易混淆的层次

| 层次 | 典型输出 | 完成该层不代表 |
| --- | --- | --- |
| 目标理解 | 结构化目标及约束 | 已形成可执行计划 |
| 规划/批准 | 冻结能力计划，或允许边缘规划的目标合同 | 设备已执行 |
| 执行 | 控制器/工具回执 | 指定物理后置条件已成立 |
| 验证 | 有来源的观测与判定 | 范围之外的长期可靠性 |

例如夹爪到达闭合位置，与正确杯子稳定被持有，是不同事实。任务完成需要后者对应的证据，不应只复用前者的成功字段。

## 1.3 时间、信息与物理效果

控制周期给出确定的时间预算。频率f的周期为1/f；100Hz对应10ms，但实际机器人有电流、关节、导航、策略等不同环路。平均模型延迟不能证明最坏时限，首token到达也不等于决策完成。

感知输入需要采集、对齐、融合和语义解释。假设两相机各输出640×480 RGB三字节、深度两字节、30fps，未压缩数据率为`2×640×480×(3+2)×30 = 92.16 MB/s`（十进制，不含开销）。能否上传取决于实际链路与任务，不是普遍禁止原始数据；时间敏感处理通常保留在设备侧。

物理动作不能由数据库回滚。网络超时可能发生在动作前，也可能发生在动作后。请求失败并不告诉调用者杯子有没有移动，必须保存这种不确定性。

## 1.4 分层的工程推导

```text
目标与批准：用户、任务服务、不可变版本
决策与协调：Agent、能力目录、世界投影、资源
执行与采集：设备Runtime、本机控制器、传感器
验证与追溯：后置条件、来源、命令日志、事件账本
```

当前实现将云端粗目标与本机细规划分开：云端保留全局分工与批准，边缘在工具、参数、效果、次数和期限包络内编排能力，Runtime/控制器负责物理闭环。Local 和 Fleet Worker 是接入同一个边缘目标宿主的两种部署入口；同一机器人只启用一个控制入口。模型推理可在云端或本地运行，推理位置不改变任务权威。部署选择应由时限、失效域、带宽、运维和规模解释。

设备停止还受惯性、重力、负载及制动方式影响。通信ACK不是实际停止反馈，软件链不能替代适用的实体保护。工程方案须说明失联时停止、减速或保持的条件与证据。

## 1.5 学会提出边界问题

评审一个系统时依次询问：动作改变什么？目标由谁批准？权威状态保存在哪里？哪些证据会过期？进程中断后哪些结果未知？继续的条件是什么？一个有限任务成功，只支持对应环境与版本。

本书用Tangying作为可检查实现，不要求读者复制其包名。可迁移内容是职责、协议和判据；不可直接迁移的是设备限位、地图、标定、停止指标与现场放行。

## 1.6 控制、决策与失效域的设计方法

控制系统可用 `观测 y(t) → 控制器 → 执行量 u(t) → 被控对象` 解释；任务系统在更慢尺度选择目标和技能。二者通过接口耦合，但目标层的“继续”不能直接替代控制层的实际反馈。

| 尺度 | 处理问题 | 失败时保留的事实 |
| --- | --- | --- |
| 控制环 | 电流/关节/速度跟踪与约束 | 实际反馈、控制模式、停止/保持状态 |
| 技能环 | 导航、抓放、建图与取消 | operation、派发阶段、完成/未知 |
| 任务环 | 顺序、条件、资源和批准 | 目标/版本、阶段、批准和依赖 |
| 运行治理 | 维护、升级、容量与事故 | 配置、责任、证据和范围 |

周期预算可以分为采集、排队、计算、传输和执行各项，并考虑抖动。平均值适合容量分析，期限保证还需最坏情况和适用调度条件。外部模型故障只应影响依赖该模型的新决策，不应抹掉已有执行结果或设备停止能力。

判断是否需要分布式部署，可先写设备数量、任务跨度、带宽、网络质量、现场维护和故障隔离需求。单机闭环足够时不必引入队列和多副本；多机部署则必须承担身份、版本、消息和资源一致性的额外工作。分层价值来自可解释的职责，不来自进程数量。
