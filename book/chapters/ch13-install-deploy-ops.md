# 第 13 章 部署、升级与运行治理

**学习目标**：建立版本和配置基线；区分就绪与授权；形成可追溯升级和运维流程。

**先修知识**：第8–10章；容器、网络和备份基础。

**关键术语**：配置基线、身份、升级兼容、SLO、备份、运行治理

## 13.1 部署是一组可核对配置

软件提交/tag、容器、Python/Go包、模型路由、机器人/适配器、标定、地图、目录、安全profile、证书和数据库schema共同影响行为。只记录“v0.7.0”不足以复原现场。

本版代码复核固定9e5aebae，正式软件tag固定30df0602，书籍版次另计。发布标签不能被移到新书稿提交以制造一致。

## 13.2 三类部署边界

| 部署 | 持久对象 | 关键检查 |
| --- | --- | --- |
| Local | SQLite任务/执行、地图与私有配置 | 单派发者、Runtime、unknown/持物 |
| Edge Worker | 执行库、completion outbox、设备凭据 | shared DB、claim/Basis、Runtime目录 |
| Fleet | MySQL事件/任务、Redis租约/队列、World checkpoint | leader incarnation、资源归属、pending收尾 |

数据库、队列、世界投影和物理状态不是一个全局事务。多副本HA需要单独设计与验证，不能只增加容器副本。

## 13.3 身份、网络与数据最小化

设备HTTP凭据、FleetGateway mTLS、Runtime mTLS、安全字段和模型key有不同用途。Assist推理凭据不授予设备数据面或动作权限。开发loopback明文不适用于实机生产配置。

保持高频处理在设备，上传任务需要的结构化观测/选定证据。公开trace不含Authorization，也不代表全部业务数据可公开；权限、保留期和脱敏是独立要求。

## 13.4 升级过程

建立版本基线→确认活动任务与持物→一致备份→验证兼容/迁移→停止旧派发/旧leader→切换→核对Runtime/目录/地图/未决命令→执行对应范围验证→记录结果与回退条件。

不理解v2 pending gate的旧coordinator需部署排除。代码有回执恢复不表示混版本安全；当前没有自动二进制版本联锁。

回退软件版本前核对数据兼容，不能借回退清空journal或重放未知命令。活跃SQLite/地图文件应用一致性备份，不普通复制后假定完整。

## 13.5 运行指标与责任

观测过期、claim/lease失效、队列积压、丢事件计数、pending年龄、未闭合命令、模型预算/超时、数据库失败与资源冲突，是比单一在线数更具体的指标。

SLO要说明业务范围、指标、统计窗口和处置责任。停止响应需实际设备测量，不能用软件ACK延迟替代。附录H给出交接、升级和事故模板。

## 13.6 案例：页面健康但不可工作

healthz正常表明服务存活；readiness可能因历史未确认动作、传感器、地图或批准条件失败。正确处理是定位阻塞来源并按证据对账，而不是重启或删历史让首页变绿。

## 13.7 启动、健康与控制端切换

启动顺序按依赖组织：配置与数据身份 → 存储/队列 → Runtime/设备反馈 → 任务/边缘服务 → 世界/目录 → 控制台。具体命令按匹配版本安装指南，不以参考书旧示例替代当前配置。

| 检查 | 能说明什么 | 还需检查 |
| --- | --- | --- |
| healthz | 服务响应/存活 | 数据源与依赖 |
| Runtime 状态 | 设备/后端连接和当前状态 | 目录、真实反馈与 physical_ready |
| readiness | 当前任务入口的阻塞条件 | 批准/资源/证据及具体现场范围 |
| 队列/leader | 通知与中心持有者状态 | outbox、pending、claim/fence |

控制端由 Local 切 Fleet 前，停止旧派发，处理在途/未知/持物，再建立新控制身份；Fleet 切回同理。迁移服务数据不能自动撤销旧 command，也不能凭页面断线推断控制器停止。

运行服务与设备维护要有明确负责人。发现数据库不足、制品损坏或源序列异常时，记录受影响范围和允许读/禁止写路径；修复存储后以原身份核对，不生成空白库冒充连续运行。

### 空间部署与产物治理

部署身份除代码/镜像外，还包括 ROS 消息包两端版本、Profile/commissioning、空间部署 SHA、外部 SLAM 修订、定位来源/质量、世界/标定和停止流程。先冻结旧派发并保存 pin/journal，再更换地图或定位参数；目录摘要变化需要新准入与批准，不通过清库绕过。

运行目录与实验目录具有不同保存要求。当前 MuJoCo 按 scene/perception/seed 隔离任务历史，避免两种感知模式共享旧 Runtime pin；旧数据不自动迁移。地图数据库、测量、失败目录与执行记录可供论文复核，不能当缓存删除。

临时 scratch 文件、过时重复 CLI 和可重建输出先检查跟踪、引用、manifest 与打开文件，再按明确清单清理。[产物管理](../../docs/operations/artifact-retention.md)记录本轮删除及保留边界。电子书不同出版身份也不能覆盖已有版本，原生成器与正文可按恢复清单回读。
