# 第 18 章 长程上下文：完整事实、有界输入与跨域一致性

**学习目标**：设计不会因历史变长而丢掉安全状态的上下文，解释压缩、回查、版本、冲突和重启。

**先修知识**：第3、6、8、17章。

**关键术语**：managed projection、guard、冷归档、作用域、精确请求

长程任务的困难不是“模型能看多少字”这一件事。早期硬约束要保留，当前动作可能结果未知，多台机器人可能报告矛盾事实，中心与边缘还可能读取不同版本。把聊天摘要复制给所有Agent不会解决这些问题。

## 18.1 先确定谁拥有事实

| 对象 | 权威来源 | 模型不能做的更新 |
| --- | --- | --- |
| 目标与批准内容 | 持久Task/不可变TaskRevision | 在摘要中改目标或扩大批准范围 |
| 未决/结果未知命令 | 执行账本、Runtime journal、checkpoint | 以一句“已恢复”改为成功 |
| 当前世界 | 有来源、坐标/标定、采集时间和序号的观测 | 把历史完成当当前仍满足 |
| 资源与执行权 | coordinator、live claim、租约/fence | 生成有效授权token |
| 决策上下文 | 从上述来源构建的managed projection | 成为第二个独立任务状态源 |

中心持有批准定义和协调状态，边缘持有本机checkpoint与回执；同进程Agent订阅事件并读取持久来源。各模型视图可以不同，但作用域和事实来源必须可核对。

## 18.2 从完整历史生成精确阶段记忆

`tasks.ContextForRevisions`读取完整任务事件及不可变版本，不只保留最近若干条。它把来源整理为目标、硬约束、计划/步骤状态、命令生命周期、问题和证据引用。

命令归约使用 `(revision, robot, step, command, tool)`。另一机器人、旧revision、不同命令或缺失身份的完成事件，不能清除原命令的pending/unknown。历史缺字段保持缺失，不倒填最新身份。

相同事件ID的冲突变体保留冲突状态；随后普通CONFIRMED不能覆盖冲突。当前观测使用真实采集时间，历史任务时间不冒充新鲜度。

```text
完整TaskEvent + TaskRevision
          ↓ 确定性归约，保留来源ID
精确当前阶段 / 命令guard / 历史来源记录
          ↓ 每轮按预算生成
模型热视图 ← 同作用域context_read ← 完整JSON冷归档
          ↓
模型候选 → 既有审批/Runtime/证据门禁
```

## 18.3 热层与冷层的内容

热层保留目标、硬约束、当前阶段、精确参数和verdict，以及未决/unknown/冲突/禁止重放guard。冷层保存完整历史动作记录和冗长工具详情，保留source_record_ids、证据ID、SHA和条目索引。

归档不是有损摘要：完整JSON仍能读回。每次从源数据重建，不把旧压缩结果再压缩。最新业务工具结果放不下时也可外置，但刚回查的context_read页要保留到下一轮，避免“读回即归档”的循环。

**为什么不能把所有动作历史都标guard？** 每条guard都必须留在热层，长历史会使必要状态膨胀。正确做法是将完整历史外置，热层按命令保存精确未决边界与来源引用。相反，不能为了缩短输入把unknown或冲突删掉。

## 18.4 预算保护的是实际请求

| 默认配置 | 值 | 保护对象 |
| --- | ---: | --- |
| TANGYING_CONTEXT_MAX_BYTES | 32768 | 模型上下文正文UTF-8字节 |
| TANGYING_MODEL_REQUEST_MAX_BYTES | 65536 | 含system、工具schema和协议字段的HTTP JSON |
| TANGYING_MODEL_OUTPUT_TOKENS | 4096 | 请求的输出token上限 |
| context_read单页 | 最多4096字节 | 还按剩余输入预算缩小 |

输入字节不是供应商真实token计量。部署者要根据具体模型窗口留余量。必要状态或工具schema仍超预算时，在模型/物理请求之前拒绝；不是自动提高上限，也不是截用户硬约束。

GOAL规划有10轮、6次provider读取、3次提案和16 calls上限。actionloop等循环有自己的轮数/权限边界，不能把GOAL预算当作整个系统无限续跑的参数。当前没有自动生成无限任务阶段的调度器。

## 18.5 context_read怎样避免跨域串线

归档集合来自当前循环捕获的同task/robot/revision scope。回查指定SHA、可选item_id、UTF-8 offset/limit；返回实际偏移、总长度、完整标记。旧SHA可以在同一循环新增历史后继续分页，不能跨机器人或另一次规划访问。

规划开始时尚无taskId和revision，记录真实目录robot scope，task为空、revision为0。之后创建任务不倒填之前的模型输入身份。执行/恢复循环的scope变更会结束旧循环，不重绑旧历史。

context_read是内部只读工具，不进入待批准的机器人工具序列，不计作物理执行；独立恢复复验重新调用原诊断读取，不把分页文本当复验。

## 18.6 精确请求与数字身份

实际模型HTTP请求保存为ModelRequest原文及SHA，外置Artifacts随投影/trace留存。复盘可以把模型所见输入与记录对齐，不从重新运行的模型响应猜当时上下文。HTTP Authorization密钥不进入这些trace。

源哈希、视图哈希、模型请求哈希是三种不同对象。一个SHA没有其preimage或完整制品引用，不单独证明完整来源已留存。

跨通用JSON边界的动态业务数值需保持可移植，超过安全范围的业务ID用字符串。协议fence/sequence使用typed uint64和精确JSON，不能经float64舍入后比较“相同命令”。

模型请求本身可能包含用户任务和业务数据；不含Authorization不等于可以全部公开。保留访问权限、脱敏发布和原始私有证据的区别。

## 18.7 不一致的处理表

| 输入矛盾 | 处理结果 |
| --- | --- |
| 同ID不同参数/fence | 拒绝冲突，保留guard，不静默合并 |
| 缺robot/revision/command身份 | 保留未知，不与相似步骤合并 |
| 旧成功对应另一命令 | 不解除当前pending/unknown |
| task snapshot与claim不匹配 | Basis/digest校验拒绝执行 |
| 待批准新提案但active内容相同 | 可接受校验后的active revision，提案仍无执行权 |
| Runtime目录/Profile变化 | 拒绝，重新配置/登记/规划/批准 |
| 世界来源、坐标或时效错误 | 等合格新证据或停止 |
| completed旧结果遇到新revision | 仅按精确不可变receipt确认旧结果 |
| 必保留状态超预算 | 拒绝模型调用，缩小明确阶段 |

没有“最后一个Agent说的为准”规则。权威对象、身份和证据决定接受与拒绝，不以消息到达顺序覆盖物理未知。

## 18.8 一个真实的预算故障

修复前的Gazebo run-002有335事件。历史完整动作都被标为不可归档guard，必要状态超过32KiB，诊断尚未调用就被拒绝。镜像参数冲突还使状态必须保守保留，不能通过忽略冲突缩短输入。

修复把完整动作历史保留为可归档verification来源，热层按命令精确聚合未决边界。真实生产形态工具回执再次暴露第二轮溢出；最终允许完整业务Detail外置，同时保护context_read当前页。

离线真实文件重放的执行历史两轮输入为31,634/32,530字节，遥测为31,572/32,334字节，低于原32,768上限，原unknown/冲突没有被关闭。该重放的读取回调是测试替身，不能把它说成真实机器人已恢复。后续run-007才提供实际任务结果，见第19章。

## 18.9 如何检查自己的实现

先构造含早期硬约束、500个已完成动作、一个未知动作和一个冲突事件的历史，再检查：

1. 完整来源能否按SHA/条目精确读回？
2. 未知/冲突是否仍在热guard，旧成功能否错误关闭它？
3. 换robot/revision之后旧归档是否被拒绝？
4. 中文/emoji分页是否保留合法UTF-8及偏移？
5. 最新业务结果归档后，实际请求是否仍在预算内？
6. 落盘关闭/重开能否还原实际模型输入？

附录F提供相应测试与观察方式。压缩率高不等于一致性强，关键是哪些状态绝不允许改变。

## 18.10 小结与源码路线

路线：[ContextForRevisions](../../tasks/context.go)→[命令记忆](../../tasks/context_memory.go)→[managed projection](../../core/agentcontext/managed.go)→[回查](../../internal/actionloop/context_read.go)→[规划trace](../../internal/capabilityagent/planner.go)。真实故障与数字见[预算修复](../../docs/development/2026-10-10-context-budget-recovery.md)。

完整权威来源、有界模型视图与执行Basis分工不同。中心/边缘不必保存相同聊天，必须核对身份与依据；压缩和分页不改变未知、冲突和批准权。必要状态超预算仍拒绝，不保证无界持续规划。
