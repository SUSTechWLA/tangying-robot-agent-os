# 第 15 章 当前边界与未来方向

本章按1.1.0源码快照区分已经实现、已经验证和仍待扩展的能力。旧版未实现清单不再作为当前路线图；原正文保存在1.0.0历史快照中，旧规范和失败报告仍可查阅。

## 15.1 已经完成的架构升级

| 旧缺口或旧表述 | 当前实现 | 证据边界 |
| --- | --- | --- |
| 标定、建图依赖专用页面推进 | 注册能力经统一 Task/Revision/审批执行 | 当前 Local 与云边接线测试；页面不是状态机 |
| 自然语言只有固定 Intent 分类 | GOAL 结合 Runtime 目录，robot.task 保留冻结 Intent | Schema 及范围受限，不保证任意语言都可执行 |
| 地图不能进入主任务完成链 | mapping.build 自动采集、保存、激活并独立读回 | 已有 Gazebo 闭环，真实传感器仍待验证 |
| 房间语义等同于最近目标点 | SLAM几何、语义标注、区域/目标点与版本分工 | 名称不能从未知几何凭空推断 |
| 长操作只有临时 session | 稳定 operationId、持久回执、绝对期限与租约 | 未知写入不重放，任意掉电仍需现场测试 |
| 边缘与服务器各写一套 Agent | 共享规划/执行，角色装配任务权威与权限 | 当前通用目标按单机器人绑定 |
| 只能统一设置一个模型 | GOAL/INTENT/PLANNING/RECOVERY/SYSTEM 独立路由 | Orin量化与GPU大模型性能尚未现场认证 |

上述实现不能消除硬件、感知和环境限制。`calibration.run` 在参考仿真中检查模型配置，不自动证明实机手眼、相机或舵机标定已通过。

## 15.2 当前已验证到哪里

2026-09-27 实际 LocalAgent+Gazebo 使用同源 XLeRobot 与 `home_furnished` 家庭场景，真实 GOAL 模型下发自由自然语言目标，经过标定、巡检 SLAM、厨房解析和导航，最终 Task SUCCEEDED，四个能力步骤 CAPABILITY_VERIFIED，到达观测 CONFIRMED。

扫描23.492米、230帧、220配准、2回环、72382点，五个房间目标 navigationReady。保存栅格38626格，其中11013格未知，比例28.512%。分母是本次保存的矩形范围，不能据此宣称全屋扫描完成。

成功前五次试验保留失败与修复记录。单次成功证明该代码、模型、地图和场景中的闭环，不构成成功率、危险失败率或通用语言覆盖率。云端/Worker的实际 HTTP 测试使用 Runtime fixture，不能冒充云端+实体机器人试验。细节见[闭环报告](../../docs/experiments/2026-09-27-capability-goal-closure.md)与[附录C](../appendix/C-experiment-index.md)。

## 15.3 仍须独立验证的部署范围

| 范围 | 必须补充的实际证据 |
| --- | --- |
| Orin NX量化模型 | 权重/量化/驱动身份、峰值内存、热功耗、延迟、超时与失联策略 |
| GPU大模型服务 | 模型版本、并发/排队、认证、数据边界、超时和回退行为 |
| 真实机器人 | 驱动、坐标、足迹、传感器、标定、停止响应、带载行为与未知结果对账 |
| 云端+真实边缘 | 证书/时钟/网络故障、稳定操作身份、watchdog停止与持久回执 |
| 多设备目标规模 | 目录/心跳容量、调度公平性、数据库/队列压力及故障隔离 |
| 长期生产 | 备份恢复、证书轮换、升级回滚、容量增长、报警及现场责任流程 |

这些项目须按设备、任务、环境和版本验收。Docker启动、交叉编译、Runtime READY和软件release-gate均不能替代现场动作许可。[实机接入指南](../../docs/guides/hardware-agent-integration.md)说明分阶段步骤。

## 15.4 扩展性已提供的接口与尚未提供的保证

新增能力通过 Provider 注册输入、效果、资源、输出、操作和验证契约。新增本体在驱动/Provider中处理机构、传感器、IK和安全，不要求 Agent 按仿真器分支。这个接口允许扩展，不保证换一个本体就能执行同样任务。

当前只有 robot 独占资源；共享空间、物体、地图写资源仍需 Broker 设计与认证。通用 GOAL 绑定一台机器人，任意目标跨设备分解、能力协商和联合完成判定尚未实现。已保留的多机器人 Intent 协调不能扩大为任意跨机器人任务支持。

长建图有稳定操作、取消和状态，尚无任意位置暂停/续扫契约。暂停在能力边界生效。Schema为明确的严格子集，不支持的组合/引用关键词拒绝。增加工具时必须补契约实现与故障证据，不能只补模型描述。

## 15.5 六个后续研究方向

### 方向一：语义来源与世界预测

当前已有几何、区域标注和目标解析。后续可研究长期物体记忆、标签冲突、动态对象和预测模型；预测应保留不确定性、原始来源与版本，不能覆盖新鲜观测。应分别评测标签正确率、身份一致性、过期拒绝与错误目标的停止行为。

### 方向二：跨机器人经验

经验可复用任务建议，但不能绕过本体、地图和标定校验。训练/回放制品须绑定模型、机器人结构和来源；迁移到新设备后重新验证。应测试旧经验在新场景被拒绝或降级的路径，而不只测成功案例。

### 方向三：VLA与动作接口

通用 Agent 使用任务与能力契约；VLA或策略在受限执行端产生动作候选。动作空间、频率、状态质量和安全约束随本体变化。后续应验证模型动作适配、限幅、取消、感知降级与结果核验，不能从离线策略成绩推出生产控制可靠性。

### 方向四：机群一致性与共享资源

数据库、队列、资源租约和物理效果属于不同系统。仍需验证leader失效与业务提交窗口、跨存储转移、旧持有者恢复和长期故障。共享空间 Broker 应有明确所有者、过期与转移流程，且停止不明时不能把空间立即交给下一台设备。

### 方向五：长时程任务

当前16调用上限、持久回执和绝对期限给出有限计划的边界。长时间任务需设计分段目标、审批续期、地图变化、能源管理、任务中断及部分完成。动态重规划必须产生新的可审查版本；不能在同一批准版本下无限延长或更换目标。

### 方向六：设备标定与在线校准

标定已有工具入口和版本读回，真实算法由设备Provider提供。后续可研究相机/手眼/里程计一致性、误差预算与漂移检测；改变配置仍须记录来源、监督条件、验证与回退。自动校准不等于可以无人监督地使能所有执行器。

## 15.6 设计经验与后续门禁

- 提交完成时列明判据、来源和绑定版本，不仅列成功布尔值。
- Unknown与False分别保留；未知写入先对账，不重放。
- 共享执行机制，按角色注入任务权威、目录、模型与权限。
- 目录只接纳能验证效果的工具；未实现的资源与Schema约束拒绝。
- 对长操作验证进度、身份、期限、停止和持久性，不能只测试启动。
- 更新当前指南和书籍正文，保留旧版、设计规范、失败与实验原记录。

每项新能力的门禁应包括完整用户目标、审批范围、成功证据、拒绝/歧义、超时/断网、重启恢复和取消核验。真实硬件新增停止及带载验证；目标规模新增负载与故障测试。
